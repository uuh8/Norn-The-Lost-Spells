# 物品分类、测试金币和三地图携带指南

本轮针对分类、金币配置与跨 Scene 拾取。正式游戏的 Repository 实现保留；Editor 默认 Scene Preview，在一次 Play 中共享内存资产，退出后下一次 Play 重新从初始配置和场景布局开始。分类和实际拾取/回程已通过自动验证，具体范围见第5节。

## 1. 目前物品如何分类

“道具”按能否实际放入 4–0 使用判断，即 `ItemUseKind`。南瓜、食物和草药目前没有使用能力，统一归材料，不因为模型像消耗品就当成可使用道具。

| 目录/物品 | 界面主分类 | 底层类型及原因 |
| --- | --- | --- |
| Apple、Beetroot、Bread_A/B/C、Carrot、CheeseBig/Small、Meat、Pumpkin | 材料（Food） | `Consumable` 保留，尚未接食用效果 |
| Herb_Flower_01–05 | 材料（Herb） | `Alchemy` 保留，尚未接炼金配方 |
| Container_01–03、既有采集瓶 | 道具 | `Container`，可以绑定4–0，保留采集/撒出/投掷 |
| 固体元素实物、商店 GMU 原材料 | 材料 | `Material`；GMU 报价仍使用原有连续数量交易 |
| 法术 | 法术 | `Spell`；优先进独立12格，满后尝试背包 |
| 法杖A/B/C | 法杖 | `Wand`；属于1–3装备，不能当道具 |
| 背包外壳 | 背包 | `Backpack`；携带容器本体，不是4–0工具 |

统一规则在 `Scripts/Run/Inventory/ItemInventoryClassification.cs`。仓库、旧目录、商店都调用它。没有更改资产的 `ContentId` 和底层 `ItemKind`，因为这些值还控制数量、状态校验和旧档兼容。将所有资源直接改成 `Material` 会把食品误接进固体 GMU 规则。

## 2. 设置测试金币

1. 停止 Play，在 Project 搜索并选中 `Assets/_Project/ScriptableObjects/SinglePlayer/Hub/SinglePlayerRaids/StartingInventory.asset`。
2. Inspector 修改 **Initial Currency**，例如 `5000`。字段默认 `0`，负数配置会被拒绝。
3. 回到据点 `_Systems` 的 `SinglePlayerInventorySession`，确认 **Starting Inventory** 引用这个资产，并保持 **Editor Profile Mode = Scene Preview**。
4. 开始新的 Play，打开背包、进入仓库/商店区域按 E，三个界面都读取同一个 `WalletReadOnly.Currency`。
5. 完成购买/出售后，再打开其他界面核对新余额；余额是实际交易结果，不能直接改 UI Text。

`Initial Currency` 只在 Repository 报告缺少档时发放。当前 Play 已经建立临时档后，修改种子不覆盖当前余额；需要重新进入 Play。`Saved Profile` 模式已有档也不会被初始金额覆盖，不必删除真实存档进行本轮测试。

## 3. 地图物品如何带回来

普通物品都由 `WorldItemSpawnPoint` 注册具体实例。正式远征以当前 `RaidId + SceneKey + SpawnId` 区分一次投放；物品不写进据点初始投放账。成功撤离沿用结算服务，保留背包/法术专区中的同一个 `InstanceId`。死亡、放弃和未拾回地面物的既有规则仍生效。

P7/P8 采用 Single Scene 加载，据点 Session 必然被卸载。因此 `HubPracticeSession` 只保留 Repository 和返回路径等纯上下文，每张图创建一个 `PracticeInventoryWorkspace`。在新 Scene 的 `Start` 前，从同一个 Repository 恢复物品、次数、内容和金币，再配置玩家、拾取输入和背包。旧 `Store` 的资格策略不跨 Scene 共享，避免出现“库存已有资格策略”的双写错误。

练习工作区 Prefab：`Assets/_Project/Prefabs/SinglePlayer/PracticeInventoryWorkspace.prefab`。它从已保存的背包与拾取列表生成，外框样式沿用作者布局，内部引用指向本工作区，不引用已卸载的据点角色、商店或仓库。背包暂停使用练习图现有 `RunPauseCoordinator`，同时持有 Guide/Inventory 的 Pause Reason；练习中禁止远程存取仓库。

回程前可靠保存；只带回已收进携带背包或法术专区的物品。留在练习图地上的本图物品随 Scene 释放，不在据点凭空恢复。连续 P7→P8→据点也使用同一份临时资产。`EditorScenePreviewFileSystem` 在下一次 Play 的 `SubsystemRegistration` 清空内存文件，因此本次测试拾取不会写入正式磁盘档。

## 4. Editor 接线和验证

正式据点只需要在 Session 上配置 **Practice Workspace Prefab**。工具菜单 `Tools/Norn/物品/应用三地图携带工作区（Undo，不保存）` 增量设置该引用；一组 Undo，不自动保存。生成 Prefab 的流程使用独立 `SinglePlayer_Hub_ItemCarryReview`，不会覆盖你的正式排布。

在副本放置可拾取 Prefab 后，使用已有批量 SpawnId 工具扫描；不要复制已有实例的 SpawnId。进入地图后观察 F 列表，收集一件南瓜/容器/草药/法术，通过实际回程门返回，检查原 ID 和内容仍在。满背包按 F 应打开背包，地面模型保留，腾出空间后再拾取。

验证证据集中在 `TestResults/SinglePlayer/M6-T3-ItemCarry/`。自动测试修改的金币种子、临时物品和文件都来自隔离副本，不在正式地图添加测试物件。当前阶段仍在开发中，原购物清单/整单结算第二阶段等待你验收后再开始。

## 5. 已验证范围和实际试玩顺序

真实 Catalog 共28种定义：16种材料（10种Food、5种Herb、固体冰），4种容器道具，3种法术、3种法杖、2种背包。分类清单见证据目录 `catalog-classification.tsv`；仓库按类别显示，不会把同一名称的不同次数实例合并成一个资产。

独立 Review 以克隆的 StartingInventory 发放5000金币，实际购买40、出售12后，三窗口余额同时为4972；正式种子没有被测试改为5000，默认仍是0，需要按第2节自行设置。

PlayMode 使用 Input System 的真实 F/Tab 输入和实际出口：正式远征、P7、P8各收集容器、南瓜、草药、法术并带回原实例；连续P7→P8→据点也保留资产。满包F开背包且保留地面源、回程保存失败后保留原地面资产并可重试、下一次 Preview 清除测试拾取身份均有独立测试。原练习战斗流程继续保留，这次对接的是物品、拾取和库存携带。

P7拾取列表46帧 Profiler 采样：`Norn.Items.NearbyQuery` 和 `Norn.Items.PickupList` 两个子树的 `GC Alloc` 均为0；不等于整个 Editor 每帧零GC，也不包含首次初始化和拾取事务。

你实际验收时建议先设置金币并重新Play，依次查看三窗口余额和买卖，再走三个地图入口各拾取一件物品返回，最后测试满包与连续P7→P8。正式Hub引用由工具以一组Undo增量配置，需你自行Ctrl+S保存；工作区Prefab来自已保存背包布局，若后续大幅精修背包，可重新生成Review与Prefab，再检查练习图布局。
