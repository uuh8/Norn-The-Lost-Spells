# P7/P8 新版背包、施法与奖励配置及验收指南

本轮第二阶段统一的是玩家操作所连接的真实资产。两张地图复用据点的背包、12格独立法术专区、1–0手持栏、附近拾取列表和5×5小白点。法杖编辑写入具体实例的程序，左键从同一个实例取得程序、Mana和次数；旧 RunSpellSession 的 Library 不再作为这两张地图角色施法与奖励的资产来源。关卡任务、角色HP、Boss HP、死亡/胜负、暂停、Fade和音乐继续保留。商店第一阶段的双入口购买和满包转仓库已经先行交付。

## 1. Editor 中的资产与入口

- 共享工作区：`Assets/_Project/Prefabs/SinglePlayer/PracticeInventoryWorkspace.prefab`。它从你已保存的据点背包、HUD和拾取列表生成；不包含据点站点或据点角色的Scene引用。
- 两张正式地图：`Assets/_Project/Scenes/P7_DemoRun.unity`、`Assets/_Project/Scenes/P8_BossField.unity`。
- 地图启动器：`PracticeModernInventoryBootstrap_新版库存入口`。Inspector 引用工作区、返回门、Catalog与StartingInventory；不要另外放第二个库存Session。
- 隔离验证副本：`Assets/_Project/Scenes/SinglePlayer/P7_DemoRun_ModernUiReview.unity`、`P8_BossField_ModernUiReview.unity`。这些是验证资产，正式地图使用正常出口目标。
- 新增法术物品定义：`Assets/_Project/ScriptableObjects/SinglePlayer/Hub/PracticeSpellItems/`。文件名和ContentId来自原SpellDefinition的Asset GUID，改显示名称不会生成另一种物品。
- 全部物品目录：`Assets/_Project/ScriptableObjects/SinglePlayer/Hub/SinglePlayerRaids/Catalog.asset`。原有火球、冰球、触发火球定义保留，只追加尚未映射的法术。
- 初始资产与测试金币：同目录的`StartingInventory.asset`，Inspector 的 **Initial Currency**。只影响新档和下一次新的Editor试玩，不覆盖当前携带资产。

如果今后修改了据点UI，需要先保存你要保留的Scene，再重新生成共享工作区；不能只改旧练习场的编辑器。正式地图增量应用菜单是 **Tools > Norn > 练习地图 > 应用当前P7或P8新版UI（Undo，不保存）**。每次先单独打开一张地图，应用并自行保存后，再单独打开下一张；交付时恢复单独据点入口。它保留敌人、地形和镜头布局，移除旧法杖编辑Canvas、旧Mana显示和纯UGUI红十字。共享的是工作区Prefab，三个完整地图各自独立运行。

**2026-10-12 交付修正：** 原来的 `apply-maps` 把两张正式地图以 Additive 打开后留在 Editor，导致玩家按 Play 同时运行三张地图。这是工具的交付错误，不能把事后保存和关场景作为正常工作流。该入口已移除；多个独立地图同时加载时，进入 Play 会被取消，编辑状态原样保留。需要恢复入口时，先自行保存要保留的修改，再执行 **Tools > Norn > 练习地图 > 恢复单独据点入口（仅已保存场景）**；有 Dirty 场景时工具拒绝关闭或保存。传送门继续使用 `LoadSceneMode.Single`，带过去的是本轮库存数据，地图、角色和场景 UI 会正常替换。

## 2. 两种进入方式与内存生命周期

从据点传送进入时，HubPracticeSession先可靠保存当前库存，再把同一Repository带入P7或P8。Scene切换会重新创建角色、UI和元素世界，同时恢复原物品InstanceId、位置、法杖程序、次数、道具绑定和金币。返回据点不发第二份初始资产。

直接在Editor打开P7/P8并Play时，启动器建立独立临时内存Repository，再创建同一工作区和回程门。已有传送上下文时启动器直接退出，避免两个背包或两次初始发放。退出Play后这套临时数据销毁。Build中的练习入口按当前单机流程从据点进入；直接初始化的入口只供Editor试玩。现代练习重试继续使用本轮owned库存和程序；旧Library Checkpoint保留教学进度兼容，不用它回滚具体物品资产。

工作区先配置Run库存，激活Prefab后UI在Awake绑定库存和共用Pause Coordinator；Character桥接也在Awake绑定角色的手持输入、容器使用及OwnedWandCastAdapter。Wizard通过显式方法更新Awake缓存并取消旧待施法，不能仅AddComponent就认为旧引用会自动刷新。桥接Start补发准心可见性事件，覆盖CrosshairUI先隐藏、随后订阅的生命周期顺序。

## 3. 玩家验证步骤

1. 从据点分别进P7/P8，再分别直接打开两张地图Play。每次应只有一套1–0手持栏和屏幕中心小白点，没有红十字和旧法杖编辑器。P7任务文字位于手持栏下方。
2. 按Tab打开同款背包，编辑法杖程序；关闭后实际左键施法应跟随该程序。1/2/3切换真实法杖；查看Mana和有限发射法术的剩余次数。
3. 背包打开时按Esc应只关闭背包。再次按Esc才打开暂停菜单，恢复后可继续移动/施法。测试死亡/胜负时背包应让出结算界面。
4. 4–0选择道具；容器左键撒出、E采集、G投掷。F收集普通世界物品；拾取列表出现时滚轮切换目标。采集/投放必须由地图真实元素世界接收，不只是改数字。
5. 清理关卡取得单法术和全集奖励。它们优先进入黄色专区，满后进入背包；不会远程塞到仓库。满容量时保留世界奖励和出口领取入口，整理后可重试。全集允许分批领，每个奖励键下已经收到的法术不会重复发放。
6. 修改一个有限次数法术，记录它的实例与程序、金币，经过P7出口进P8再回据点。它们应保持；重新启动一次Editor Play应回到初始试玩状态。

## 4. 奖励与资格的设计取舍

普通奖励需要具体ItemDefinition映射，直接把SpellDefinition加入旧Library只改变“可以编辑什么”，不会产生可移动、可带回的物品。新桥接按SO身份查Catalog，再由唯一归属表验证法术专区或背包位置。尝试多个位置复用同一新实例，失败候选不占位；未知或重复映射明确报错并保留奖励。

练习奖励沿用原教学的无限使用语义。其他来源的有限法术保留次数；有限Modify/Multicast属于“一轮练习”的资格，而非每个Scene的新资格。跨Scene上下文记住已取得资格的InstanceId，恢复先登记这些ID，再Reconcile新安装的法术，避免一张已扣到0但本轮合法的卡在P8再次扣费或被拒绝。该状态只存在进程内，没有升级正式存档Schema。

## 5. Debug 与回滚

- 新背包编辑无效：先看角色OwnedWandCastAdapter.ReadOnly与背包Session.InventoryId是否一致，再看Wizard缓存是否经过BindOwnedInventory更新，最后检查实际投射物与该法杖资源。
- 白点之外仍有红十字：老节点名是`AimPoint `，它没有CrosshairUI组件，仅扫描消费者会漏掉。正式增量工具按已核对节点身份删除。
- 关闭背包又被暂停：InputAction回调发生在Update前；Pause Menu需先判断Inventory Pause Reason，让背包消费此Esc。
- 奖励丢失或重复：检查世界入口是否只在全部成功后消费；检查全集领取与出口使用相同奖励键；失败时Store版本/数量应保持。
- Review不符合新代码：先核对实际Editor Assembly DLL的更新时间，再生成Review。本工具属于`Game.PbfTask13.Editor`，不能误用Assembly-CSharp-Editor的时间戳。
- 正式应用可通过单组Undo撤销。不要批量删除新增Catalog条目；先检查当前资产是否引用它们，以免恢复出现UnknownContent。不要清空正式资产来解决试玩差异。

自动验证证据集中在`TestResults/SinglePlayer/M6-T5-PracticeModernUi/`。XML、截图、Profiler子树与正式Scene hash分别证明不同事实；截图和单元测试不能替代你在Editor里的最终手感验收。
