# 元素世界固定固体与气体扩展实施计划

> 执行方式：用户已授权理论评估后直接实施，由当前主 Agent 使用 `superpowers:executing-plans` 执行；不启用 SubAgent、不创建 Worktree、不自动 Commit。用户明确停止低效的 P7 通关／Boss 实战验证，当前采用源码审查、复杂度评估、编译与小范围 EditMode 回归，不再次要求计划确认。

**Goal：** 优先验证玩家在有限区域内持续施法与 Boss 战的流畅性，控制模拟、显示和恢复的实际工作量；在此基础上加入固定固体、真实气体与可解释的转换，保持统一材料身份、数量、交互和显示。

**Architecture：** `Game.Materials` 定义材料身份与行为类别；`Game.ElementField` 持有各形态真实数量、空间状态、模拟、冻结／恢复和转换；`Game.Rendering` 通过只读接口消费世界状态。沿用既有统一写入与查询入口，每种材料仅有一个 Simulation Owner，液体继续由当前 Grid Liquid 负责。世界活动范围与显示范围分别配置；相机裁剪不会自行改变 Gameplay 活动状态。

**Tech Stack：** Unity 6.3（6000.3.16f1）、URP 17.3.0、C#、ScriptableObject、稀疏 Chunk、固定 Tick、预分配 Buffer、Mesh／MeshCollider／NavMeshObstacle、URP HLSL、NUnit／Unity Test Runner／Profiler。

**设计依据：** 本对话确认“万物皆元素”；用户接受可理解的消耗、消散与排水；确认新增固体和气体；2026-10-06 同意先做固定固体与气体，再扩展颗粒固体。按照 `AGENTS.md:79-82`，本文件合并设计与详细实施计划，不另建 Spec。

**2026-10-06 范围与优先级修订：** 用户确认圈外材料可以完全停止模拟，返回后恢复；随后明确“大圆＋雾”不是必须采用的技术，最终目标是有限可玩区域内流畅。保留状态并冻结是已确认规则；具体半径、区域形状、Fog 与 CPU/GPU 并行方案通过同条件测量选择。先增加 Phase 0 的现有元素基线与范围／恢复门禁，再实施 Phase A–E，不能依靠新增气体或固体自动解决当前卡顿。

**最新验证约束优先于本文旧门禁：** 下面保留的 Scene／Playthrough／Boss／Profiler 清单是未来实测参考，不作为当前执行的前置条件。当前不自动通关 P7、不进入 Boss、不反复录制长窗口，也不保存或重载关卡。完成代码与针对性测试后继续获准的实施；真实 FPS、GPU Overdraw、视觉感受只报告未实测，不用理论或逻辑测试替代实测成绩。

## 1. 目标、当前基础与范围

**2026-10-06 固体/气体基础交付记录：** 已实现 Phase A–C 的材料身份、唯一写入/查询、稀疏数量 Store、固定固体表面/Collider/导航段、真实气体扩散/排气/冻结恢复、胸头暴露、只读 Rendering；已创建四材料、四法术/Prefab 与 P7/P8 基础接线。Gas 显示使用 Texture3D + 16 步 Ray Marching，替代拟议的软采样层；固体初版是格状实体。Solid 起始池为 32 Chunk（避免初始化 4096 个导航对象），Gas 为 256；这些是理论预算，尚未取得产品 FPS 上限。官方定向批次 41/0 与资产/Shader 6/0 通过，补充同步原生断言检查用于保护当前 Dirty P7。证据与逐文件解释见 `Assets/_Project/Docs/2026-10-06 元素世界固体气体与材料转换完整解析（更新中）.md`。后续“继续”已授权 Phase D，下方追加本轮转换实施记录；Phase E 的长时/Boss/视觉验收继续保持未完成。

本阶段把元素世界从主要支持液体和反应场，扩展为能够容纳固态、液态和气态物质的统一世界。玩家看到的冰、固化残留、蒸汽和毒性气体都必须对应可查询的真实物质；法术、场景初始材料和材料转换都通过同一世界入口创建它们。固定固体生成后，要根据材料属性改变阻挡与接触；气体要能在障碍约束下扩散，并根据浓度产生暴露。显示效果读取这些结果，不能自行决定物质存在或伤害。阶段先交付两类材料的最小真实状态与行为，再接通蒸发、凝结和干燥固化。该次序能分别验证材料身份、数量、碰撞、扩散和转换，避免视觉效果掩盖数据错误。同时，转换不能成为另一种累积问题：静止固体应复用几何和阻挡数据，气体需要受规则约束的通风／反应路径，旧液体的稳定化与外壳缓存也要继续有效。本计划完成后仍须用正常 Boss 战验证性能，不能用接口测试替代实战帧率。

本段的材料扩展顺序保持；整个阶段的执行入口前移到现有元素性能验证。活动半径只限制空间，圈内还可能持续增加活动格、表面覆盖和透明叠层。必须明确本游戏支持的最大正常施法速率、材料活动规模和可见覆盖规模，并在该负载下验证帧时间。超出已测负载时不能宣称无限持续生成也始终不卡，也不能通过遗漏可见材料或让 Gameplay 更新长期积压掩盖容量不足。

### 1.1 只读核对得到的当前状态

- `MaterialId` 已序列化为 byte：Empty=0、Water=1、Fire=2、Poison=3、Sticky=4，原编号必须保留。
- `MaterialBehaviorKind` 为 None=0、Liquid=1、ReactiveField=2；行为类别与 Simulation Backend 已分离。
- `MaterialDefinition` 只保存身份与行为，不能塞入 Shader、Status、密度、所有 Solver 参数而变成 God Object。
- `ElementWorldWriteRouter` 一次请求只选择一个写入 Owner；失败不回退到其他后端。
- `MaterialStateQueryRouter` 输出的 byte 是接触状态投影。真实液体数量通过 `ILiquidQuantityReadOnly.TryGetQuantity` 的 uint GMU 读取；转换不能拿 byte 投影记账。
- `ElementFieldSolidBaker` 将场景 Collider 采样成地形阻挡缓存；当前不代表可生成、可转换的固体材料。
- `GpuFireParcelRenderer` 的 Gas 相位属于视觉，不创建 Gameplay Gas；本阶段不重分类 Fire 的现有身份与行为。
- P7／P8 已使用当前 Grid Liquid。10 月 4 日集中诊断 267/267 是历史证据，非本阶段验证成绩；旧 Boss 性能边界仍未收口。
- 项目已有 Ground Layer=8；固定固体 Collider 使用该层，避免新增 Layer 或改动全局碰撞矩阵。

### 1.2 本阶段材料与语义

| 拟新增身份 | 类别 | 玩家与世界意义 |
| --- | --- | --- |
| Ice=5 | Solid=3 | 固定冰体；阻挡与承托由真实占据体积决定，可被融化规则消耗 |
| DriedSlime=6 | Solid=3 | 固化粘液残留；Play 反馈修复后启用真实高度的角色/投射物碰撞，液体按部分 GMU 占据，粘滞投影为 0 |
| Steam=7 | Gas=4 | 水的气态材料；数量与浓度独立于烟雾粒子数，可扩散、通风排出、凝结 |

这些名字和编号是本计划的拟新增协议，当前源码尚不存在。保留独立材料身份，以数据配置转换关系；不会给每个 Water 格增加可由任意模块直接修改的 Phase 字段。

固定固体表示生成后位置不由颗粒求解器推进。第一轮不加入砂土／粉末堆积、可拾取 Rigidbody 碎块、任意地形破坏、完整热传导、完整压力流体、完整化学组成、火焰身份重构或新增 Boss 法术程序。这些范围不影响本阶段的统一材料入口与后续扩展。

## 2. 设计选择与统一 Runtime 链

### 2.1 统一身份与坐标，分别存储和模拟

```text
法术／初始材料／调试写入
    → ElementWorldRuntime → 最终材料路由
        → 现有 LiquidWorldRuntime
        → 新 FixedSolidWorldRuntime
        → 新 GasWorldRuntime
    → 本场景真实数量／局部版本／变化 Bounds
        → Gameplay 查询与角色暴露
        → 固体 Physics Adapter
        → 只读 Solid／Gas Renderer

转换：局部条件 → 算出转换量 → 预约目标容量／阻挡变更
    → 在固定 Tick 统一提交源消耗与目标生成 → 更新局部版本与账本
```

第一轮三种形态使用同一个 World Origin、基础 CellSize 和 Chunk 坐标映射。Gas 保持基础分辨率，以便墙、门与细缝的阻挡结果准确；通过稀疏存储、活动集合、较低更新频率和显示采样控制成本，不在首轮用粗格平均把墙两侧连通。随后若要加入粗细分级，必须有隔墙与通道等价测试。

数量沿用 GMU 作为**游戏物质量单位**，使用 uint／ulong 记账。相同 GMU 的液体、气体、固体可以有不同空间占据／显示体积，由对应 Behavior Profile 映射，不能要求蒸发前后占据体积相等。库存、排出和转换账本用整数；插值、光照与显示浓度可以用 float。现有 Fire 的反应场强度继续独立查询和统计，不能与 Water 的 GMU 直接相加；提供热条件也不等于它已经拥有温度或能量守恒模型。

新增后端枚举 FixedSolid=4、GridGas=5。保留 Water 的现有 Compatibility 决策；对 Solid／Gas 路由验证 Catalog 行为与目标后端匹配。新增可选 Runtime 未就绪时明确拒绝写入，不能回写旧 Cell 或仅生成视觉。生产 Profile 在 Renderer／Physics 未通过验收前不启用对应新材料。

### 2.2 固体：材料占据与地形缓存共同决定阻挡

新增稀疏 FixedSolid Store，保存每格材料、真实数量和占据高度。Ice 的可见几何与 Collider 使用同一占据描述；DriedSlime 保存真实数量与薄层几何，但其配置可不阻挡角色／气体。Terrain 原阻挡保持独立，通过只读空间接口组合查询，不能把可融化 Ice 烘进永久地形缓存。

首轮每个基础格仅有一种 Solid 身份；同种追加数量，不同种写入已有 Solid 的格时明确拒绝，不能覆盖原材料。液体／气体是否还能进入由剩余占据空间决定。`FixedSolidPhysicsAdapter` 注册自己生成的 Collider，由 `ElementFieldSolidBaker` 排除采样，防止 Ground Layer 的动态材料反过来进入永久 Terrain 缓存。

变化采用局部版本与 Dirty Chunk 队列。只有材料数量／占据改变的 Chunk 重建外表面和 Collider；内部相邻面不生成，静止固体不每帧重建。避免每个格创建 GameObject、Collider 或 NavMeshObstacle。Physics Adapter 属于 `Game.ElementField`，Renderer 只读几何描述，两者都不拥有材料量。

实际碰撞采用预建池中的 Chunk MeshCollider；导航阻挡采用占据形状合并出的 Box NavMeshObstacle，使用 Carving。不能把含空洞的整个 Chunk Bounds 当障碍。形状／Collider／Obstacle 容量不足时，新增阻挡保持未提交；不能让 Gameplay 已堵住、画面或 Collider 仍未准备好。材料、Physics 与显示在同一次局部提交边界生效。生成区域与角色相交时延后或拒绝，不能在角色身体里突然创建实体墙。

NavMesh Carving 的更新由 Unity 导航系统处理，不能承诺与 Collider 在同一 Tick 完成。Task 2 单独测量动态障碍生效的延迟与近距离绕行；实际 Collider 负责实体阻挡，导航是否及时重新规划必须经过场景验收，存在持续顶墙或穿行就不能通过该 Phase。

支持面缓存和 Stable 湖盆收到局部拓扑失效；Ice 移除后唤醒活动范围内受影响的液体与气体，冻结区记录失效并在恢复前重查阻挡，不能留下隐形阻挡，也不能因失效通知隐式启动冻结区 Solver。角色 GroundChecker、液体支撑、Gas 邻接和敌人导航都必须纳入验证。

### 2.3 气体：真实浓度场与有依据的出口

Gas Store 的 Current／Next 数量 Buffer 在初始化时预分配。固定 Tick 中对活动格进行六邻面交换，根据浓度差、材料扩散系数和浮升偏好产生整数通量；交换同时扣源、加目标，不能按遍历顺序原地扩散。Steam 的上升是可配置热蒸汽行为，ToxicVapor 的浮升默认中性，不能把所有气体写死为向上。

世界阻挡查询决定相邻面是否开放；封闭测试箱中气体总量保持。开放世界的退出由显式 GasVentAuthoring／GasBoundaryAuthoring 表示，默认没有通风配置的封闭区域不偷偷扣量。排出量写入账本；相机、玩家距离和透明度不会触发真实量删除。低浓度也保留数量，显示透明不代表没有物质。

角色暴露增加胸部与头部有限样点，合并材料浓度后统一投影到 StatusController；同一 Tick 不因多个 Collider 重复应用。ToxicVapor 映射 Poisoned；Steam 初始不自动赋予 Burning／伤害，温度伤害作为独立 Gameplay 规则验收，不随视觉颜色隐式开启。

Gas Renderer 使用真实场驱动的相机朝向软体积采样层，密度决定 Alpha，世界坐标裁剪与 Depth Test 防止穿墙。正面、侧面、俯视都要验收，保留原火焰样式与液体厚度。采样层有独立可见预算；优先显示新生成与角色交互区域，旧区域使用同场的连续低密度表示和渐变过渡，不能在预算耗尽时漏掉可见的危险气体。若该方案达不到遮挡／体积感或 Overdraw 预算，Phase C 不过门禁，先在该 Phase 调整显示，不进入相变。

### 2.4 相变与干燥：局部条件和原子提交

不以统一 Lifetime 删除材料。Phase D 首轮规则为：Water→Steam（局部受热）、Steam→Water（局部冷凝）、Water↔Ice（冷／热条件），以及水基 Sticky→DriedSlime+Steam（干燥）。采用独立 Conversion Profile 与环境条件 Authoring，Fire 接触可提供规则规定的热输入；本轮不把完整 Temperature Field 假装已经实现。

Sticky 默认配方假设为水基材料，4 GMU 输入对应 3 GMU 固态残留+1 GMU Steam。这个比例是游戏配方，不是现实材料常数；批准本计划即采用可在 SO 调整的起始配方。转换只处理能完整形成该配方的整数批次，剩余量继续保留在源侧，防止持续舍入丢量。Poison→ToxicVapor 仅由明确标记挥发性的 Poison Behavior 启用，默认不改变全部现有毒液的生命周期。

目标空间／Store／Collider 先预留；多产物任一预留失败，全组释放，源量不扣。提交时校验源局部版本，版本变化即取消并重新排队。转换量按局部条件、源可用量、目标容量和配置速率共同限制；Water／Steam 的反向转换用分离阈值与冷却时间避免往返抖动。

对每个使用同一 GMU 配方的转换族，长期总账必须满足：初始量+外部注入量=该族所有形态现存量+明确排出量+明确规则消耗量。共享产物的规则归入同一族：首轮 Water／Steam／Ice／Sticky／DriedSlime 共同组成水基族，Steam 只计一次；Poison／ToxicVapor 组成另一族。水基 Sticky 干燥按配方同时记录来源与两种产物，检查族级总量；不能把 Fire 强度或角色 Status 强度纳入这条物质量等式。转换内部不计为世界损失。Pending 预约仍计入源所有权，提交后才转交目标；不出现双重数量或 invisible material。

### 2.5 性能选择与替代方案

| 选择 | 原因与 trade-off |
| --- | --- |
| 稀疏固定固体／Gas 数量场 | 共用坐标与真实查询；需要容量、休眠、出口与局部版本维护 |
| 预分配与局部 Dirty 队列 | 暖机热路径 GC Alloc=0；初始化占用内存，复杂变更需要排队 |
| 固体只重建变化 Chunk | 累积的静止固体不增加重建量；MeshCollider Cooking 的单次成本必须测量 |
| Gas 显示独立于 Simulation | 可裁剪显示，Gameplay 继续正确；可见危险区域必须保留最低表示 |
| 条件规则代替完整热传导 | 首轮闭环可验证，避免引入无依据的全域热模拟；不能对外宣称完整热力学 |
| 第一轮不重写所有 Solver 为 ECS／Jobs／GPU | 先解决工作集合和生命周期；并行化可在证据证明需要后推进 |

按材料类型计数、按局部版本失效；新 Steam 写入不应取消远处 Water 稳定区识别。现有 `StableLiquidRegionDetector` 的材料级版本取消与 `GridLiquidFieldSurfaceRenderer` 的页面依赖在 Phase E 按实际测量检查，不能只增加固气功能后宣称 Boss 卡顿解决。

### 2.6 已确认的外围冻结与提前恢复

以角色的世界位置决定有界活动范围，内部仍以固定 World Space Chunk 寻址；范围移动不搬动材料坐标。采用清晰区、显示过渡区、外围冻结区，并在过渡范围之外保留恢复与传输所需的缓冲。加载阈值与冻结阈值分离，离开后使用宽距离差与短宽限时间，避免同一 Chunk 反复装卸。具体米数与垂直层数在 Phase 0 实测，不先指定一个未经测量的大球。

冻结区保留真实数量、材料身份、支撑／拓扑、模拟所需运动状态与规则剩余时间；暂停流动、扩散、材料反应、转换、材料自身衰减和通风扣量。返回时从保存状态继续推进，不按离开的真实时间执行补算，也不在一帧补跑大量 Tick。全局角色状态、敌人 AI 与飞行 Projectile 不属于本次材料冻结自动扩展的范围；不能借冻结材料顺便修改它们的玩法。

恢复是一个受预算约束的局部准备过程：读取冻结状态、准备必要的活动集合与碰撞、准备首次显示，然后在提交边界启用该 Chunk。玩家移动前方、视野即将进入的过渡范围优先准备；相机预测只用于准备显示，不决定材料模拟是否运行。Dash／传送需要预备或明确的恢复屏障；不能让玩家先走进缺少支撑／危险显示的区域。冻结固体保留已生效的基础阻挡和 Collider，不每帧重建；细致显示可以卸载，材料冻结不会制造导航穿行或地形空洞。

流量进入冻结区之前先经过活动缓冲；到缓冲外沿的跨冻结边界通量暂停，源量保留，恢复后继续输送。这是区域冻结带来的远程传播暂停，不能把边界写成永久 Terrain 墙。未完成的材料转换先提交或取消预约，再冻结，防止保存一半的产物。圈外一次性法术写入仍需通过唯一 Owner 保存或明确报告容量失败；它不能隐式启动持续模拟。该规则在 Phase 0 专门验证远程命中、查询与返场恢复。

冻结只卸载高成本运行／显示资源，保存记录依然占用内存。活动 Store 与冻结记录分开记账，归档容量有明确上限和拒绝原因；到上限时不删旧材料、不丢源量、不无限扩容。首轮优先复用现有 Archive 结构与只读查询，必要的新记录由各后端提供，GMU 与 Fire 强度分别保存。

### 2.7 资源分工、显示遮蔽与工作量预算

固定固体采用 CPU 真实状态与局部几何／Physics 提交、GPU 绘制缓存 Mesh；气体采用 CPU 稀疏活动场、GPU 绘制真实浓度驱动的软体积。现有液体的量和流动也由 CPU Grid Liquid 负责，表面重建／绘制使用 GPU；Fire 的 CPU 真实反应场和 GPU 视觉生命周期分开，不能把现有方案概括为“所有液体都由 GPU 模拟”。

各子系统分别限制活动格／面数、采集量、Dirty／重建页、Collider 准备量、数据上传量与恢复量。只限制每 Tick 处理量不代表全部活动格都有相同频率；同时记录最老待处理时间、实际更新间隔和队列增长率。近处接触与新增材料要及时提交；旧材料的精细工作可以分摊，但保留完整可见结果与正确查询。静止后不再重复求解或提取表面；同类材料尽量使用紧凑场、稳定区域与共享显示资源，避免物质量增加直接增加等量 GameObject／粒子实例。

Fog 是显示遮蔽的可选消费者，没有材料数量与生命期权限。优先比较现有渐隐、低成本距离／高度雾与无 Fog 的同条件结果；真正的 Volumetric Fog 只有在边界体验需要且 GPU 预算允许时采用。雾已遮住的对象还要实际停止表面重建和绘制，才能减少成本。Fog 与所有液体／Fire／Solid／Gas Shader 使用协调的 World Space 范围，检查第三人称相机偏移、俯视、发光火焰与透明材质，不能以强雾遮挡近处危险范围换取性能。

CPU 多核与 GPU 迁移依据测量：先减少不必要工作，再比较可分离计算核的 Job System＋Burst 与单线程；新后端不能每帧回读完整 GPU 场以驱动 Gameplay。完整 GPU Pass 时间未获取时，WaitForGPU 与 CPU Dispatch 时间分别记录，不能替代 GPU 计算成本。CPU 与 GPU 可能重叠执行，全帧预算不能简单把两者所有 Scope 相加。
