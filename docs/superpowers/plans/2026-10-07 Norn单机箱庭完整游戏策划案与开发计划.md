### 0.1 游戏到底是什么

这是一款以法术编程和“万物皆元素”为基础的 **3D 单机箱庭搜集撤离游戏（Hub-based Extraction）**。玩家在据点整理法术、三根法杖、背包和材料容器，进入有限场景探索、战斗、采集，完成地图的轻量撤离条件后把物资带回，再用于下一次冒险和真实材料实验。

首版只做一张用户寻找的外部场景。PvP、剧情、多地图、永久被动、新炼金规则表和据点炼金设备均延期。敌人暂时只概率掉落法术。箱庭不提供保存续玩，据点资产需要持久化。

## 1. 产品定位、体验目标与设计支柱

### 1.1 一句话定位与首版载体

玩家用自己编排的法术和携带的材料，在一个可学习、可探索、可反复进入的箱庭里冒险，把值得保留的发现带回据点。

项目目前采用键鼠角色控制，首版按现有桌面输入实现。目标发布平台、正式目标硬件、发行方式和商业化未在本轮确定；不把这一原型默认扩展成 MMO 或付费资产商城。

### 1.2 四个设计支柱

| 支柱 | 对玩家的承诺 | 对开发的约束 |
|---|---|---|
| 法术是可编排的程序 | 同样的法术能因顺序、修正、多重施法和 Trigger 形成不同用途 | 保留 interpreter，避免为每个组合写专属技能分支 |
| 材料是世界的一部分 | 水、火、毒液、粘液、固体和气体能持续存在并参与状态、采集和投放 | 材料身份、数量、玩法查询与表现不能各维护一份互相矛盾的真相 |
| 有风险的跨局积累 | 本局收获只有真正撤离才能保留；玩家决定带什么、用什么、留什么 | 带入、消耗、保护、搜获和结算都必须基于独立物品身份 |
| 有限地图内稳定体验 | 短途取料和深入挑战都成立，材料增多后仍有清楚的性能边界 | 不能用隐形材料、任意删可见材料或强制长流程掩盖性能和内容问题 |

首版的成功标准是完整循环可玩、规则可靠、能够反复出发，而不是地图数量或系统数量多。探索奖励、材料与法术的用途应能被玩家通过操作和反馈理解。

### 2.2 首版延期

PvP、联网、剧情、多地图、永久被动、据点炼金设备、设备升级、用户未来长篇炼金规则表、材料制作/设备供料等新增用途、其他敌人掉落物、全场景元素化与破坏、箱庭磁盘保存续玩、临时涂覆。

“材料用途留空”指新增用途延期。采集、投掷、撒出、法术附着和真实库存实验已经确定，是首版核心。

### 2.3 内容完成定义（Definition of Done）

玩家可以从据点出发，携带三根以内的法杖和材料容器，在地图里打怪、搜法术、采材料，满足基础撤离条件并返回，结算结果能保存；再次出发能使用带回的物资。死亡/放弃也能可靠结算并获得补缺基础装备。商店交易和实验对真实库存产生正确变化。

完成还要求独立测试、用户 Editor Gate、同局元素压力和多轮资源释放通过，学习文档与交接进度更新。只编译通过、只做出背包或只跑通一次撤离都不算整个首版完成。

## 3. 核心循环、风险决策与示例体验

```text
据点：仓库整理 → 买卖 → 法术/材料试验 → 配置三根法杖与背包 → 选择保护对象
  ↓ 出发，携带资产转入本次冒险
箱庭：观察环境 → 战斗/探索 → 采集或搜获 → 处理背包和材料消耗
  ↓ 玩家决定返程，完成轻量撤离条件
出口：启动撤离 → 区域内存活至倒计时结束
  ↓ 成功：实际携带物进入据点；失败：普通资产损失，保留有效保护对象
据点：结算 → 保存 → 使用新资产 → 下一次冒险
```

短途采样可以只去相对安全区域取少量材料，再完成较轻的出口条件；深入探索可以占用更多时间、空间和资源，换取更稀有的法术或材料。普通地图不设强制总时长，不要求每次出发完整通关。

**体验示例，属于地图设计参考：** 玩家在实验区发现缺少毒液，带空瓶和采样法杖出发，击败控制侧门机关的守卫，采集毒液后撤离。另一轮玩家带更多补给和强力法术进入深区挑战 Boss。首张场景的主题、守卫、机关位置及材料分布尚未确定，不能把示例当作已存在内容。

首版敌人只掉法术，基础撤离条件可以通过“击败指定守卫后开放机关”完成；不要为这个示例额外引入钥匙、设备零件或杂物掉落系统。

## 4. 玩家资产、背包、堆叠与保护

### R01：据点与出发准备（已确认）

据点承接仓库整理、法杖装配、容器准备、商店和真实库存试验。玩家出发前选择本次携带物及受保护法术。地图结束回据点，不直接把所有地面物资算成收获。

### R02：物品定义与实例（已确认需求，技术表达见第 13 节）

同名法术可以有多份，每份分别拥有剩余次数、附着、位置与保护关系。法杖、背包和容器也需要实例身份。配置回答“某类物品是什么”，实例回答“玩家拥有的这一份是什么状态”。

图鉴或已发现法术列表不等于物品库存。看到某个法术不能从 UI 无限复制实例；永久知识也不自动生成相应消耗品。

### R03：二维背包与状态相容堆叠（已确认）

背包按二维格子、尺寸、形状与朝向拼放，物品可旋转、移动、拆分与丢弃。剩余格子总数足够，也可能由于不连续而放不下。

法杖程序槽与背包格子独立；已经安装在法杖上的法术不再占背包格子。容器占背包空间，容器中的材料量单独计量。

普通消耗品、空容器、状态相同的法术可以有上限地堆叠；剩余次数、附着配置、材料组分等不同的物品分别保存；法杖保持独立。具体占格和堆叠上限是配置数值。

堆叠只是空间和展示组织，不能把多份法术的身份合成一个。保护某一份、拆出一份或扣除次数后，必须仍能找到具体实例；状态改变导致不再相容时，需通过明确规则拆分，不能暗中丢弃或挤出物品。

**实施提案：** 容器空满保持相同外部占格；三根可切换法杖采用独立装备位，额外法杖不能通过背包绕过“最多携带 3 根”。背包外壳换装先验证全部物品能否迁移。背包嵌套、重量惩罚和快捷整理不作为首版必做项。装备位表现、堆叠改变时的拆分策略在 M1 界面与规则设计中审阅。

### R13：保护与死亡损失（已确认）

初始 2 个保护名额，每个保护具体一份法术，不因稀有度多占名额，不覆盖所有同名副本。出发前选择，局内锁定；本局新捡到的物品必须成功撤离才能保留，不能临时顶替保护对象。

| 结局 | 带入普通物资 | 本局新物资 | 尚存受保护法术 | 据点未带出资产 |
|---|---|---|---|---|
| 成功撤离 | 带回真实剩余状态 | 带回实际携带内容 | 随携带资产带回 | 保留 |
| 死亡 | 损失 | 损失 | 带回真实剩余次数 | 保留 |
| 强行撤退/主动关闭 | 按死亡处理 | 按死亡处理 | 保留尚存对象 | 保留 |

法杖本体、背包本体、容器及其材料属于普通携带物，失败时损失。法术次数耗尽后不通过保护复原；携带资格的最后一次使用见 R06。保护是否收费和未来扩容没有确定，首版不得暗设稀有度限制或新增保护消耗。

### R14：基础补给（已确认）

失败后有免费基础套装，使玩家能继续出发。只补缺项，不重复制造已有同类基础配置；不设每日次数或等待时间。基础套装不能直接出售或拆解变现。

已有讨论的套装构成为基础法杖、基础无限使用法术、小背包和普通采样容器，具体资产与资格表在配置中确定。免费装备不能卖不代表无限法术制造材料的经济问题已自动解决，R18 另设收购与来源约束。

## 5. 三根法杖、法术编程与资源计量

### R04：法杖属性与切换（已确认）

玩家最多携带 3 根法杖，数字键切换。每根法杖有自己的有序法术配置，以及 Mana 上限、Mana 恢复速度、施法冷却、槽位容量、每次抽取数量。用户所说的 WandLayout 是法术排列概念，当前代码输入容器名是 `WandLoadout`。

未握持的法杖也按自身规则恢复；切换不重置 Mana、冷却或法术状态。单纯用切换和重新实例化装备清除冷却会违反该规则。

Mana、使用次数、携带资格和容器材料是四种资源：Mana 会恢复，有限使用次数会耗尽，携带资格以冒险为单位消费，附着则转移真实材料。UI 必须分别说明。

### R05：普通产出法术次数（已确认）

法术可以无限使用或有限使用。有限产出法术按指令执行扣一次，同一次执行的分裂产出不会按颗数倍增扣次；多条独立指令分别计量。无限使用仍受 Mana 与冷却约束，失败时仍可能丢失。

不能按玩家点击、投射物是否命中或求值命令列表长度简单扣次数。Mana 不足而整次施法失败不扣；缺失 Prefab、非法配置或无法提交产出时，需要明确失败反馈和资源回滚。

### R06：修正和多重施法的携带资格（已确认）

装在三根法杖内的修正/多重施法卡进入箱庭时扣一次携带次数；背包备用卡本局首次安装时补扣。获得本次资格后局内无限使用，卸下重装不重复扣，换法杖也不重复扣。

最后一次资格用完，本局仍可使用，冒险结束后卡耗尽。保护不能恢复已经用尽的下一局资格；这张卡在最后一次冒险中使用和在终局后销毁是两个时点。

技术上需要“剩余未来资格”和“已经取得的本局资格”两份状态，不能在入场扣成 0 后立即删掉本局仍能用的卡，也不能退出后把它自动补回 1。

### R07：Trigger 的预扣规则（已确认）

成功施法开始时，一次预扣 Trigger 与后续 Payload 中相关有限使用次数。没有触发不退；Mana 不足导致整次失败不扣。修正/多重施法仍用本局资格，不额外按每次 Trigger 扣携带次数。

Payload 的程序和修正快照需在发射时保存，不能因后来更换法杖、移动卡片或耗尽实例，改写已经发出的法术。Trigger 的后续程序严格是较短的后缀，继续保留现有递归和输出上限。

**实施边界：** 预扣使用次数不自动等于预付所有层的 Mana。当前生产代码 Payload 触发时分层支付 Mana；采用原法杖还是当前法杖支付、分裂父体的多次独立 Payload 如何预算、施法排队中切换法杖如何锁定来源，属于 M2 必须审阅并测试的技术提案，不能由已有一次“同意预扣”暗推全部细节。

**推荐技术方向：** 锁定发射来源法杖与程序快照，使用有限且可追踪的子层执行预算；分裂共享既有预算与材料，不能复制稀有材料或把一次预扣变成无界子层执行。对原本会多次独立执行的 Payload，需要在起始执行计划中计算预扣次数。正式实现前以真实解释器路径验证。

### 5.1 稀有法术与奖励

稀有法术与普通法术使用同一套资产和解释规则，获取更难、效果更强。稀有度不免除次数或失败损失，不额外改变保护名额。强度、稀有度与掉落权重由数据定义，具体列表和数值在内容阶段填写。

## 6. 统一材料世界、采集与三种容器用法

### R08：世界与库存真实转移（已确认）

材料是持有身份与数量的世界数据，不只是一张 VFX。固体、液体、气体都属于同一材料世界，但使用不同模拟表示。采集量多少，世界就减少多少；释放量多少，容器就减少多少，世界收到对应数量。

不按液体 Mesh 高度、气体透明度或 GPU 可见像素反推材料量。容器存放稳定材料键、数量和组分；库存内不为每格材料继续创建世界 Solver 或 GameObject。

### R09：固定速度近距离采样（已确认）

玩家靠近材料，以固定速度采集。不是远距离吸取全地图，也不默认选中名称就分离混合物。采到混合区域后容器也是混合组分；液体与气体通过容器保存，合适稳定固体可装入容器或直接形成材料物品。

具体距离、每秒数量、采样区域和交互按键是配置。只转移实际存在且可装下的量；容器满、目标消失、版本改变或几何操作失败时保持数量一致并反馈原因。

当前材料身份协议：Water=1、Fire=2、Poison=3、Sticky=4、Ice=5、DriedSlime=6、Steam=7、ToxicVapor=8。是否某类材料可以装入某种容器，由兼容规则表达；“万物皆元素”不要求普通瓶子首版无条件收走火焰、整片地面或所有建筑。

### R10：三种使用方式（已确认）

| 方式 | 玩家操作结果 | 必须满足的数量与资产规则 |
|---|---|---|
| 投掷破碎 | 容器飞出，碰撞破碎，存料进入目标区域 | 投掷容器本体损失；组分全部有明确去向；不能在飞行时同时保留一份装满的背包容器 |
| 慢慢向前撒出 | 持续向角色前方投放材料，松开或耗尽后停止 | 每次只扣实际提交量，混合物按实际组分投放，容量/投放队列拒绝时不能继续扣空 |
| 附着某份法术 | 配置供料容器与剂量，法术输出携带额外材料 | 配置绑定具体卡实例，实际产出时取料，不足剂量部分附着，空容器仍可基础施法 |

混合材料容器不因为选择其中一个名称就变成免费分离器。首版采用按实际组分取料的方向，器内分层与化学反应留给后续规则扩展。

**容器内保存的技术提案：** 用紧凑组分表封存数量，不运行逐格流动、扩散或自动炼金。已存在材料投回世界后继续按世界规则行为；新增器内反应需要未来炼金定义。实际组分必须可被 UI 检查，不能以“混合”丢失身份。

### R11：持续附着与部分剂量（已确认）

附着配置属于某一份法术，持续至关闭或调整；同名副本可以分别配置。未参与本次产出的卡不耗料。来源不存在、空了或被投掷后，基础法术仍能执行，并显示供料失效。

不足一次设定剂量时转移实际剩余量，不能凭空补齐。一次分裂/多输出必须共享或按明确预算分配实际材料，不能每颗复制整份剂量。附着产生什么反应由材料世界决定，不另外写一套特殊组合反应表。

**实施提案：** 剂量按每条独立产出指令计量，子产物分配该剂量；独立的 Payload 输出另行取料。来源按容器实例 ID 关联；移动法术保留自身配置，删除源容器使关联失效。剂量与多输出分配在 M3 的执行计划中审阅。

## 7. 地图、敌人、探索收益与撤离

### R12：首张场景与接入边界（已确认）

首版只有一张用户在网上寻找的场景。基于其现有空间增加水、毒液、粘液、火、固体、气体、敌人和探索物。原墙、地面、家具先保留其结构与普通碰撞，不在首版全面元素化或可采挖。

用户尚未选定场景；本文不虚构地图面积、房间数量、故事背景和精确机关位置。接入前检查 URP、单位比例、Collider、角色通行、光照、材质、可放置元素与敌人的区域。可独立于场景的 M1—M5 使用灰盒直接测试。

### R15：固定布局、有限资源和同局状态（已确认）

地图布局保持可学习，在作者设定的候选位置允许有限资源/敌人编组变化；变化不能移走必需撤离对象或阻断基础出口。初始储备、探索物与普通敌人消耗后维持本局状态，圈外再返回不会重刷。增援和持续环境来源有单局边界。

此有限资源规则不代表已经解决无限法术的材料生产或 Boss 同局积累；资源输入、稳定表示和材料去向仍需性能验收。

### R16：首版敌人只概率掉法术（已确认）

复用已有敌人战斗能力，死亡按配置概率掉落各种法术。掉落表表达无掉落概率、候选定义、权重与实例初始状态。拾取进入真实库存，包满明确提示，物品留在地图，不自动解锁无限法术。

同名重复奖励允许存在，不使用 P7 的“定义已解锁则奖励去重”规则。每个死亡来源最多结算一次掉落，死亡事件重复投递不能复制奖励。

首版不做设备零件、图纸、可售杂物或金币实物掉落。地图机关可直接消费战斗/交互事件开放路线，不额外扩张掉落物类别。

### R17：轻量条件的基础撤离路线（已确认）

首张地图提供较轻条件的基础路线，支持为少量材料短途出发。深区与 Boss 可提供更好的收益或捷径，Boss 不成为所有冒险的必需门槛。

基础条件的示例为启动机关或击败指定守卫；具体选择依场景。玩家需要收到当前条件、出口位置/方向和是否可用的反馈，不依靠看不见的门槛。

解锁后玩家进入实际撤离区域并主动启动短倒计时。区域内可移动、施法和防御；普通受伤、毒和燃烧不取消准备；离开或主动取消后重新计时。结束前死亡按失败处理，只结算当时实际携带物。

**终局竞争的技术提案：** 同帧死亡和倒计时结束由单一终局状态机裁决，建议已死亡则失败优先；结果仅提交一次。倒计时秒数与范围是配置，不把此前讨论示例 5 秒当成用户固定数值。

## 8. 商店、货币与真实库存实验

### R18：首版商店（已确认）

支持法术、法杖、元素和容器买卖。设备与其商店条目延期。商店有有限供货与收购预算，随明确冒险进展更新，反复进出据点或箱庭不会自动刷新。

材料身份不按“来自法术”与“来自地图”分成两种。法术生成的材料可以继续参与材料世界、采集和库存；经济通过供给、预算、价格与稀有产出定义管理，不能在系统里暗加一个玩家看不懂的假材料类型。

交易需要检查余额、库存空间、可出售资格、货源与收购额度，并以整笔提交改变双方资产。免费基础套装不可直接出售/拆解变现。材料销售需要说明是出售瓶中材料还是瓶壳，不能一个按钮静默同时卖掉二者。

**实施提案：** 首版使用据点钱包数字货币，不做金币实物掉落；交易只在据点进行。买元素时要求容器有兼容空间，卖元素按实际组分转移，卖空容器作为实体物品。商店用冒险进展记录决定刷新机会，不用现实日期或仅进入地图触发。货币表示、交易 UI、刷新进展事件和价格表在 M5 一并审阅。

有限收购预算能限制部分无限造料卖钱，但不能单独保证稀有材料仍值得探索。必须审查“无限法术能生成什么材料、生成开销、收购价格与奖励消耗”的闭环。数据中发现冲突时优先调整产出与经济配置，不能宣称预算表天然解决所有漏洞。

### R19：据点实验消耗真实库存（已确认）

玩家从容器释放材料到实验区、给法术附着或施法时，都按真实数量与规则消费库存和法术资源。使用现有世界行为观察材料，不提供可带回仓库的免费试验材料。

未被反应消耗的材料仍是真实世界材料，允许按正常采集规则回收；这不等于凭空补库存。实验区不提供免费的材料分离、净化或创造接口。

2026-10-09用户明确补充：离开据点Scene时释放尚留世界中的材料，返回生成空实验世界，不在每次出发前询问残留。可靠出发/加载失败时尚未离开，保留原世界；已采回容器内的材料按真实库存持久化。只在据点内走出实验区域仍暂停模拟、回来恢复，不触发Scene清空。

新增炼金配方、材料制作用途与据点设备留空，未来由用户提供规则表后扩展。首版可用明确划定的实验空间和当前材料/法术反馈，不设计设备制造或新反应表作为验收前提。

## 9. 冒险状态、据点持久化与异常边界

### 9.1 玩家能理解的状态流程

```text
HubReady → Preparing → Departing → Exploring
                                  ├→ Extracting → SettlingSuccess → HubReady
                                  └→ SettlingFailure → HubReady
```

Extracting 离开/取消回 Exploring；死亡、强退或主动关闭进入 Failure。每次冒险有唯一 RaidId，终局只能提交一次。新冒险重建初始世界，旧世界在结果可靠提交后释放。

### 9.2 箱庭不保存与据点要保存（已确认）

首版不保存敌人、机关、世界材料和角色位置供下次继续冒险。同一进程中的远处冻结、返回恢复仍保留本局因果，不能误当成取消这部分功能。

据点保存库存、钱包、装备、法术次数和配置、容器组分、商店进展及已结算记录。出发必须把携带物从仓库归属移入本局，不能留下可再次使用的副本。保存使用稳定内容 ID 和实例 ID，不使用显示名称或 Unity GetInstanceID。

### 9.3 主动关闭与异常崩溃

主动关闭游戏按失败结算已确认。进程可能在无法执行 OnApplicationQuit 的情况下结束，所以不能仅靠退出回调扣物资。

**技术提案：** 据点 Profile 记录 PendingRaid 与携带/保护资产、资格消耗和事务代号。正常结束清除 PendingRaid 并提交终局；重启发现未结束 Raid 时按明确恢复策略处理，不恢复箱庭世界。原子保存、备份与幂等结算保证不会把物品同时放在仓库和冒险。

**必须在 M4 前确认的异常策略：** 崩溃是否完全等同失败、受保护法术使用次数按哪个可靠提交点恢复、可容许的日志偏差。当前没有承诺崩溃瞬间每次施法都已落盘，也没有批准崩溃后完整冒险恢复。即便采取失败策略，也要先保留损坏存档与错误信息，不能用新建空档悄悄覆盖。

## 11. 性能目标、材料生命周期与不能破坏的体验

### R20：空间与工作量分层（已确认方向）

玩家周围有限区域内保持材料体验，圈外暂停模拟，同一次冒险返回后恢复；摄像机看不到不等于玩家附近材料可以停止产生危害。视锥剔除主要减少表现成本，活动区域决定模拟范围，稳定材料休眠减少无需变化的数据工作。

| 层次 | 保留什么 | 可以停什么 | 唤醒条件 |
|---|---|---|---|
| 近处正在变化 | 身份、数量、速度/行为、查询与画面 | 无关远区、未变化表现重建 | 正常活动 |
| 近处稳定材料 | 实际存量、碰撞/状态查询、可见表面 | 重复 Solver、无变化 Mesh/采样重建 | 新材料、采集、反应、几何变化 |
| 同局远区冻结 | 本次储备、采集结果、材料与机关状态 | 材料模拟及其表现资源更新 | 玩家接近或真实影响到达边界 |
| 背包容器 | 紧凑组分与数量 | 逐格流动、世界 Collider、渲染 Solver | 撒出/投掷/附着实际取料 |
| 冒险终局 | 据点资产与结算记录 | 旧世界所有实例工作 | 下一局重建初始场景 |

活动边界使用缓冲和 hysteresis，防止来回跨线反复激活；画面过渡可以借助已有环境雾和渐变，不把雾自动扩展为新体积雾研发。模拟半径与表现半径是参数，最终根据视距和硬件定，不把一个很小近区制造成明显远近分界线。

### 11.1 为什么落地稳定后仍可能卡

稳定材料也可能产生遍历、场景查询、表面重建、数据上传、readback、Draw Call、透明 Overdraw、阴影和固定 Tick 追帧成本。GPU 等待样本既可能是 GPU 工作，也可能是同步和读回造成的等待，需要同时看 Timeline、相关代码与 GPU 数据。

优化依据真实瓶颈，优先睡眠/脏标记、局部更新、缓冲复用、空间查询、实例与表现资源管理。不能仅靠“没有流动”判断成本，也不能把等待全算成流体计算。

### 11.2 数量去向与感知约束

采集真实移走材料，撒出/附着真实释放材料，既有反应消耗按材料账本记录，稀薄气体可按现有阈值渐淡清理。固体不在无外界条件下为省性能强行快速融化；可见且有玩法的液体不因数量大就消失。

有限地图初始资源和终局重置解决跨局积累，但无限法术与 Boss 在同局仍可增加材料。长期输入可能超过去向，这是性能和内容共同风险。首版不假定收集玩法能自动消耗所有材料；必要调整要让玩家能理解，并保持已确认规则。

### 11.3 性能验收目标与记录方法

- 以 60 FPS / 16.67 ms 为建议目标预算；目标硬件和分辨率尚未确定，不承诺未测的数值。
- 记录 CPU 与 GPU median/p95/p99、帧峰值、GC Alloc、活动/冻结 Chunk、稳定/动态材料、三相数量、待处理队列、Mesh/渲染资源和 Draw Call。
- 同机同分辨率测空地图基线、稳定材料多、混合连续施法、采集/撒出/投掷并行、远近往返、Boss 压力和终局释放。
- 建议连续 10 分钟压力、至少 3 次出发结算回据点，比较内存/资源和静态订阅是否回到相应基线；这是建议测试长度，不是地图强制限时。
- Profiler 默认关闭 Deep Profile，单独记录保存、场景加载、首次池预热和 Shader 编译；不要把 Editor 开销当作全部运行成本。
- 新增每帧热路径 GC Alloc=0，离散资产操作的分配单独统计。异常增长或数据未释放必须有复现和根因记录。

| RuntimeItemState / ItemOwnershipStore（Run） | InstanceId、ContentId、唯一 Location、动态子状态 | 发放/拾取创建，恢复保留身份；Run 统一迁移 |
| InventoryGrid / GridPlacement（Run） | Footprint、占格、方向与所属背包 | 布局变更时更新，不逐帧重建 |
| WandRuntimeState（Run） | 安装的实例槽、当前 Mana/冷却、固定属性引用 | 随法杖实例存在；切换不重置 |
| SpellUseState / RaidSpellEligibility（Run） | 剩余使用/携带次数、本局资格、预扣记录 | 施法/出发/安装时事务更新 |
| SpellAttachmentState（Run） | 卡实例 ID、源容器 ID、剂量与开启状态 | 卡配置；真实产出时读并取料 |
| ContainerComposition（Run） | 稳定材料键与数量、总容量、兼容信息 | 库存紧凑数据；转移事务修改 |
| MaterialItemState（Run） | 可直接携带的稳定固体材料键、数量和占格定义 | 采集进入资产归属；释放时恢复世界数量，不逐颗模拟 |
| SinglePlayerProfile（Run） | 资产、钱包、商店进展、PendingRaid、已结算代号 | 据点与资产层磁盘保存 |
| RaidState（Run） | RaidId、阶段、携带归属、保护锁、本次已用资格、撤离条件 | 进程内本局；不保存世界供续玩 |
| CastExecutionUse（Skills） | 程序索引、执行层、参与/产出、子层预算 | 调用方复用 Buffer，Run 实例通过索引映射 |
| MaterialAmount / 交易事件（Core） | byte MaterialKey、ulong Quantity、RequestId、版本与结果码 | 无上层引用；队列或同步请求持有有效快照 |

ContentId 是稳定配置键，InstanceId 是一份资产身份，RaidId 是一轮冒险身份，RequestId 防重复请求。不能混用这些身份，也不能用 GetInstanceID 做磁盘键。字符串/Guid 只在新资产和事务创建等离散操作生成。

堆叠保留实例集合，合并不销毁各自身份。容量单位统一转换后使用整数累计；溢出、未知材料键和负数量输入拒绝。视觉体积和材料数量允许有美术比例，但采集/释放/相变必须用同一权威计量。

### 13.3 原子事务与幂等

原子事务（Atomic Transaction）表示一组操作一起成功或一起保持原状态，幂等（Idempotency）表示同一请求重复到达不重复改变结果。

```text
移动：检查来源与目标版本/空间 → 统一迁移归属和占格 → 发布结果与版本
交易：检查余额/库存/额度/资格 → 一次提交双方资产 → 发布收据
采集：预留容器空间 → 世界验证并预留真实数量 → 提交双端数量 → 账本与结果
释放：预留世界投放能力 → 扣容器实际量 → 世界接收 → 账本与结果
结算：核对 RaidId 与未结算状态 → 转移/损失/保护 → 保存提交 → 发布结果并释放世界
```

队列接受不是任意未来容量的保证。投放若只能暂缓，必须保留已承诺数量的唯一 Owner 和查询；若无法接受，库存不扣。投掷中的材料由投掷实例持有，不能在背包、飞行体和世界同时记三份。

跨场景前完成或取消在途事务；容器预留期间不允许另一操作破坏预留。超时、重复请求、失效版本或消费者已销毁都要有明确结果，不能把丢失的结果通知当作转移完成。
