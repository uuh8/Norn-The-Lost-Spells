# 法杖入包、选中容器购买与物品轮廓落格修正 Implementation Plan

> 在当前工作区由主代理按 executing-plans 实施，不使用 SubAgent/worktree，不提交，不自动保存或丢弃正式 Scene。设计与实施合在本文件，不另建 spec。本轮聚焦三个已出现的玩家操作问题，完成后一次交付 Editor 验收。

**Goal：** 法杖可购买进背包并从仓库拖入；元素购买明确注入中列选中的具体容器；容器不堆叠；物品落格跟随实际拖拽轮廓，同时保持鼠标抓取位置。

**Architecture：** 沿用 Run 的归属表、候选交易、Repository 和 Core 事件，UI 不直接改金币或组分。装备法杖仍为 1–3 槽；备用杖进入背包按形状占格，解除旧“总携带三杖”限制。容器按独立 InstanceId 呈现，落格定位在 UI 层统一，最终空间与交易仍由 Run 仲裁。

**Tech Stack：** Unity 6000.3.16f1、UGUI/EventSystem、Input System、RectTransform、ScriptableObject、EventBus、既有 InventoryPlacementPreview/ShopTradeService。

## 1. 用户要求、证据与待确认规则

1. 用户购买法杖默认进仓库且无法拖入背包。`ItemOwnershipStore.ValidateCarriedWands` 把已装备和装备背包内的法杖一起计入上限 3；初始三杖已占满。快捷交易实际尝试了背包，但被这个规则拒绝，然后回退仓库。推荐改为只限制装备槽三根，备用杖消耗实际背包空间，不自动替换现有装备。背包外壳仍不能嵌套。
2. 用户要求中列背包/仓库选中容器后，才可买液体/气体；每个容器独立显示余量、不能堆叠。当前 ShopController.Send 从 `_containers` Dropdown 取第一个/既有容器；SelectOffer 清空 owned 选择，SelectOwned 清空商品选择，两者不能共存。`bottle.asset` 的 `_maxStack` 为 3；WarehouseCatalogGridView 按 ContentId 归类所有容器。
3. 用户希望落格由实际移动后的图片/轮廓决定，而不是要求鼠标进入目标格。当前 MoveGhost 用连续抓取点保持手感，但 PreviewGrid/SubmitToBackpack 用鼠标 Floor 格坐标减整数 `_grab`，导致量化时机取决于格内点击位置。保留连续抓取点，改为根据 Ghost 的实际轮廓左上角转换到目标 Grid Local Space，再吸附最近格；预览、OnDrop、OnEndDrag使用同一坐标。依据的是物品占格轮廓，不能用有透明留白的 Sprite 像素尺寸代替真实形状。

## 2. 方案、失败反馈与 trade-off

- 法杖：装备槽本来就是 3 个且已有 SlotIndex 验证，移除总携带数量校验，不新增法杖专用仓库通道。空包买新杖进包，满包仍回退仓库；仓库拖入失败只因空间/位置等明确原因，保留原资产。RaidPreparation 当前只统计 EquippedWand，因此仍符合 1–3 杖出发规则。
- 容器：商品选择与中列物品选择各自保留。点元素商品不取消中列容器；点另一个物品或取消中列选择则重新验证目标。禁用购买按钮并给出“请在背包或仓库选中兼容容器”等原因；再次点击弹层和下方按钮走同一检查。送出交易只传当前选中的 InstanceId，后台继续复核归属、容量、材料兼容、版本、供货和币值；满瓶/不兼容/已移动/已删除不扣钱、不自动换瓶。Dropdown 退出快捷购买目标决策，不让隐藏控件参与交易。
- 不堆叠：容器 MaxStack 固定为 1，背包拒绝同格合并；仓库同类容器每份一个方格，显示自己的 Total/Capacity，其他材料/法术仍按类汇总。保留所有已有 InstanceId、组分、道具绑定、法术附着引用。旧同格容器若恢复时出现，按原顺序保留一份原位，其余寻找背包空位，放不下回仓库；不清档、不删除或合并材料。合法旧布局尽量保留；未知损坏继续明确拒绝。
- 轮廓落格：保留 PointerDown 抓取点，Ghost 不跳动；以视觉轮廓最近格的坐标投影代替鼠标格量化。CanvasScaler、源与目标不同 CellSize、滚动、中键平移、旋转都转换真实坐标。轮廓进入可见目标网格时，鼠标仍在旧格也能预览/放置；网格边界外不偷偷夹到合法位。保留临时重叠红框与切换选择撤销、整叠/Shift 拆分和界面外丢弃语义；Nearby 的自由排布采用相同定位，避免两种拖拽手感。

不采用 UI 再发第二笔购买、自动挑瓶、隐藏额外杖或仅改变显示数量；这些做法会造成资金/目标不明确。无需新模块、新 EventBus 通道或外部依赖。

## 3. 资产依赖与精修保护

复用现有 InventoryItemView/DragGhost/Grid/Image/Text、物品图标和 PickupItemEntry Sprite，用户不需要补充素材；图标缺失沿用当前名称显示。容器定义位于 `Assets/_Project/ScriptableObjects/SinglePlayer/Items/Container/` 以及 `Hub/SinglePlayerContainers/bottle.asset`，只规范堆叠字段，不改模型、Sprite Import、容量或兼容材料。保留用户商店/仓库排布与右侧详情占位，正式场景增量变化用 Undo，最后保持单独据点入口，绝不留下 Hub/P7/P8 Additive 混合状态。
