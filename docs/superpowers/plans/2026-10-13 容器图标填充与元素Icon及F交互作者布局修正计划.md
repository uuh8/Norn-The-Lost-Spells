## 1. 玩家效果与根因

容器的五位数储量在小格中溢出；改为容器图片本身自下而上的蓝色填充，空瓶保留原图，满瓶完全着色。背包、附近物品、仓库、商店内库存、道具栏和手持栏复用同一表现。普通物品数量和有限法术次数继续保留；道具栏只留快捷键数字和图标，删除名字、空位说明及容量数字。

商店材料报价没有 ContentId，ShopOfferSnapshot 的现有分支直接返回 Icon=null，因此需要在报价 Authoring 数据中提供 Sprite。冰球 PNG 已由 Single Sprite 改为 Multiple Sprite，法术资产仍引用旧 fileID 21300000，而当前子 Sprite 的 internalID 已改变；通过 AssetDatabase 获取实际子 Sprite 修复引用，保留裁剪与导入配置。

NearbyPickupListView 每帧 ApplyAnchor 会覆盖作者 Panel 的 RectTransform，另复制 Station entry 分支并强制放在(0,0)。移除复制和持续定位，站点/门和拾取共用 Entry 池。所有交互仍由已有 F 仲裁处理，不改变交易/拾取/传送优先级。先输出实际 Text/背景 Rect 数据，再针对对齐修正，避免把整个作者界面重建。

## 2. 资源与实现取舍

素材实际目录是 Assets/_Project/Art/UI/Funtion_UI2（目录原名保留），八张 PNG：water、Fire、poison、Mucus、Ice、Dry mucus、Steam、poison gas。用途分别为水、火、毒液、黏液、冰、干黏液、蒸汽、毒气报价。实际检查发现八张图都设置为 Multiple Sprite，却没有任何切片；仅这类空切片资源改为 Single Sprite，再绑定真实 Sprite。RGBA/sRGB、Alpha Is Transparency、无 Mip Maps，保留现有分辨率及其他导入设置，建议单图256–1024像素；缺少或多于一个候选时报告而不绑定猜测资产。冰球保留 Skill_Icon/Spell_Emit_Iceball.png 已有的 Multiple Sprite 裁剪，并使用其中实际子 Sprite。

采用 UGUI Image.Type.Filled + Vertical + Bottom 的同 Sprite 叠层，填充 Image 是原 Icon 的子对象，局部 stretch，不改变原 Icon 的位置/尺寸。蓝色 tint 默认可在各 Slot Prefab 的 CapacityFill.color 编辑。Sprite alpha 保留图片轮廓，不画整格色块。首轮截图发现普通 UI RGB 乘法把棕色容器染成很暗的绿色，因此增补 ContainerCapacityFill Shader：以 Sprite 亮度保留细节，再乘统一容量颜色，alpha 和 UGUI Stencil/RectMask 裁剪保留。颜色公式为 tint.rgb × (0.65 + 0.35 × luminance)，明确提高识别度。没有新贴图依赖；共享 Resources/ContainerIconFill.mat 在初始化加载，不为每格生成 Material。代价是多一个 Graphic 和极简 fragment pass；层只在容器有内容时开启。容量比例先用 double 相除再 Clamp01，避免 ulong 整数除法和溢出。填充层在初始化/池预热创建，不在稳定帧创建；刷新只写变化的 sprite/ratio/enabled。
