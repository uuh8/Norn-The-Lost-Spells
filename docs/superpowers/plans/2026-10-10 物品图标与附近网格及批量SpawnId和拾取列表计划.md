## 2. 一次扫描补齐 SpawnId

菜单拟为 `Tools/Norn/物品/扫描当前场景并补齐 SpawnId（Undo，不保存）`，Inspector 增加同名入口并支持多选。

扫描当前 active Scene，包括停用对象上的 `WorldItemSpawnPoint`，不改其他加载 Scene、不扫描 Prefab Asset、不处理纯美术装饰。对空白编号分配 `Guid.NewGuid().ToString("N")`；已有非空编号保持原值。报告扫描数量、新生成数量、重复编号、缺失 Definition、SceneKey 与 Session 不匹配对象，报告可定位 Hierarchy。

重复键为 SceneKey + SpawnId。**默认不自动改重复的非空编号**：复制品与原物品都可能具有同一值，仅凭遍历顺序无法证明哪个才是存档记录对应的原点。提供单独的“对选中的复制品重新编号”操作，先选定复制品，再由工具生成，避免扫描悄悄使原物品重新发放。复用现有单物品按钮作为明确操作。

一次批量修改使用一个 Undo group，记录组件并写入 Prefab Instance override，标记该 Scene dirty，不保存。可在当前已有未保存修改的场景运行，因为不切换、不覆盖、不丢弃；自动测试仍遵守现有未保存 Scene 拒绝规则。再次扫描无空编号时只报告，不修改、不再次标脏。

SpawnId 是投放点稳定身份；InstanceId 是已生成资产的实例身份；ContentId 是共享物品种类身份，三者不能互换。保留稳定 SpawnId 才能保证拾取/出售后返回据点不会重复发放。不在 Awake、OnEnable、每次 Play 或 Update 自动生成。

## 3. 图片获取与网格辨认

### 3.1 方案选择

推荐 **Editor 中批量拍摄已有 WorldModel，导出 PNG 并绑定 Sprite**。选择理由：直接使用用户18个模型，外观匹配，统一灯光与角度，游戏只显示资源，没有每个物品一台运行时 Camera 的成本。

替代一：导出 AssetPreview 缩略图，工具更简单，但构图、背景与生成时机受 Editor 预览控制；可作调试 fallback，不作为正式图标管线。替代二：手绘或生成图标，美术表达更强，但需要额外资产且容易与已有模型外观不一致，本批不要求用户新提供素材。

### 3.3 渲染实现与学习要点

在隔离 Preview Scene 内实例化源模型，使用 Renderer Bounds 找出可见包围盒。Bounds 是世界空间范围，Camera 的取景是镜头空间范围；根据包围盒角点转换后的宽高决定 orthographicSize，使正交相机不会因模型大小不同而裁切。灯光采用统一主光/补光；不继承据点夜景、雾和后处理。

URP 使用 `UniversalRenderPipeline.SingleCameraRequest` 与 `RenderPipeline.SubmitRenderRequest`，检查 SupportsRenderRequest；输出到独立 RGBA RenderTexture，再一次性读取 PNG。摄像机清理透明背景、关闭后处理；需在当前 Renderer 实测 Alpha 是否保留，失败修正输出路径而不全局修改 URP 资产。此工作只在 Editor 菜单执行，可接受一次性分配与 GPU Readback。

临时相机、光源、模型明确归属 Preview Scene；try/finally 释放 Texture、RenderTexture 和 Scene，恢复 active Scene、RenderTexture.active 及任何临时环境设置，禁止误把对象加入用户当前 Scene。不通过 Render 回调触发嵌套渲染。

官方依据：[Unity 6000.3 URP Render Requests](https://docs.unity.com/en-us/engine/6000.3/manual/cameras/urp/multiple/user-render-requests)。

### 3.4 同一个物品看起来是整体

占格仍由原 Shape 裁定，旋转90度保持空洞。绘制同物品连续底色，弱化内部格线，仅强化实际占格形状的外轮廓和选中态。图标每件显示一次，优先放在其连续实心区域内并保持比例；细长/异形图标不得覆盖可放其他物品的空洞，必要时用较小图标保留名称辅助。数量/容器容量放角落，避免文字占据整张图。拖拽 Ghost 使用同一图标、轮廓与旋转状态，仍以真实占格和 Raycast Filter 决定落点。

共享 Icon 经现有只读快照传播；已有商店、仓库消费者自然获得图片，不重排其页面。模型拍摄是共享种类的表示，动态次数、组分、容量仍显示为实例数据。

### 3.5 用户追加：可拾取物品表面轻微发光

2026-10-10用户确认计划时要求：可收集物体表面增加轻微发光，帮助区分地图装饰。本项纳入Task B，复用真实世界代理的生命周期，只对仍在地面的可拾取资产显示，拾取/销毁时消失；纯美术装饰、图标拍摄预览、商店陈列不自动发光。

优先在隔离的运行时材质副本上启用适配Shader的Emission，弱暖白/淡金色、默认无脉冲，原有颜色/纹理/透明度保持。URP Lit的Emission关键字属于Material状态，仅写MaterialPropertyBlock不能启用关键字；必须明确运行时副本所有权与释放，不能修改sharedMaterial资产。颜色/强度在表现配置SO中调节，不在Update创建Material。Emission能让表面看起来发亮，画面外溢光晕依赖Bloom，本批不全局开启或修改后处理以实现发光。特殊透明/自定义Shader须逐材质验证能力，不能盲目套同一材质导致瓶子不透明；必要时使用局部轻微轮廓fallback。

由Game.Run通过Core代理生命周期事件通知Game.Rendering表现绑定器，Rendering不回写库存，Run不直接引用Rendering。新增文件拟为`Scripts/Core/Events/WorldItemVisualBoundEvent.cs`、`Scripts/Rendering/Items/WorldItemHighlightBinder.cs`、`Scripts/Rendering/Items/WorldItemHighlightProfile.cs`，配置资产放`ScriptableObjects/SinglePlayer/Items/Presentation/`；具体路径在实现前结合材质验证收敛，不使ItemDefinition查询将表现配置误当可携带物品。验证白天/夜间草药、容器、食物，发光足够轻微且能识别；记录额外材质实例/Draw Call与稳定帧GC。

## 4. 固定位置的多物品拾取列表

使用 Screen Space Overlay HUD，默认在屏幕右侧中部偏下；RectTransform anchor、offset、行高、最大行数在 Inspector 可调。它不读取物品屏幕位置，不执行 Billboard，不随镜头旋转/远近移动，也不会因物品暂时在镜头后方隐藏。候选依旧取决于同场景、同库存、真实距离、代理启用与归属合法性。

Game.Run 每0.1秒以预分配缓冲扫描附近代理，默认仍为3m。候选按距离排序，距离相同按 InstanceId 排序；只存真实可拾取物品。排序使用可复用比较逻辑，禁止热路径 LINQ、闭包、装箱或构建新数组。以候选集合变化、库存版本和选中身份变化驱动 UI 更新。

首次显示选择最近项，随后保持玩家选中的 InstanceId，移动造成排序变化不擅自切换目标。默认最多显示5行；超过5件滚轮可选择全部候选并自动滚动可视窗口；列表显示还有多少未展示项。每行图标、名称、数量，高亮行显示 F；不同实例即使同名也保持独立，不把不同容器内容合并。

鼠标滚轮切换高亮，F 拾取高亮的具体实例。拾取前重新校验距离、场景、归属和冻结状态，不只相信0.1秒前的快照。不合法目标拒绝操作并刷新；成功后选择原索引相邻项。空间不足继续使用原事务失败 → 打开背包 → 选中该物品；地面物品保留，不自动拾取别件。F 不再无视玩家选择重新取最近目标。

滚轮占用只在游戏有焦点、未暂停、背包/其他模态界面关闭且候选列表可用时成立；停用、Scene 切换、失焦、Pause 必须释放。Input System 的两个独立 InputAction 不会自动互相吞掉输入，故若确有镜头滚轮消费者，需检查 Core 的滚轮占用契约，使相机跳过该输入；不禁用整个 Player ActionMap 或镜头组件。打开背包后滚轮交给 ScrollRect，左键镜头旋转及其他旧操作保持。

Core 新增只读附近候选契约与变更事件，载荷只通知 InventoryId/Revision/选中 ItemId，不每帧分配 List 或发布 UI 类型。UI 读快照，Game.Run 负责选中状态；Character 直接调用现有 Run 输入入口，延续已确认工程依赖。只在必要时增补滚轮占用契约，不建立新的通用输入框架。

## 5. 附近区域的动态网格

新增只用于 UI 的附近网格布局器，输入附近具体物品的 Shape，输出临时 X/Y。默认 CellSize 与背包一致，按可视宽度定列数，按需要增加行数；物品比可视宽度还宽时扩展 Content 并允许横向滚动，不能缩小至难辨认或丢失物品。

采用确定性 first-fit 排布，从左上搜索可用位置，以实际 OccupiedCells 检查重叠，支持矩形、L形及空洞。世界资产没有背包朝向，首版以0度展示临时形状；拖拽明确携带显示朝向，用户拖出后仍可 R 旋转。展示无需把世界物品移动进一个假的 Backpack，临时布局不进入 Profile、SaveDto 或 ItemLocation。

Content 绘制背景格与物品轮廓/图片，视图池复用；不足时 ScrollRect + Scrollbar 查看。原附近物品的真实 InstanceId、WorldOwner 保留，拖动时使用显示格的 grab offset，Drop 后仍通过 Pickup 命令确认距离与真实归属。不得把临时附近坐标当作目标背包坐标。

附近视图在打开背包、库存变化及候选集合变化时刷新；打开后游戏暂停也要在首次显示时有完整候选，不能因为提示隐藏就把附近列表清空。附近 HUD 的可见性和附近数据的有效性分开处理。布局期间保存选中身份；原物品消失时安全取消拖拽，不按数组索引拾取另一件。
