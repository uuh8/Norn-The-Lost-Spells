# 元素世界 Phase E：世界活动扩展实施计划

> 执行方式：使用 executing-plans，在当前工作区逐项实施。用户已明确授权“写计划然后执行”；Task 不单独请求确认，Phase Gate 统一报告。禁止 SubAgent。状态：已完成。

**Goal：**让单位、投射物和反应共同驱动有限的世界活动区域；相机可见性与 Gameplay 活动分离，并保持 Archive/Restore、物质量和写入队列的一致性。

**Architecture：**Core 提供活动源生命周期事件，Combat 发布，ElementField 持有固定容量活动源与区域集合。每个 CPU Chunk / GPU particle 每 Tick 只分类一次，区域使用 OR 并集。Gameplay、Streaming 和可见性各自有明确边界；异步事务冻结开始时的区域，不能用完成帧区域解释旧数据。

**Tech Stack：**Unity 6000.3.16f1、C#、EventBus、URP、Compute Shader、AsyncGPUReadback、NUnit。总路线来源：2026-09-05 元素世界性能与规模优化路线及Phase A实施计划.md 第 3、10.3 节。

## 1. 基准、设计取舍与范围

Phase D 已验证 8192 GPU Slot 完整提交 18432 粒子，Dropped=0、Pending=0；576 EditMode 通过。该证据只覆盖有限压力。D01 Main Thread P99=23.737 ms，Interval P99=37.760 ms，严格 60 FPS 尚未通过。最终仍采用当前 Ryzen 9 7940H / RTX 4070 Laptop、1920×1080 Development Player，分别报告 Frame Interval 与 Main Thread，不能把限帧等待当成 Solver 耗时。

采用固定容量小型 Bounds 并集：Region 的数目是预算，空间跨度不是预算。OR membership 保证重叠不重复推进。拒绝“为每个单位运行一次世界 Tick”，它会让重叠区时间加速；也拒绝仅扩大总 AABB，它会激活中间空白世界。总 AABB 仅可用于粗略 culling / 快照包络，精确资格必须再次检查区域并集。区域容量溢出必须计数，保留玩家范围，不能动态扩容或静默覆盖已有来源。

Game.Core 不引用上层；Combat 仅发布启用/禁用事件，不读取 ElementField。单位移动通过已注册 Transform 读取，避免每帧发送事件或 Find。世界初始化补扫现存来源一次，解决 Awake/OnEnable 顺序；之后依赖生命周期事件。禁用、死亡、销毁、场景切换均清理引用。

稳定残留仍由 Phase D 表示保留。活动不意味着每 Tick 强制 Wake；仅新进入区域、写入、碰撞或实际反应需要唤醒。Fire 等未结束的反应保留局部活动需求，结束即撤销。相机位置不续租反应。

不新增用户资源依赖：使用现有液体材质、Dormant Shader、测试地面和角色。CPU Chunk 与 Dormant Cell 的可见范围依据 Camera，GPU Surface 保留既有有限栅格预算，不能随远处单位拉伸网格而降低采样精度。任何未覆盖的远处精细液面表现必须明确记为 Gate 缺口。

```csharp

Assert.That(regions.Contains(Vector3.right * 50), Is.False);
Assert.That(regions.Contains(Vector3.zero), Is.True);
```

## 5. Task E4：Streaming、恢复公平性与可见残留

修改 `FluidChunkStreamingRuntime.cs`、`FluidChunkArchiveStore.cs`，补充多区域只读筛选。Archive Begin 冻结 Warm Region 并集；GPU Lock 和 CPU Commit 分类必须使用同一 frozen set。旧单 Region 接口用于既有 fixtures，生产扩展走独立可选接口。Restore 优先明确 Write/Exposure/Reaction 请求，其余 Cold Chunk 按活动域距离和确定顺序选取；Wake 采用有界去重队列，避免单字段覆盖掉前一来源请求。

Cold/Dormant 的 Camera 表现不应该反过来触发 GPU Restore。修改 `DormantLiquidCellRenderer.cs` 与只读 Contract，使可见静态存量按 Camera 范围构建；Camera 改变需要刷新可见缓存，不只检查 Store.Version。实例 worldBounds 必须覆盖实际矩阵，不能沿用玩家 AABB 导致远处被整体裁掉。

```text
Begin archive -> freeze regions -> lock GPU candidates
-> Readback -> validate/filter -> RAM commit -> release slots
Wake FIFO -> budgeted expand -> reserve/stage -> activate
-> Gameplay topology published -> relinquish RAM authority
```
