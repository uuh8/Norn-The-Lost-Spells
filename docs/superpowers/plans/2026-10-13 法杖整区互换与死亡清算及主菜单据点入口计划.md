# 法杖整区互换与死亡清算及主菜单据点入口 Implementation Plan

> 执行方式：superpowers:executing-plans，由当前 Agent 顺序执行，不使用 SubAgent。用户已授权“计划创建好后直接执行不用让我确认”，三项完成后统一验收。

**Goal:** 法杖整行可替换、装备位可互换；P7/P8 死亡清空全部随身资产并返回据点，Boss 胜利生成可到达的回程门；主菜单 Play 进入据点。

**Architecture:** 保持 Game.UI 只发布库存意图，LoadoutOps 复用现有原子互换。Game.Run 的 HubPracticeSession 管理本轮玩家死亡与 Boss 结算，通过 DeathEvent/RunStateChangedEvent 接入；先可靠保存清算候选，再禁止旧 Scene 退出快照覆盖，再加载据点。UI 根据所在 Scene 的现代练习上下文跳过旧 Terminal Panel，不把库存清算塞进 UI。

**Tech Stack:** Unity 6.3、UGUI/EventSystem、Input System、EventBus、ProfileSaveRepository、SceneManager、Coroutine/unscaled fade。

**Spec:** 本轮用户三项要求及死亡范围补充：遗失全部随身物品，包括已装备法杖、道具栏和背包本体；金币、仓库保留。P7 最终房间 F 回程不变。

## 全局约束与资产

- 不自动保存/丢弃正式 Scene，不合并游戏地图、不改用户精修布局；不开 SubAgent、不做 Commit。
- 不添加新玩法：没有免费补发初始装备、死亡确认框、战利品列表或重试入口。
- 复用现有蓝色标准 Portal Prefab、F 提示、渐黑/渐亮和法杖 Sprite；无新模型/Texture/音效依赖。入口动画仍向门中心缩小；死亡不向虚构的门缩小。
- 清算只遍历离散结算候选，不在 Update/FixedUpdate 创建集合、委托或 LINQ。Profiler 针对稳定库存/UI 路径核验，Scene 加载/单次结算的分配不冒充稳定帧零分配。

## Review Focus

1. 法杖拖到已填法术卡/空程序槽时，UGUI 最近 IDropHandler 不能吞掉装备意图；法术拖放仍精确进程序槽。
2. 装备位互换保留实例 ID、各自程序和 Mana，不通过复制法杖实现。
3. 仓库法杖内部法术属于仓库；死亡按父链归属移除全部随身，不能只删根物品留下孤儿。
4. 写盘失败保留原 Store，自动重试死亡清算；旧 Scene OnDestroy 不得把已经丢失的资产重新存回。
5. Boss 只生成一个可 F 交互的门；胜利不强制传送。主菜单旧序列化 P7 值不能覆盖新的据点入口。

## 回滚与 Debug

- 只回滚本轮具体文件修改，不覆盖用户其它修改，不 reset/clean。Adapter 可移除而不影响库存 Domain。
- 结算出错先查实际 Health.Id、父链是否指向 Actor、候选与原档区别、SaveGeneration、退出保存抑制，禁止用先删后存绕过可靠保存。
- Drop 出错先看 EventSystem 命中的最深 Graphic 与 IDropHandler，再看源 Kind 与指向装备 Slot，不能取消程序区域 Raycast 来换取法杖替换。
- 菜单排查实际 serialized 新字段而不是只看 C# 默认值；Scene 文件不代保存，旧字段随作者后续保存自然淘汰。
