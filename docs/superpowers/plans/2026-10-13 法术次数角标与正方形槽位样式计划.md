# 法术次数角标与正方形槽位样式计划（M6-T15）

> 用户已经明确授权写完计划直接执行。本轮由主 Agent 按 executing-plans 自行实施，无 SubAgent、Commit 或正式 Scene 自动保存/丢弃。

## 1. 玩家效果与根因

法术卡只展示 Icon：有限法术左上角显示较大的纯数字，无限法术没有角标。程序、独立储存、背包、附近与仓库使用同一数据规则；名称、保护和入局资格说明保留在已有详情/法杖描述里，不叠在 Icon 上。仓库组仍按原规则汇总，角标展示所选实际实例的次数，不把同类实例数量混作施法次数。

SpellStorageView 原本宽度根据 viewport.width/capacity 计算，而高度单独从 viewport.height 取得，导致长方形；道具槽复制的根 anchors 横向分割父区，宽度随父区变化，高度另算，同样破坏方形。改为在作者区域内计算统一边长。法术储存真实容量仍为12，窄区少显示几个完整方格，其余横向滚动；不能为美观删除库存或减少实际容量。4–0 七个真实道具位全部保留，方形等比例缩小至可用宽高，使用独立有边框样式，与上方无缝网格区分。

## 2. 架构、资产与取舍

全部运行时修改留在 Game.UI，仅读取现有 Game.Run 快照与 SpellUseState，不改变交易、施法、保护、库存位置与存档规则。有限数字从当前只读状态取得，资格次数沿用原语义；无限返回空字符串。字符串在离散 Refresh/Rebuild 计算，仓库滚动只交换缓存字符串，避免热路径分配。

各 Item Prefab 增加独立 SpellCount Text 引用，普通 Caption 继续承担容器容量/物品数量。分开两个 Text 能让作者独立设计左上角角标，避免运行时根据物品类型重写作者 Caption anchors。旧兼容模板首次绑定时创建一次角标，现有作者模板由 Editor 迁移预先配置；连续绑定只写文本与显隐，保留作者字体、字号、颜色、局部坐标。

必需素材已存在：Assets/_Project/Art/UI/Function_UI/icon_frame_square_elite.png，PNG RGBA，沿用原分辨率与 Sprite (2D and UI) 导入，不重写纹理。用途是仓库选择法杖的选中 Frame 与内嵌道具槽的装饰边框。通过 LoadAllAssetsAtPath 读取 Sprite 子资产，支持 Multiple；资产缺失就明确停止迁移，不换成黄底或臆造素材。其他 Icon/字体使用现有资产，无新增模型、纹理、VFX、音频需求。

运行时只管理动态槽根位置/尺寸，Attributes、Frame、WandIcon 的作者局部排布保持不动。法杖选择卡外形继续三张横排卡，选中 Frame 换指定素材；不把整张信息卡强行变成方形。法术卡与下方快速法术槽为方形。

## 5. 调试与回滚

实施裁定：当前已保存作者商店没有4–0道具行（整个Hub只含背包和仓库两套ToolbeltView），不为测试恢复作者删掉的GameObject。对现有两套道具行验证方形，对商店验证实际内嵌背包/仓库的纯数字法术卡；若作者以后放入ToolbeltView，会自动走相同方形模板。这不是新增商店道具功能。旧UI堆叠测试原来要求“×2”“3次”，与此次法术仅纯数字要求冲突，改验“3”，保留后续Shift具体实例/整组移动和库存Version断言。
