# 液体计算粒度与可见体积统一实施计划

> 执行方式：使用 rpg-combat-and-spell-workflow、systematic-debugging、writing-plans 与 executing-plans，直接在现有工作区执行。用户已在讨论后明确要求“下面你开始实现”，无需再次确认；本任务未授权 SubAgent。保留既有未提交修改，不创建独立 spec、不创建 worktree、不提交 Git。

## 1. 目的与设计依据

玩家希望同一团液体看起来饱满、圆润，小水槽不需要令人困惑的大量法术才能填满。此前 .32m 基础显示厚度加 .65 圆冠可以画到约 .53m，但数量仍按 .25m 格 / 255 GMU 记账；显示高度不能被当作真实水位。此次把计算分辨率和单位液量所代表的体积拆开，并让动态流动、稳定湖泊、注水、消耗、接触查询使用同一映射。

参考 Unity_Slime：README 指明 Position Based Fluid，Jobs_Reconstruction 先处理粒子邻域再重建表面。借鉴“低成本状态与连续表面分别表达”的原则，不复制其完整 PBF 模拟或美术资产。本次沿用项目现有 Kernel、圆冠和 Fragment，保留大湖稳定区域与局部 Flux。没有需要用户提供的新模型、纹理、Normal Map、VFX、音频或字体；原有三液体材质与 Shader 为可用资源。

## 2. 统一数量模型与取舍

- 世界基础格仍为 .25m，液体专用 Resolution Scale=2，因此液体格为 .5m。火焰/其它 ElementCell 材料及其坐标不改变。
- Unit Volume Multiplier=4：单位 GMU 代表基础体积的四倍。基准格容量=255，则一个 .5m 液体格容量=255×2³/4=510 GMU。格子数量约减少至同体积细格的 1/8，填同一对齐容器所需 GMU 为原来的 1/4；这不是实测 FPS 倍数。
- Resolution Scale 与 Unit Volume Multiplier 是独立参数。只改计算分辨率且倍率=1，应保持同一容器总容量；禁止为了少算直接丢弃数量。
- 扩展现有 ushort 数量存储的允许容量；状态 byte 是只读投影，不能截断权威 GMU。所有 Pending、Stable、动态转移仍使用原 GMU 账本。
- 粗格对薄墙采用保守 Collider 占用，避免穿墙；代价是窄通道或不对齐池壁的有效空间可能缩小。Scene 制作建议 .5m 对齐、尺寸至少两个液体格。
- 表面可以保留艺术夸张，但最小显示厚度必须随实际填充量下降，避免 1 GMU 也画出 .53m。动态与稳定渲染复用同一受限厚度公式。
- 角色查询从世界细格映射到液体粗格，按细格与实际水深重叠投影状态。反应明确区分火的细格与液体的粗格，禁止把两套坐标直接相加。

## 4. 验证与 Editor 操作

开发前运行一项容量/粗格行为用例，确认原实现失败；完成整批修改后集中跑液体数量、稳定区域、反应、表面与路由相关 EditMode。不要关闭当前 Unity 或在同一项目起第二个 Editor。不得将 EditMode GC 断言称为 Unity Profiler 已验证，也不得把格数比例称为 FPS 提升。

用户验证：先停 Play，等待编译；打开正式 P7。用 Collider 构造内尺寸 2×2×.5m、底面 Y=0、壁面按 .5m 对齐的水槽。在无消耗/漏水时，容量应为 16×510=8160 GMU，旧 .25m/255 模型为 32640 GMU。观察注水时数量与水位逐渐增长、溢出后周边实际有液体，角色进入液体获得状态，火/毒/粘液反应仍工作。大湖用稳定区域创建；查看 Active Cells、Stable Quantity、Pending Quantity 和新增 m³，不通过增加大量粒子来填湖。

性能观察：Profiler 中分别记录 GridLiquid.FluxSolver、PendingDeposits、StableRegions、Surface.MeshRebuild 与 GPU 时间。记录活动与静止两个阶段，GC Alloc 要单独确认。低角度检查圆肩、少量液体是否夸大、稳定交接是否变形。此次允许粗粒度艺术风格，不承诺完整 PBF 运动或参考图逐像素一致。

## 5. 调试与回退

症状“火反应错位/角色无状态”：查坐标边界是否误用细格索引读取粗格。症状“水槽容量仍太大”：查正式 Scene 引用的 LiquidWorldProfile 而非旧原型，核对运行时 0.5m / 510 GMU。症状“窄槽不能进水”：查 Collider 是否占满粗格以及 Pending 数量，优先对齐/放宽槽而不是取消墙碰撞。症状“显示过厚”：查数量相关厚度公式，不能再单独提高最小厚度。

回退数据配置：Resolution Scale=1、Unit Volume Multiplier=1 可恢复旧 .25m / 255 GMU。必须重新进入 Play，禁止运行中改尺寸/容量造成账本映射变化。代码回退只针对本计划列出的修改，禁止重置其它开发工作。
