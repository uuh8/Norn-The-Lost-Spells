# 物品落地、中键平移与场景试玩规则修正计划

> 状态：2026-10-11完整计划代码、分批自动化与四份文档已完成；最后集中补跑因Editor崩溃及Recovering Scene Backups对话框中断，待用户自行处理恢复选择。开发者人工试玩待N01–N07。由当前助手在原工作区实施，不使用SubAgent、worktree或自动commit，不另建spec。
> 执行技能：superpowers:executing-plans；项目工作流：rpg-combat-and-spell-workflow。

**Goal：** 丢弃物品可靠落地；背包/附近区支持按住中键平移；Prefab、场景初始摆放、运行时物品与存档具有明确且可验证的职责，用户配置的尺寸不再被覆盖。

**Architecture：** Game.Run继续拥有唯一物品身份与资产位置。场景投放只负责初始配置与SpawnId；运行时拾取物是资产的可见表示；Game.UI只移动ScrollRect，不改变库存。Editor默认使用独立、每次Play重新建立的临时Profile；Build继续读正式Profile。模型生成同时识别可拾取Prefab与其美术来源，保存兼容的显示变换信息；UI/Rendering仍通过现有契约工作。

**Tech Stack：** Unity6000.3.16f1、URP17.3、Unity Input System、UGUI ScrollRect、ScriptableObject、Physics.RaycastNonAlloc、现有ProfileSaveRepository及TestRunner。

## 1. 实测源码证据与目标规则

### 1.1 当前缺陷

- WorldItemVisualFactory.Create把所有模型最大边长归一化为0.45米，关闭所有源Rigidbody重力/碰撞；没有可靠落地步骤。
- SinglePlayerInventorySession.CreateProxy将新丢弃物放到玩家前方1.2米、向上0.3米。RememberGround立即记下这个悬空位置，重进游戏仍恢复它。
- 用户已修改`Assets/_Project/Prefabs/Items/Pumpkin.prefab`：根Scale=(2.5,2.5,2.5)。定义的WorldModel仍指向`Assets/_Project/Art/Prefabs/Item/Food/Pumpkin.prefab`，运行时绕过了包装Prefab根Transform。因此只移除0.45米归一化仍不能覆盖此反馈。
- WorldItemSpawnPoint.Start先隐藏全部子物体，再检验重复ID/注册结果。配置错误或写盘失败也可能隐藏作者模型；直接给带MeshRenderer的美术根物体添加组件时，根Renderer又可能没被隐藏，造成重复模型。
- SpawnPoint注册只传Position/Rotation，丢失了父节点/实例Scale和部分视觉配置。注册已存在SpawnId直接返回，因此旧生成账阻止重新发放是正确的，但当前界面没有解释这一点。
- Runtime代理被创建为Session子物体，原Test是投放模板；拾取会销毁代理而保留RuntimeItemState。Drop新建代理，不重新放回Test。EditorScene未改写，而退出Play的OnApplicationQuit保存Profile，下一次Play读的自然是Profile中的位置。此项核心持久化行为需要明确展示，不能靠清档或重新生成身份掩盖。
- ScrollRect常规拖拽只接左键；物品又拥有自己的IDragHandler，中键不能简单挂父节点事件来接管所有拖拽。
- 进一步审计：TrySpawnRaidSpell在资产进入Store前调用CreateProxy，而CreateProxy从Store查询ContentId；此时会错误进入无定义Fallback。需要显式传入已解析Definition预建模型，保留原子提交顺序，不能靠提前写资产规避。

### 1.2 已确认与推荐约定

1. **Editor默认场景试玩**：每次进入Play，从StartingInventory和当前Scene投放建立独立临时状态；不读取、删除或写正式存档。当前Play内往返场景继续使用这份临时状态，退出Play才结束。Domain Reload开/关均不能延续上一轮临时资产。
2. **真实存档模式**：Editor可明确切换进行持久化测试；Build始终走此模式。既有正式Profile继续保留，包括金币、容器组分、法术次数、装备、地面记录和事务日志。不会为了重新摆物而换SpawnId。
3. **外观与状态**：Prefab/场景配置负责模型、尺寸、材质和初始摆放；Profile负责当前归属与实际地面姿态。大南瓜仍占原定义的3×3格，3D尺寸和二维占格独立，不隐式修改背包规则。
4. **层级可理解**：Test继续代表场景投放配置；真实可拾取模型集中在明确命名的WorldItems_Runtime。源SpawnPoint在Inspector显示对应InstanceId、当前归属和定位运行时物体入口。拾取后不存在“藏在玩家下面的3D南瓜”，实际物品在数据中；丢弃重建同一InstanceId的模型。
5. **普通丢弃可靠落地**：先找合法支撑表面，并用模型真实底边对齐。普通Drop采用可复现的放地策略；不为所有草药/食物长期启用Rigidbody，避免滚走、穿地和保存仍在运动的位置。G容器投掷沿用原物理路径。如果找不到合法地面，保持背包原资产并反馈失败；不能先消耗资产再发现落点无效。
6. **存档位置与Editor位置**：持久化模式优先当前存档姿态，编辑初始点不会凭空生成另一份物品或移动玩家已丢下的物品；场景试玩模式优先当前作者布局。Prefab外观更新应作用于重新生成的同类物品，不受旧世界坐标阻止；明确Scene Prefab Override会按Unity原规则覆盖Prefab默认值。

## 2. 方案比较、依赖与文件职责

### 2.1 设计取舍

落地可选持续Rigidbody模拟、一次Ground Query、短时模拟到静止。持续模拟成本和物理碰撞规则最多，短时模拟还需“运动中退出/暂停/Save”的处理；本轮推荐一次可靠Ground Query，先消除浮空并确定稳定资产姿态。需要滚动/抛物运动的物品以后通过明确使用能力扩展，容器G路径保持。

Editor可选清除正式存档、另建磁盘测试档、内存临时档。删除正式档具有资产风险且无法表达真正的持久化测试；磁盘档容易让下次试玩又继承状态。推荐每次Play独立的内存文件边界，复用真实Profile规则和事务实现，正式文件原样保留。

生成模型可继续只引用Art Prefab、让可拾取Prefab成为生成来源、或完全复用原Scene对象。只引用Art会继续丢包装Transform；完全复用Scene对象会将SpawnPoint生命周期、资产交易重建和世界表现混在一起。推荐显式可拾取Prefab引用与场景来源绑定，统一提取实际视觉配置；运行时复制体禁用投放组件，防止递归发放；来源配置和当前实体的角色在Inspector直接展示。

中键可依赖ScrollRect原拖拽或独立捕获Input System。前者不能覆盖物品抢占IDragHandler的情况；推荐已有组件旁的平移适配器，按下时捕获一个Viewport，直到释放/取消，不在每帧遍历Scene。自动边缘滚动、左键拖物及中键平移互斥，两个Viewport各自正确限位。

### 2.2 资产依赖

无新增用户素材。使用已有Food/Herb/Container Art Prefab、业务包装Prefab、ItemDefinition、18件图标和PickupItemEntry.png。保持源模型、Material、LODGroup、Alpha Clip、Vertex wind、图标GUID；新行为不需要贴图/Shader/VFX。新增配置引用只指向既有Prefab，不能自动覆盖用户的Scale、旋转、材质或变体。

可拾取Prefab在`Assets/_Project/Prefabs/Items/`；Art模型在`Assets/_Project/Art/Prefabs/Item/`；定义在`Assets/_Project/ScriptableObjects/SinglePlayer/Items/`。保持WorldModel供美术/图标消费者兼容，新增显式PickupPrefab来源。普通物品无美术引用时保持明确的小立方体Fallback，不能因此把有模型的物品也统一缩小。

## 4. Editor操作与回滚

现有Scene/Prefab/布局由用户保留。自动测试若当前Scene未保存，只请求用户自行保存，不替代保存/丢弃。正在Play时先停止再进行刷新/测试，不在运行中改存档结构。各测试使用Review和内存/独立测试档。

Editor可在Session的明确选项中切换Scene Preview与Saved Profile。Scene Preview不需要“删掉旧存档”才能生效。真实Mode用于专门测试保存，进入时明确可见当前Mode/路径，避免误以为普通布局试玩会修改正式资产。

物品落地检查Collider是否存在、Physics Scene是否正确、Ground Mask是否包含Terrain/地板层；Pivot/Bounds错位检查各父级Scale、包装/Art Prefab与局部Transform。Prefab不生效先检查实际Definition的PickupPrefab/WorldModel来源，再查Scene Override，不改SpawnId。

回滚先恢复生成/模式选项与PickupPrefab引用；保留现有正式存档、Schema8备份和原Prefab。Schema9不能假装由旧代码直接读取，持久化真实档测试应先备份并确认迁移；不要把恢复资产配置误写成回滚玩家历史资产。UI平移可单独禁用组件，Slider/滚轮仍可用。
