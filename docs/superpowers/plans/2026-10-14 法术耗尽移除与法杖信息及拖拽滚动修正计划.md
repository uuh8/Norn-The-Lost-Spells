# M6-T20 法术耗尽移除、法杖信息与拖拽滚动

用户已授权写完计划直接执行，不再请求计划确认。当前据点为单一、非 Play、干净 Scene；全项完成后统一验证。不使用 SubAgent、不保存或丢弃正式 Scene。

## 1. 玩家效果与设计理由

有限 Emit 成功消耗最后一次后从权威库存移除，释放所在格子。Prepare 只修改候选库存，失败或 Cancel 不删除；已经发射的 Trigger 依靠预付快照完成后续层，不再依赖消失的卡片。无限法术不显示次数。Modify/Multicast 的次数目前表示未来入局次数；本局已获得资格时即使未来次数为零仍可用，不能误删正在生效的指令，仅隐藏零标注，保留原规则。剩余次数改为大号白字、底部中央，避免左上角 Trigger/Delay 标识。

法杖信息统一称“法术槽”。第一行保留基础抽取，第二行按 Mana（蓝）、恢复（浅蓝）、冷却（黄）排列，不重复基础抽取，不展示保护数量。标题及属性字号适度放大，不重设作者 Attributes/Frame/WandIcon 的 RectTransform。预估保持真实根层解释器语义，同时展示槽内全部指令的 ManaCost 合计；基础抽取为 1 时新增未执行 Emit 不改变根层成本，但合计能体现编辑变化，不能把总和伪装成本次扣费。

移除背包、附近物品及仓库目录的拖拽边缘自动滚动调用，保持手动滚轮、Scrollbar 与空白处拖动。保留静止指针的绿色/红色落格预览刷新，防止清色后预览消失。

## 2. 文件及架构

- Run/Inventory/ItemOwnershipStore.cs：在资源准备候选中移除耗尽实例，同一 Commit 原子生效。
- UI/Inventory/InventoryItemView.cs、SinglePlayerInventoryController.cs：零角标隐藏、兼容旧模板底部数量、取消拖拽自动滚动。
- UI/Inventory/WandInventoryView.cs、WandProgramPanelView.cs：有色且更大文字、双口径预估，使用现有只读投影。
- UI/Inventory/NearbyItemGridView.cs、WarehouseCatalogGridView.cs：取消旧自动滚动入口。InventoryViewportPan 保留；不随意删除仍由旧资产引用的组件脚本。
- Editor/SinglePlayerInventorySlotPrefabSetup.cs：增加针对 SpellCount 的样式迁移，不重建作者其他节点；独立 Prefab 更新，Review 从已保存据点生成。
- Tests/Run/CastResourceServiceTests.cs 与 RunPlayMode 的视觉/交互检查：最后一次提交、失败回滚、Trigger 后续层、次数位置、动态预估与拖出后滚动位置。
- living explainer 与验收记录追加本 Task：原因、取舍、运行链路、检查与边界。

不新增模块依赖，不改变保存 Schema、随机奖励、装备/死亡规则。全部使用既有图标、Font 与独立 InventorySlotPrefabs，不需要新美术资源。

## 3. 验证与交付

先增加最后一次施法及旧上角位置的回归检查，运行 Unity Test Runner；修正后运行对应 EditMode/PlayMode，扩展相关资源事务与既有背包/仓库回归。PlayMode 在隔离 Review 验证真实 UI，抓图检查新字号与角标。稳定交互观察 Profiler，区分检查范围内零 GC Alloc 与整帧开销。正式 Scene 不代保存，若确需 Undo 修改，全部完成后统一交给用户保存。

## 4. Debug 与回退

若 Trigger 失效，检查资源 Ticket 内的快照，不恢复零卡片来掩盖问题；若预估不更新，检查库存 EventBus、Wand 投影版本与 Refresh 顺序，并用真实拖拽重现。仅修改 SpellCount 节点避免覆盖作者 UI。回退按上述脚本/Prefab 分组恢复，禁止清空用户库存或重建正式场景。
