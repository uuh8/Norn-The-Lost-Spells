# 仓库横向属性、快捷法术栏留白与据点卡顿排查 Implementation Plan

> 使用 writing-plans 记录本轮边界，使用 executing-plans 在当前工作区执行。用户已明确要求计划完成后直接执行；不再请求计划确认，不使用 SubAgent，不保存或丢弃正式 Scene。

**Goal:** 保留作者删除仓库独立道具栏后的布局，横向利用法杖属性区域，修正两个快捷法术栏内边距与上下不对称，并以实际 Profiler 数据定位据点周期卡顿。

**Architecture:** 外框、法杖 Attributes/Frame/WandIcon 的作者坐标保持归作者所有；Game.UI 只布局动态快捷槽与更新属性内容。槽位仍使用独立 Prefab，12 个真实法术位不减，窄区域横向 ScrollRect。Editor 诊断与 gameplay 分离，不修改库存或正式场景资产。

**Tech Stack:** Unity 6.3、UGUI RectTransform/ScrollRect/RectMask2D、Unity Profiler RawFrameDataView、Unity Test Runner。

## 1. 当前证据与设计取舍

- 用户仅确认据点卡顿；P7/P8 尚未检查，不能声称三图均有性能问题。
- 仓库 `_tools` 已为空，不能为了旧测试重建作者删除的行。
- `WandInventoryView` 仓库属性字符串主动插入 `\n`，使右侧宽度空置。改成同一段横排文字，交给 Text 在必要时自然换行；不通过缩小整个区域或重排作者法杖子对象处理。
- `SpellStorageView` 以 Viewport 高度决定边长，再按完整列缩小，但 Content 仍贴顶部，造成剩余高度只堆在底部。现有 Viewport 离装饰框太近，导致内容遮框。
- 采用作者可配置的内部留白，计算可用宽高后确定正方形边长，纵向居中。已有作者 Viewport 不重排；运行时内层 ClipViewport 承载 Content，并作为 ScrollRect.viewport，使首尾槽均可滚到、内容不会进装饰边框。不缩减实际容量、不恢复仓库道具栏。
- 当前最初采样为背包打开、TimeScale=0 的状态，600 帧 Main Thread 最大 22.35 ms；不能用它证明正常游玩无卡顿。需正常据点持续运行窗口，并区分 PlayerLoop、EditorLoop、Render Thread 等待与 GC。
- 用户补充主要在移动/转镜头时卡。追加通过 Input System 诊断设备驱动真实 Move/Look 的 20 秒窗口，不能用静止据点的数据替代。临时设备只在诊断开始创建，结束撤回，保留 native 键鼠；诊断自身输出不进入测量窗口。

## 4. Editor、调试和回滚

- `SpellStorageView` 内留白是逻辑 UI 单位，CanvasScaler 会整体缩放；外框厚度不同可在 Inspector 调整。默认预留 8 个单位，上下居中；动态 Content 坐标由槽布局负责，不能拿 Attributes 的作者坐标作布局输入。
- 如果末槽不可达，检查 ScrollRect.viewport 指向内部裁剪视口、content 正确及水平滚动启用；不通过缩小容量掩盖问题。
- 如果只在 Editor 出现等待尖峰，报告该限定，并保留 native capture；不能把 Gfx 等待时间算成 C# 工作，也不能通过 TimeScale=0 冒充正常性能回归。
- 回滚限本轮脚本改动与独立 Review/测试产物。用户正式 Scene 与精修素材不回滚、不覆盖。
