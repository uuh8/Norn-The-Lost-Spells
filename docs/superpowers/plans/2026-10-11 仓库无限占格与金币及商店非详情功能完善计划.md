# 仓库分类方格、金币与商店非详情功能完善计划

> 2026-10-11 执行中修订：用户最新更正“仓库不用物品形状占格，单独一类物品一个方格，只有背包体现形状，从仓库拖动也显示形状”。此要求替代旧空间方案。用户已批准本计划两阶段实施，不重复申请架构审批。
> 当前主代理使用 executing-plans/TDD 逐项实施；不使用 SubAgent、不建立 worktree、不自动提交 Git，不自动保存或覆盖用户当前场景。没有单独 spec。

**Goal：** 两个窗口都显示实际无限仓库的分类网格与真实金币，补齐搜索、目录整理、背包存取；用户验证第一阶段后完成商品图标和购物清单。最右侧详情暂缓。
**Architecture：** Game.Run 的单一归属表、钱包、商店仍是权威；Game.UI 对仓库按 ContentId 分组显示，每份实例保持独立，通过 Core EventBus 提交存取/交易意图；没有仓库空间迁移。
**Tech Stack：** Unity 6000.3.16f1、URP 17.3.0、C#、UGUI、Input System、既有 JSON Profile、Test Runner、Profiler。

## 1. 玩家规则与现有缺口

同一种具体物品显示一格，例如南瓜一格、胡萝卜一格；不是把所有食物或者所有容器压成一个格。每格显示 Icon、名称、总数量，以及当前准备操作的一份的必要状态。不同法术次数、容器成分、保护/附着等状态仍是独立实例；重复点击已选中的仓库格切换具体一份，提示“第 N/M 份”，起拖拿当前显示的一份。仓库分组不受背包 MaxStack 限制，也不销毁实例来伪造数量。

仓库始终显示空格背景，至少铺满当前视口并留一行空格；种类增多后 Content 随之扩展，可滚动，没有固定 60 格容量。仓库刷新按稳定名称/配置键排序；“整理”是对显示目录排序并回到顶部，不能擅自改变物品归属、次数、成分或钱包。搜索/类别过滤只改变显示，清除过滤恢复全部资产。

仓库方格只是目录。起拖之后 Ghost 显示该物品完整形状并保留所选实例身份；放入背包仍按形状、四种旋转、空洞、堆叠兼容、容量与现有红框临时重叠/撤销规则判定。仓库内部没有形状碰撞和格子坐标，不制作此前用户已撤回的仓库空间规则。

| 区域 | 已确认缺口 | 完成结果 |
|---|---|---|
| 两个仓库 | 目录只有持有项，没有持续空格，也没有按具体物品合并的数量视图 | 同一真实库存的分类方格、总数、具体实例选择、可扩展网格 |
| 金币 | Wallet 后台已存在，商店混在文字中、仓库为占位 | 图标和真实数字独立显示，所有可见钱包同步 |
| 仓库搜索/分类/整理 | 仓库草稿是文字占位 | 搜索、分类、整理目录可用，绝不修改隐藏资产 |
| 商店背包 | 只读镜像，拖动目标控制器关闭 | 与仓库直接拖拽存取，保持抓取点、旋转、中键及边缘加速 |
| 当前背包 | 装备预览是占位 | 实际背包名称/Icon/真实占用显示，替换仍复用既有校验 |
| 商品 | 文字为主，图标信息不足 | 第二阶段显示图标、名称、价格、供货和加入清单 |
| 购买预览 | 占位，当前仅单项真实购买 | 第二阶段可加减、删行、清空、合计并一次结算 |

右列已有选择详情和购买设置可保留，不重排/精修效果预览、保护、附着和店主区域。左侧清单提供完成购买所需入口。

2026-10-11 用户补充：仓库 BackpackRuntime_Wands 改为上方三个选择卡，选中一根后下方仅显示其属性与程序；背包继续三根完整展开。复用 WandInventoryView 的单程序路径，增加独立 selectorLayout 配置、响应式卡片/选中边框、属性与保护数量。切换查看不改变角色手持，不增加 Fold，也不移动外围区域；长程序使用横向 ScrollRect。黄色12格法术专区保留。素材沿用实际 ItemDefinition.Icon/中文字体，缺图仍显示法杖名称，无新素材依赖。新增 WarehouseWandSelectionPlayModeTests 验证点击、各槽 OwnerId、编辑归属、空程序、背包回归；Editor 增量接线保留用户布局，单组 Undo、不自动保存。

## 2. 数据、性能与输入边界

仓库继续使用现有 ItemLocation.Warehouse，Schema 保持 9，原档读取和 Raid 回滚逻辑不改。撤回本次刚加入的形状占格候选代码和对应实验测试，恢复本轮修改前的空间行为；只撤回本轮差异，不运行 git reset/clean、不覆盖其他工作。

目录用 ContentId 分组，数量为实际实例数，代表项优先使用当前选择的 InstanceId。移动只提交该实例；背包堆叠的 WholeStack 语义不套用到整个仓库种类。法杖中的子法术、包里的子物品不单独计入仓库顶层数量，根对象移动后父链照常跟随。

视口采用池化空格和池化目录 view，Content 反映逻辑行数；预计算每组的文字/代表快照，滚动时只重用可见窗口，不在每帧 new/LINQ/装箱、格式化字符串或 Instantiate。池扩容只发生在初始化、尺寸变化或离散库存变化。测试空仓库、数百种物品和滚动，不能只用几种小图证明可用。

商店启用复制库存控制器的显式 embedded 模式：受 ShopController 控制开放/关闭，复用 Grid、Ghost、拖拽草稿；不订阅 Tab/Esc，不独占 Pause，不自行消费 Hub 开仓库事件。实际背包仍拥有 Tab，ShopController 拥有商店 Esc/暂停。商店旧只读背包镜像不再与交互网格重复渲染。Ghost raycastTarget/blocksRaycasts=false，结束拖拽隐藏。

Run 的仓库访问仍须确认 HubReady、实际 Shop/Warehouse 区域、版本及资源锁；普通 Tab、远征、远程命令不能访问。适配已有测试的无 Hub 配置纯会话 fixture，不用测试便利放宽生产场景的已配置区域权限。保存沿用当前明确 Save/结果反馈链，用户精修场景不自动保存。

## 3. 金币与资源依赖

WalletView 读取 SinglePlayerInventorySession.WalletReadOnly.Currency，只在金额变动时格式化字符串；仓库 GoldRegion、商店商品标题和背包区域钱包绑定同一实际值。0 金币显示 0，样板数字不作为初始资产。已有购买和出售后同步。

本轮无需新增用户素材：

| 资源 | 来源、格式与用途 | Import / fallback |
|---|---|---|
| 物品 Icon | ItemDefinition.Icon 与现有 Spell Icon；已有食物、草药、容器图标 | Sprite (2D and UI)、保留 Alpha、128–512 像素足够；缺图使用类别图标/清楚文字并记录 ContentId |
| 金币 | 优先用户背包 GoldRegion 已用 Sprite；备用 Assets/_Project/Art/UI/Funtion_UI2/附近物品：金币与宝石徽章.png | Sprite、Image preserveAspect；无图仍显示金币文字和实际余额 |
| 背包装备 | 当前装备 ItemDefinition.Icon 和实际名称 | 保持比例；缺图显示名称与真实容量 |
| 边框/背景/按钮 | 现有复制界面引用的 Sprite 与色块 | 保留当前布局、Sprite 边界、Image 类型；新增控件使用清楚色块标注 |
| 字体 | 已配置/验证的中文字体 | 复用初始化 fallback，不每帧创建 Font |

没有新 Shader、发光、模型、VFX、音频、Noise/Normal Map 需求。阶段一不修改钱包资产发放规则。

## 5. 阶段二：商品图标与原子购买清单

商品卡显示 Icon、名称、实际价格、库存和加入清单入口；左下行包含单价、数量、小计、目标，支持 +/-、删除、清空和购买。默认普通物品到仓库；选背包时按真实形状检查容量；材料按 GMU 和合法目标容器，不能把材料量当实体瓶子数量。OfferId/目的地/目标相同才合并行。

清单只存待购买意图，关闭重开保留，同一会话成功/手动清空后移除；切换库存身份清空。新报价更新预览，价格由 Run 配置计算。失败保留清单并指出具体行原因。

**原子事务：** 新增 Core 批量请求/结果 struct；Run 克隆一个候选、复用实际单项规则逐行校验应用，累计金额/供货，一次保存，成功才采用。不得循环调用已会各自保存的单项事务。缺钱、缺货、累计超库存、容器失败、背包装不下、版本过期、overflow 或存档失败时整单原资产不变；RequestId/Fingerprint 重试幂等。
