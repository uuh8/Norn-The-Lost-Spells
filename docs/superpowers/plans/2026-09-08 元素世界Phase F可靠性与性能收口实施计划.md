## 2. 统一验收合同

以下数值是本计划提出的验收标准，不是已经测出的结果。采用现有 Ryzen 9 7940H / RTX 4070 Laptop，1080p、固定 Render Scale/Quality、插电、记录功耗模式、驱动和 API。保留 8192 GPU slots，Water/Poison/Sticky 为 8 GMU/particle，禁止通过删除残留、改变反应速率或降低写入量达标。

| 维度 | 必须通过的标准 |
|---|---|
| 无反应物质量 | 同一审计时点按 MaterialId 核算，未解释 GMU 差额为 0；GPU Alive/Free/Reserved 槽位也独立闭合 |
| 有反应物质量 | 每材料期末量等于期初量+实际生效生成−实际生效消费+转换流入−转换流出；只按已执行结果记账，不能按计划命令扣量 |
| 写入可靠性 | 规定负载内入口请求全部接收、exactly-once 生效、Dropped=0；停止注入后 8 s 内完成 Drain；超时为失败 |
| 清洗及时性 | 落地到 Water 可查、首次 Wet 分别记录；规定负载内 Water/Wet 延迟 P95≤0.5 s、Max≤1 s；Burning/Poisoned/Sticky 各有干燥对照，效果符合现行 Reaction 数据 |
| 限帧体验 | 三次独立 Player 运行，Frame Interval P99≤18 ms、超过33.33 ms帧比例≤0.1%；精确报告16.67 ms超预算比例 |
| 实际工作预算 | 另跑 Uncapped 相同负载；用 Profiler 区分等待和执行，CPU/GPU 工作时间 P99≤16.67 ms；缺 GPU 数据则该项未验证，禁止用 Main Thread 总时间替代 |
| GC | 预热后本次世界管理、归档/恢复和查询热路径无周期性 managed allocation；报告整个 Player 的 P50/P95/P99/Max 与 allocation stack，不能只用 GC P99=0 判断全部零分配 |
| 长时间 | 30 min 综合测试，无 Crash、Readback Error、未解释差额、永久积压或来源槽泄漏；稳态对象循环不造成持续内存增长 |

18 ms 是限帧调度容差，不能写成“每帧严格16.67 ms”。报告同时给出两类标准。旧 D01/E04 历史数值只能作同场景参考，正式前后比较必须固定配置、输入、API、供电条件和测量方式。
