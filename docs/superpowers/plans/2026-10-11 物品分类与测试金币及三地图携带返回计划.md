# 物品分类、测试金币与三地图拾取带回 Implementation Plan

> 执行方式：主代理在当前工作区使用 executing-plans / TDD 逐项实施；不使用 SubAgent、不创建 worktree、不自动提交或保存正式场景。无独立 spec，本计划包含需求和设计。

**Goal：** 南瓜等普通资源归材料、可使用物品归道具；三个界面读取同一个实际钱包；正式远征、P7、P8 都能 F 拾取并经回程门带回同一背包，Editor 退出 Play 后临时资产重置。

**Architecture：** 保持现有 ItemKind 的数据结构语义和 Schema 9，使用统一展示分类规则；新档发放 SO 配置初始金币。正式远征共享据点 Session，并补场景物品的本局投放入口。P7/P8 继续现有 Single Scene 练习流程，由 HubPracticeSession 持有当前试玩的 Profile/Repository 引用，在每个目标 Scene 建立唯一临时库存工作区，回据点前可靠提交至同一内存 Repository。工作区 Prefab 包含原背包、拾取列表、NearbyPickupInput、Run Session 和必要的暂停协调器，模块引用仍遵守现有方向，Run 只持有 GameObject Prefab，不直接引用 UI/Character 类型。

**Tech Stack：** Unity 6000.3.16f1、UGUI、Input System、ScriptableObject、EventBus、现有 ProfileSaveRepository / EditorScenePreviewFileSystem、实际 Unity Test Runner。

## 1. 已确认需求、证据及取舍

用户明确：道具是能绑定4–0实际使用的物品，目前只有容器；南瓜属于材料；三种入口都支持拾取并带回。Editor 采用此前已确认 ScenePreview，整个 Play 共用临时资产，下一次 Play 重置；本次不新增永久存档功能、不删除真实存档。正式远征失败/死亡/放弃的既有损失规则保持，成功返回验证携带不丢失。

当前错误有直接源码证据：WarehouseCatalogGridView 分类9把 Consumable/Alchemy/Backpack 都计作道具，分类3只接受固体 Material，因此 Food/Herb 无正确目录入口；SinglePlayerStartingInventory 创建 Profile 未提供初始金币；WorldItemSpawnPoint.Start 仅查同Scene的Session，TryRegisterWorldItem又拒绝PendingRaid；HubPracticeSession按Single卸载据点，仅保存回程路径，没有练习地图普通库存和拾取入口。EditorScenePreviewFileSystem已有static内存文件及SubsystemRegistration重置，继续复用，避免引入另一套测试档。

方案比较：把所有资源改成ItemKind.Material会改变容器与固体元素数量语义、旧实例校验和交易规则，成本过大；统一展示规则可以保留Food/Herb细分类及现有ContentId。把整套据点Systems标记DontDestroyOnLoad会保留无效角色、实验区和商店引用；保留Profile/Repository并按Scene建立工作区可以明确释放世界代理、输入和UI。把P7/P8全部改成Additive会影响旧教学与Boss跳转，采用现有Single流程加库存衔接更可控。

主要边界：连续P7→P8→Hub、返回门多Collider重复触发、背包满后F开窗、同SpawnId跨图和同图重复、角色/代理/输入跟Scene释放、Domain Reload关闭、原存档读取失败、购买后钱包同步、已有Scene脏标记。不能用新建同名物品替代原InstanceId，也不能用清空正式资产解决问题。
