# 背包重叠草稿、附近自由摆放与拾取光晕实施计划

> 状态：已完成实现、Unity编译和相关自动验证，正式据点已单Undo增量接线且未保存。待用户M01–M07集中试玩；完整GPU/目标设备验收边界见结尾。默认边缘光比两张参考图稍暗；颜色、Sharp/Halo强度与宽度可在Inspector调整。
> 执行：确认后使用superpowers:executing-plans，由当前助手在原工作区实施，不使用SubAgent、worktree或自动commit。按项目约定只维护这一份中文计划，不另建spec。

**Goal：** 玩家可以先把物品转到需要的方向，再整理重叠；附近区保留玩家拖放的位置；可拾取物呈现参考图中的明亮青蓝描边与柔和光晕。

**Architecture：** Game.UI管理未提交的整理草稿和附近显示坐标；Game.Run继续拥有真实资产并拒绝非法占格；合法操作沿用Game.Core现有Place/Pickup/Drop事件。Game.Rendering沿用真实拾取代理事件和既有Alpha/LOD/Vertex wind适配，用URP RenderGraph Renderer Feature为轮廓生成独立光晕。

**Tech Stack：** Unity6000.3.16f1、URP17.3.0、C#、Input System、UGUI、RenderGraph、ShaderLab/HLSL、Unity Test Runner、Profiler、Frame Debugger。

**需求依据：** 用户2026-10-11三项反馈，以及同一请求中的苹果/草药参考图。此前“重叠立即拒绝”和“1.5像素淡金薄边”的方案被本次交互/视觉要求更新。

## 1. 当前证据与边界

- InventoryGridView只从真实Snapshot显示位置；Controller.ClickItem直接提交Place。空间不足时库存拒绝，UI因此无法保留旋转后的重叠姿态。
- NearbyItemGridView.Refresh每次调用NearbyItemGridLayout.Build，后者从左上角first-fit，并把所有WorldItem显示旋转设为0。原Ground Drop Target不接收释放坐标；丢弃成功后RevealItem只能滚到自动排布的位置。
- ItemPickupRim为Stencil排除内部的外壳，当前淡金色Strength0.22、宽1.5像素，Blend One One。它没有柔和光晕。DefaultVolumeProfile的Bloom intensity为0；仅断言“边缘有像素变化”不能证明达到参考图观感。
- 当前PC_Renderer为Forward+，已有SSAO；Mobile_Renderer为Forward。现有遮罩占Stencil bit7，源草药的Alpha、LOD和风摆动适配已验证，继续保留。
- 当前Unity为SinglePlayer_Hub、非Play、SceneDirty=false。执行时重新检查；不自动保存、覆盖或丢弃用户Scene。独立Review从最新已保存正式场景复制，不覆盖已存在的用户Review。
- 本轮范围为背包及附近区的交互和可拾取物视觉，右栏、商店经济、仓库功能、三个法杖程序内容和原有按键规则保持既有行为。

这里要区分三种“位置”：真实库存占格；背包正在整理的候选位置；地面物品在附近面板中的显示位置。后二者属于UI状态，不能把红框重叠写进真实库存，也不能把附近格子坐标当作世界空间坐标。

## 2. 玩家可见规则与方案取舍

### 2.1 背包：允许临时重叠，合法后提交

1. 第一次点击未选物品只选中；后续点击同物每次顺时针90°，R拖拽旋转保留。
2. 旋转或释放到背包后，若与其他物品重叠，物品保持候选姿态/位置，选中外框变红，不立即弹回。候选物位于其他物品之上，方便继续抓取；原实心Shape的空洞仍可点到下面物品。
3. 继续拖动或旋转同一选中物，把候选位置整理到合法格位。验证通过才提交原Place/Pickup事务；成功后恢复橙色框。不会移动或挤开其他物品。
4. 未整理合法就选中另一个物品，撤销这一件物品尚未提交的整理草稿，回到最后一次合法位置/朝向。连续多次非法旋转/移动视为同一段草稿，不只撤销最后90°；已成功提交的合法操作不撤销。
5. 越界也显示红框候选，不能保存越界资产；候选仍从实际可视格位抓取。选其他物、Esc、关闭、失焦、组件停用或请求保存前，取消未完成草稿。关闭再开不能出现红框资产泄漏。
6. 一次只维护一个选中物/整叠组的整理草稿。普通拖整叠、Shift拖指定一份，保持当前规则；原占格在草稿未提交时仍由真实资产占有，其他物品不得利用这段时间占用它。
7. 从附近拖入背包且空间不足，也可显示“待拾取”的红框候选；真实物品仍在地面，附近的重复UI投影暂时隐藏。整理合法才提交Pickup；取消则恢复附近原显示，不生成新ID、不提前消费物品。
8. 只有占格冲突/越界进入可继续整理的红框状态。错误物品类型、距离失效、Ownership或版本失败必须说明原因并恢复真实状态，不能用红框掩盖其他事务失败。
9. 外部库存变化时重新核对草稿来源和占格。来源被移动/移除或组成员变化，取消草稿；来源未变则用最新只读版本重验候选，最终事务仍校验ExpectedVersion。

推荐单个UI草稿：保存来源身份、最后合法快照、候选X/Y/QuarterTurns、整叠语义和版本。View只投影候选，Controller负责提交/取消。替代方案是让真实库存暂时重叠，但这会影响存档、商店、装备和其他读者；全背包事务式编辑则需要新的批量提交/回滚协议，本轮无须扩大到它。

### 2.2 附近区：自由放置的地面整理区

- 仍是可以F拾回的真实地面物品，“垃圾桶”表示自由丢放区，不表示永久删除物品。
- 从背包丢到附近的空格，以释放格减抓取偏移记录显示位置；保留当前显示朝向。物品物理位置仍由现有Drop生成在玩家附近。
- 已在附近的物品可以在该区拖动、点击旋转；只改变UI坐标/朝向，不重新执行Drop，不移动真实世界模型或增加ItemId。
- 刷新、拾取另一件物品、数量变化、滚动、关闭再打开，同一Scene/Session仍保留既有显示位置。离开Scene或更换Session清理这份显示缓存；不为它新增正式存档迁移。
- 只有初次出现、没有缓存位置的物品自动找空位。不会每次重排全部物品，更不会把手放位置吸回左上角。
- 附近区也支持红框临时重叠、继续调整及切换选中后撤销显示草稿。新丢弃成功的物品真实状态已是WorldItem：即使附近显示重叠被取消，也只回到新物品预留的合法显示格，不回背包或撤销已经完成的真实Drop。
- 丢到已有物品上不能被错误地解释为再次丢弃目标或非法合并；读释放坐标，由附近显示层处理候选布局。新物品的合法备用格只生成一次，重叠整理取消时使用。
- 保留足够空白整理空间。开始拖动时按当前布局及所拖Shape离散扩展Content，横纵Scrollbar和边缘滚动可到达空白区；成功放置后按所有保留坐标扩展尺寸。稳定滚动帧不实例化格子、分配集合或反复重新排布。
- 附近网格的显示碰撞不限制真实丢弃。超宽/高物品、背包已满时仍可扔到地面；附近UI不能变成另一个有容量的背包。

推荐InstanceId→显示格位/朝向的缓存，单独处理“初次出现”和“持续可见”。继续使用首次first-fit作为默认布局，但不再作为每次Refresh的布局。用同一个临时整理模型处理红框/撤销，减少两个区域行为不一致。

### 2.3 发光：亮边 + 柔和青蓝光晕

参考图包含清晰近白色的青蓝描边，轮廓之外还有渐弱的软光晕。默认先以2–3屏幕像素的亮边和约10–16像素的光晕范围制作可调样例；参数是起始值，最终以苹果/草药在据点中的实看结果验收。

推荐为当前外壳增加专用Glow Source Pass，用Renderer Feature把这些轮廓写入独立Render Texture，再做横向/纵向Gaussian blur，最后把柔和青蓝光晕叠加到场景。细线继续用已验证的遮罩/外壳绘制，保持原材质、Alpha Clip、LOD和Vertex wind。模型内部在合成阶段用覆盖遮罩排除，不能用全物体Emission覆盖原色。Glow所需遮罩作为显式纹理输入，不假定后处理后Stencil仍可读取；不得与同一输出Texture形成读写反馈。

- Glow Source只有真正的可拾取代理，使用自定义ShaderTagId；普通灯、天空、施法VFX和地图装饰不进入这张纹理。
- 独立光晕在场景后处理之后、Overlay UI之前合成，避免额外修改全场景Bloom或被Tone Mapping压暗。Sharp edge及光晕都提供Inspector参数；相关宽度以屏幕像素解释，不随模型Scale变化成粗壳。
- 来源使用场景深度裁定可见性，完全被墙遮住时没有发光来源。软光晕可在可见轮廓外正常衰减，不能显示被遮物的完整形状。透明草药不能出现发光矩形或静态幽灵线。
- GPU资源由RenderGraph管理，正确声明颜色/深度输入输出、MSAA匹配与resolve、相机尺寸和动态分辨率；不改变Main Camera的物理Culling Layer，也不把全部物品换到保留Layer。
- 相机/场景无真实拾取代理时跳过该效果。暂停、切场景、代理停用/销毁和不同相机都正确清理，不留下额外光壳或跨相机纹理。
- Game.Rendering仅增加URP/Core RP包Assembly引用，不新增上层游戏模块依赖；无Renderer Feature的平台明确报告配置缺失，不能拿旧淡金薄线当成完成效果。

替代方案是打开全场景Bloom并提高原线亮度，实施较快，但会连带改变灯光/法术等所有高亮物。多层大外壳模拟柔光会增加每个Mesh的绘制并产生粗轮廓阶梯；本轮选择独立轮廓缓冲和可控模糊，代价是额外纹理带宽与几个屏幕Pass，必须实测。
