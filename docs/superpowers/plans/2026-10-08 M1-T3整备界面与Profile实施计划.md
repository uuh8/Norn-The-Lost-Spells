# M1-T3：整备 UI、Profile 保存与直接入口

> 总案 M1-T3 实施附录。用户已明确继续开发，沿用已经确认的范围；原工作区执行，无 SubAgent、worktree、自动提交。M1 完成后交付用户 Editor Gate，未经该 Gate 不进入 M2。

## 1. 玩家结果与边界

玩家在独立 InventorySandbox 直接进入整备界面，查看仓库所有实例、二维背包和三根装备法杖的程序槽；拖拽、旋转、堆叠、拆分、丢弃/拾取、装备与卸下都提交资产命令。拖拽取消或目标非法保留来源。明确保存后关闭 Play Mode 再进入，恢复原 ID、位置、次数与旋转。正式三杖施法/Mana/资格/真实材料内容不在本 Task。

无需用户提供美术资源：UGUI 使用基础 Image/Text、系统中文字体和现有法术图标可选引用，缺图标显示名称/颜色。测试地面代理使用 Cube。字体通过 Unity 动态 OS Font 回退，不新增字体版权或导入依赖；测试 Scene 与 SO 放 Tests 子目录，Profile 放独立 SinglePlayer/Sandbox 子目录，绝不覆盖未来正式 profile.json。

## 2. 架构与取舍

1. Run 持有一个 Profile/归属表，UI 只拿 IInventoryReadOnly 快照并向 Core EventBus 提交命令。会话统一发布命令结果和实际版本变化；WorldItemPickup 继续只处理匹配的拾取，避免双响应。命令新增明确目标（仓库/背包/程序槽），保存单独请求与反馈。
2. 批量恢复先建全部 ID，再检查完整父链/空间，支持子项先于父项的 DTO 顺序。无半份库存发布。Profile 保存单机资产普通数据，不保存 ElementWorld、战斗或箱庭续玩。沙盒地面资产恢复为重新排列的拾取代理，M4 再建立 Raid 结算和持久化边界。
3. JsonUtility DTO 使用 schema、提交代、ActorId 和数组。映射验证 schema、定义、重复 ID、次数、唯一归属和空间；未知 schema/定义不回退成空档。损坏主档可加载合法备份，后续保存将损坏主档隔离保留，避免覆盖唯一合法备份。
4. Repository 写同目录临时文件、FileStream.Flush(true)、首次 File.Move、后续 File.Replace 并保留备份。测试通过文件操作边界故障注入验证中断；不宣称断电/多进程一致性。保存成功才更新提交代和已保存版本。已有文件未成功读取前不允许覆盖。
5. UI 的格坐标用 RectTransformUtility.ScreenPointToLocalPointInRectangle 换算，顶部起算整数格；真实空洞不拦截底层物品。复用 Ghost 和按版本缓存的视图；拖拽中不修改来源。窗口关闭、失焦/禁用、Escape 都取消拖拽，释放自身 Inventory 暂停原因；不覆盖其他原因。
6. 法杖程序容量目前还未配置：本 Task 在 ItemDefinition/冻结空间规则中补可配置容量并验证实际槽号，独立于背包尺寸。数值仅测试配置；M2 引入 WandDefinition 时明确迁移固定参数来源，避免两份权威容量。

替代方案：UI 直接写 SO 或维护自己的可写实例表，容易破坏共享数据及失败一致性；逐项恢复不支持任意父子顺序。整份映射/快照在离散加载、拖拽提交或版本变化时分配，持续拖拽只移动 RectTransform，不逐帧 LINQ/创建对象。实际 Profiler 验收属于用户 M1 Gate。
