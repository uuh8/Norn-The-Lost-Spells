## 2. 具体方案与取舍

1. `InventoryShape` 保存只读局部整数格点；每次 90° 旋转 `(x,y) -> (height-1-y,x)` 并交换包围框宽高。空洞没有占用，可以放其他物品。SO 增加形状、堆叠上限、背包宽高，目录创建时验证并冻结空间配置。
2. 归属表是唯一写入口。离散命令在临时字典中形成完整目标状态，再检查身份、父链、装备位、真实占格、堆叠上限和携带法杖数量；全部合法才替换表并增加一次版本。格子是归属表的投影，不再维护第二份可写占格数组。
3. 相同位置、旋转、定义、次数、无限标记、附着/组分状态键的实例构成一组堆叠，每份身份仍独立。状态键只提供后续材料/附着的相容接口，本轮不宣称已实现容器材料内容。保护名单将在 M4 按 InstanceId 实现，本轮只验证被指定 ID 的副本可单独拆出。
4. 一份堆叠成员状态变化时，调用者提供独立目标格；先检查新状态与占格，满包则拒绝整个变化。空容器装料采用总案 D02 推荐方向，M3 接真正材料事务。满包下不会暗中消耗、装料或隐藏成员。
5. 装备采用总案 D01 推荐方向：3 个可切换位，装备加背包内备用法杖总携带不超 3；背包外壳不能嵌套。换背包一次迁移全部直接内容并保留布局；较小背包不适配则拒绝，后续 UI 可先整理再换。
6. 地面拾取物仅作为某份世界资产的 Unity 代理。先创建未绑定的灰盒对象，归属迁移成功才显示；拾取成功停用代理，保持同一实例。事件契约放 Core，纯操作和 Unity 代理放 Run，Editor 仅增加 Run 引用，不改变旧 P7/P8 Runtime 链路。

临时字典分配发生在点击/交易等离散操作，换来可靠的多实例原子提交。替代方案是双表加回滚日志，维护成本更高且容易漏恢复。当前规模优先正确性；每帧只读枚举和 Gizmos 使用结构体 Enumerator，不分配。真实 Profiler 留在阶段 Editor Gate，不能由源码推断通过。
