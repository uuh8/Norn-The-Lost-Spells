# M6-T25 Editor 交接与统一试玩

本轮无需新增图片、模型、VFX或字体。复用现有火焰GPU资源、PortalGold和真实物品模型；修改共享Runtime及两份生产SO，不需要保存正式Scene。M6整体仍在更新中。

## 1. 已实现行为和配置位置

- 从据点按F进入P7/P8，选1–3，左键运行当前已配置法术；只有资源预约成功才扣Mana/次数并创建弹体。副本权限不再依赖从据点复制来的旧实验区开关。
- 副本选4–0中的容器、固体或普通Items，按住G预览，松开G投出真实模型。固体与满容器分批交回材料世界，容量不足扩大落区到最多2m，未提交的量仍保留在途。
- 普通Items撞到墙边时，在碰撞点附近最大1.5m内寻找完整支撑，避免角落跨出地板使物品卡住；常规背包Drop及已保存地面姿态不参与该搜索。
- 实验室真实Fire有可见GPU火焰。家/P7共享`ScriptableObjects/ElementField/Liquids/ElementWorldProfile_P7_DemoRun_Grid.asset`；P8使用`ScriptableObjects/P8/ElementField/ElementWorldProfile_P8BossField.asset`。两份Profile的Max Fire Down Flow Per Tick均为255，世界Tick Rate现为10，Cell Size为0.25m。
- Fire在空处逐格下落，实体支撑阻挡，既有自然衰减及接触反应继续执行。该规则处理真实Cell，不是只让渲染粒子下飘；改变Water Backend不关闭Fire规则。
- 家门视觉面朝向当前Camera；逻辑根/入门Collider/OutsideArrival/缩入中心仍保持原位置。不要通过旋转逻辑父根修正观察角度。
- 背包、仓库等材料数量只显示数字。内部材料账仍使用原数量单位，存档和交易计量不变。

## 2. 一次性统一试玩路线

1. 只打开SinglePlayer_Hub，Hierarchy应只有这一张Scene。Play后应只有一个玩家、EventSystem、Inventory Session和有效Main Camera。
2. 据点F进入P7；Tab配置法术，关闭后选对应1–3并左键，检查真实弹体、命中、Mana和有限次数。选道具按G，观察真实模型和落地元素。P7通关后F返城。
3. 进入P8做同样的输入检查；胜利后才有返程门，不能用提前寻找门来判断回程失败。死亡按既有规则结算，本轮未改死亡遗失范围。
4. 回家，把火写入空中并看它落到地面；用冰/水等验证原有接触反应仍生效。家内仍无敌、隐藏玩家血条。
5. 投出一堆5000冰和15000固态粘液；观察它们能完成落地，不能永远留下等待释放的模型。测试混合气体满瓶同样能完成。比较数量时区分相变后的水/蒸汽，不能只凭冰块外形判断总量。
6. 绕家门左右移动及转镜头，门面持续朝镜头，F进入仍向门中心缩小，回据点后仍出现在原OutsideArrival。
7. 家中留下一件普通物品后出入：普通物品保留，世界元素重新刷新。检查背包、仓库材料Caption没有GMU。

## 3. Debug顺序和证据边界

施法：InputAction→选中法杖→世界权限/冻结→法术程序→资源预约→EmitCommand→真实Projectile，不能只用施法动画作为成功标准。

火焰：真实Fire Cell→Renderer IsReady→TotalSeeds增长→GPU绘制→Camera/视域。Unity已销毁Object的C#引用可能仍非null；用Unity的==判断原生对象存活。禁止用??掩盖已销毁兴趣Transform。

材料：来源量→在途余量→World Imported→真实三相Owner→相变家族账。Capacity拒收不等于丢量；若在途长期不清零，则检查落地区域、活动域、Journal和几何验证。不要删除来源来让PendingFlights显示0。

证据位于`TestResults/SinglePlayer/M6-T25-WorldGameplayRepair/`。末轮290项EditMode和28项PlayMode全部通过。实际火焰Profiler窗口65帧：FireFall 78样本、GPU生命周期和Draw各65样本，三范围GC Alloc均0 B；Editor整帧19474 B，平均Main Thread约21.21ms，不能据此声称整帧零分配或所有GPU负载达标。Editor收尾以该目录最终报告为准。

测试使用内存Repository和隔离Review，未清正式存档。编译、纯测试、实际Scene输入、Profiler、玩家手感试玩分别作为证据，不互相替代；不承诺不存在任何未发现缺陷。
