# 商店三列草稿精修指南

草稿按你提供的样板分区，颜色帮助你快速定位。展开 `__UI/InventoryCanvas_商店/ShopWorkspaceRoot_商店`，本次正式 Scene 修改在 Editor 中保留，由你 `Ctrl+S` 保存；一次 `Undo` 可以撤销本次应用。已有背包、仓库的排布不重建。

## 1. 找到区域并修改

| 父节点 | 区域节点 | 颜色 | 内容 |
| --- | --- | --- | --- |
| `ShopDraft_Left_商品与购买预览` | `GoodsRegion_商店货品` | 蓝 | 真实供货，搜索、分类、商品选中 |
| 同上 | `CartRegion_购买预览` | 金棕 | 清单占位，实际钱包、收购额度、成交反馈 |
| `ShopDraft_Middle_背包与仓库` | `CarryRegion_携带背包` | 绿 | 真实占格背包，旁边装备图预留 |
| 同上 | `WarehouseRegion_仓库` | 青 | 真实仓库资产、出售物品/材料 |
| `ShopDraft_Right_详情与交易` | `DetailsRegion_物品详情` | 紫 | 现有真实商品/资产详情 |
| 同上 | `SpellPreviewRegion_法术效果预览` | 橙 | 法术图标、效果、Mana、冷却的展示占位 |
| 同上 | `TradeInfoRegion_购买信息` | 蓝灰 | 实际数量、目标容器、购买去向 |
| 同上 | `MerchantRegion_商店信息` | 酒红 | 头像、名称、简介占位 |
| 同上 | `ActionsRegion_操作` | 深灰 | 加入清单（停用）、购买所选、关闭 |

区域根的 `Image.color` 修改颜色；`RectTransform` 修改大小。`anchorMin/anchorMax` 是父区域中的比例坐标，左下角是 `(0,0)`，右上角是 `(1,1)`。内部控件使用比例位置，因此修改大区域时可以整体跟随。精修框架材质、描边和标题可直接在这些节点下添加，不需要修改真实库存。

商品和仓库列表使用 `ScrollRect`，它只显示 `viewport` 内的内容；`GridLayoutGroup` 管卡片排布，`ContentSizeFitter` 根据卡片行数扩展内容高度。背包是按物品实际格子位置的只读镜像，可以滚动查看。商店里点背包物品用于选中待售物品；实际旋转、拖拽整理继续在 `Tab` 背包中操作。

背包镜像的 `ShopBackpackView` 位于携带区域的 `ShopBagViewport/Grid`，Inspector 的 `Cell Size` 当前是 70，增大它能让图标更清楚，ScrollRect 会处理超出部分；不会增加真实背包容量。图标角落的余量使用紧凑字号，完整名称与状态看右侧详情。

## 2. 当前已有功能和占位

在商店区域按 `E` 打开；`Esc` 或关闭按钮关闭；`Tab` 切回背包。只隐藏内部 `ShopWorkspaceRoot_商店`，原 `ShopController` 常驻在 `ShopCanvas_据点商店`，它的 Canvas 不绘制。不要停用其 GameObject，否则它无法接收交互事件。商店复制出来的 `SinglePlayerInventoryController` 已停用并解除共享 InputAction；不要重新启用它。

购买前先选商品、输入数量；购买元素需要选择兼容容器，实体购买可选入背包或仓库。底部 **购买所选** 直接走既有交易，不会购买清单占位内容。仓库显示只筛选真实仓库资产，目标容器下拉仍包含所有实际持有容器，防止因为展示分区而无法购买元素。钱包和交易反馈来自同一个正式资产会话，样板中的数字没有作为真实余额写入。

购买清单、加入清单、法术效果卡、店主肖像和背包装备图目前是预留。加入清单按钮保持不可点击，后续确认购买批处理规则后再制作。已有购买、出售的业务规则和可靠保存沿用当前商店系统。

## 3. 原节点、DragGhost 和撤销

复制背包的 `LeftPart/MiddlePart/RightPart/Logo` 仍在原位置，但停用。它们是作者备份，不参与商店 Runtime。商店的 `DragGhost_商店未使用（停用）` 本次也停用，因为商店只展示和选中资产；背包/仓库的 `DragGhost` 仍用于拖拽物品跨越 `RectMask2D` 后跟随鼠标的图片，必须保留。

`Tools/Norn/商店/应用三列颜色草稿（Undo，不保存）` 用于首次应用。工具遇到已有草稿会拒绝执行，避免覆盖你精修后的布局。需要从复制背包重新应用时先 Undo；不要通过反复运行工具替代手工精修。独立审阅 Scene 用于自动测试，正式 Scene 不会被自动保存或用 Review 覆盖。
