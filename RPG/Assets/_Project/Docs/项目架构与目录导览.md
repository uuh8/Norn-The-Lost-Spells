# Norn 项目架构与目录导览

这份文件用于找到入口、理解职责和选择阅读顺序。完整技术解释见[双端开发基础指南](<2026-10-21 双端开发基础指南（是什么、为什么、怎么操作）.md>)；逐项实现、失败证据和验收范围见[联机系统开发解析](<2026-10-20 联机系统开发解析（更新中）.md>)。N4 已完成本机技术验收；正式 P7/P8 场景与共享 UI 的体验接入仍单独验收。

## 1. 三个目录对应什么

外层 `RPG` 是 Git Monorepo；其中内层 `RPG/`、`Server/`、`Shared/` 是三个并列目录，不是三个独立 Git 仓库。

| 目录 | 项目和产物 | 主要责任 |
|---|---|---|
| 内层 `RPG/` | Unity 6000.3.16f1；可分别 Build Client 和 Dedicated Server | Character、Combat、Run 等玩法代码，以及 Client 的输入、相机、UI、Rendering；通过明确的 ExecutionMode 区分权限。 |
| `Server/Norn.Business/` | ASP.NET Core 10 业务程序 | 账户、Session、线上持久资产、匹配房间、实例租约、JoinTicket；它访问 MySQL，不运行 Unity Physics。 |
| `Shared/Protocol/` | `netstandard2.1` Class Library，同时是 Unity 本地 UPM 源码包 | `.proto`、生成消息和纯 C# 合同；它没有 Web Host，也不独立监听网络。 |

Dedicated Server 是从 Unity 项目构建出的独立程序，部署时不需要安装 Unity Editor。Unity 项目里的 Authority 玩法代码用于生成该产物；业务后端仍在并列的 `Server/`。把一份 Gameplay 同源构建为 Client/Server，可以复用角色与技能数据，但必须继续阻止 Replica 写伤害、扣资源或自行运行 AI。

当前灰盒 MovementWorld 与 OnlineCombatHud 是技术验收设施。正式联机必须使用现有 P7/P8 内容和同一套 UI，包括 Tab 背包、左上角道具栏、准心、状态 Icon 与血条；网络适配数据和命令，不另维护正式联机界面。技术测试通过不代表正式共享体验已经验收。

业务 API 使用 HTTP/JSON；本机开发只监听 loopback。实时副本链路使用 Mirror、KCP/UDP 与 Protobuf。Mirror 负责连接和消息适配，不替 Norn 判断伤害、物品归属或法术次数；这些规则仍在本项目的玩法与事务模块里。

## 2. 从玩家操作追踪一次副本

1. 主菜单的 Login/Register 通过独立、持续存在的账户应用根访问业务服。进入据点必须取得新的成功 Profile 响应；缓存 Token 本身不是通行许可。单机同样先登录。
2. 玩家在据点按 F 与副本入口交互，`DungeonEntryChoiceGate` 才显示单机/匹配选择。单机沿原场景与存档路径进入；匹配进入业务房间，不把本地背包直接上传成线上资产。
3. 同一 Dungeon 的 2–4 名玩家准备后，业务服启动或接管独立副本进程；DS 通过 Ready/租约验证后，玩家取得一次性 JoinTicket。
4. Client 完成认证后加载在线世界。Server 收到当前 ConnectionEpoch 的首个合法输入，才把角色视为玩法就绪；连接建立和角色就绪有不同职责。
5. AuthorityTickDriver 在 Update 中推进 30 Hz 逻辑步。角色动作、施法事务、AI、Physics、伤害和状态由 Server 裁决；Client 预测本机移动/动作，通过服务器事实校正资源、远端角色与输出。
6. UI 通过 Core EventBus 消费事实。Replica 保留身体供准心 Physics Query 使用，但没有本地移动、伤害或资源写权限。业务断联进入 Frozen 后停止 Gameplay Tick；表现不能继续推进权威倒计时。
7. 玩家返回据点时恢复原 Hub 会话。其他人仍留在独立 DS 中；同 Run 重入使用原 Actor 和更高的 ConnectionEpoch，不补满已经消耗的资源。

N4 的 Run 内 Mana、法术次数和动作事务由 DS 内存工作区持有；它们不等于已完成结算写库。材料世界联机与正式持久结算分别属于后续阶段，不能把当前战斗同步当作这些功能已经完成。

`Game.Core` 提供合同、事件与基础能力；Combat/Skills/Run/Character 各自持有本领域规则。`Game.Networking` 只做协议与连接适配，`Game.Multiplayer` 组合连接身份、预测、Replica 与权威玩法，`Game.UI` 通过 Core 事件显示结果。不要为了方便让 Combat 引用 UI，或让底层 Core 反向依赖这些上层模块。

## 4. 在 Editor 中怎样核对

用 Unity Hub 打开内层 `RPG/`。在 Project 窗口进入 `Assets/_Project/Scripts` 找到上表脚本；双击在 IDE 中查看。正式业务程序在 IDE 打开并列 `Server` 的 Solution，Shared 是 Class Library，不要误建成 ASP.NET Core 项目。

网络资源由 `Tools > Norn > Online` 下的明确 Setup/Verify/Build 菜单维护；正常情况下先读对应阶段的基础指南，再操作具体菜单。测试在 `Window > General > Test Runner` 中按程序集/fixture 查看。EditMode、真实 Physics 的 PlayMode、两个可见 Player 与 Profiler 是不同证据，单独一类通过不能替代完整玩家路径。
