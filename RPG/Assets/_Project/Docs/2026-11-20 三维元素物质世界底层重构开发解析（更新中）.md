# 三维元素物质世界底层重构开发解析

Home、P7、P8 的单机和联机世界共用 CPU 三维元胞后端。玩家开洞、倒水、沙子下沉和气体扩散共享同一套基础格地址。整个体积有材料，并不要求每格都有对象或每个 Tick 都接受模拟。设计依据见[底层架构设计](<../../../docs/superpowers/plans/2026-11-20 三维元素物质世界底层架构设计.md>)和[Noita 实现研究](<2026-11-20 Noita元素物质世界实现研究与Norn三维设计借鉴.md>)。

## 一格岩石被挖走时

1. 地图作者在世界配置中以整数半开盒定义天然石头和泥土。一个完整岩层共享一条材料记录和一份盒形几何，哪怕下面全是空气也保持原位。场景中已有的普通静态 Collider 可以阻挡材料，只有明确定义为地形材料的体积才有可编辑的材料身份。
2. 工具可按基础格调用 `TrySetTerrainMaterial`，也可将命中地形的 `RaycastHit` 传给 `TryExcavateTerrain`。后者沿命中面的法线向内定位被挖走的格，返回移除的材料身份。挖掘命令可供不同玩法复用。格内已有其他材料时填石会失败，调用方可以保留原有物品或动作成本。
3. 地形树沿最长轴切分到目标格。兄弟区域仍共用完整的块，复原为相同材料时兄弟节点重新合并。地形数据和实际 BoxCollider 提交后唤醒邻域，所以上方的沙、水以及斜上方有斜落路径的沙能继续运动。运行期间还可在初始地形范围外填筑或挖除新地层。
4. 一份静水可以由整个同质盒保存。开口旁边的水能流动时，先让动态格完整接收真实数量，再把同一位置从静水中扣掉。接收容量不足时，原位置继续拥有这份水。初始边界检查按 Tick 预算摊开。读格、采集、气体占位和渲染在交接后看到同一个结果。

以一个 100 × 100 × 100 格的完整岩层为例，它表达一百万个有岩石的位置，初始只需要一个岩层叶节点。与它同样大小、由一种液体填满的初始静水区域也能用一个均匀叶节点表达。新开口附近会增加节点、活动格和可见面，变化越破碎，压缩收益就越小。这个例子说明数据布局，不能换算为帧率。

## 数量、活动和物质属性

| 内容 | 权威表示 | 更新条件 |
|---|---|---|
| 天然石头、泥土 | 可编辑的同质区域树和材料身份 | 地形写入，按命令修改局部几何 |
| 初始液体或后来积成的新湖 | 初始同质盒、按需建立的冷页、实际格容量和例外位置 | 初始边界检查、液面稳定、邻域变化、采集和归还 |
| 动态水、油、毒液、黏液、松沙、冰、干燥残留 | 稀疏基础格，共享预分配槽和按坐标索引的活动队列 | 写入、局部可运动、相邻支撑或成分改变 |
| 蒸汽、毒气 | 同格独立数量，合用主材料留下的空间 | 局部浓差、浮升、挤气和接触反应 |
| 火 | 既有 Fire 强度通道 | 火时钟、衰减、流动和灭火反应 |

一次运动先验证源量、目标容量和可置换性，再成组提交。沙可整格沉入水，原来的水换到沙腾出的格。水和油按密度分层，密度只决定谁可以置换谁。黏液的下落和侧流额度可以较小。两种气体分别计算在剩余空间中的浓度，蒸汽可配置向上偏好。蒸汽与冰面接触能冷凝为等量水，水火接触沿用 Norn 的灭火公式，消耗的水进入蒸汽通道。

每步只处理给定数量的活动候选。新移入的量等下一步才可继续移动，堆积稳定后可以离开工作队列。玩家在空地上倒出新湖时，已稳定的整格或部分装满的液体、落稳的沙和冰都可以进入待归档队列。静水调度器重新核对附近的通量，再把液体从动态槽转交给按需创建的 4 × 4 × 4 冷页。挖开池边、倒入更重的液体或落沙时，边界按需转回动态格。这样，即使池子的位置在编辑地图时还不知道，已稳定的内部也能释放动态槽。

默认每 Tick 动态预算为 1,024 个候选，静水预算为 128 个候选。一份默认配置预留 32,768 个动态驻留槽，静水和岩层另行存储。候选预算控制的是调度数量。地形编辑几何、首次查询旧场景碰撞、火接触、可见 Mesh 和气体 Texture 上传均有各自的成本。开发阶段可分别读取 `CellularActiveCount`、`CellularOccupiedCount`、`CellularCellsProcessedLastTick` 和 `RestingCellsProcessedLastTick`。

火遇黏液沿用原有点燃阈值和湿度抑制。火遇毒液时，沿用原有预热和冷却，结算前重读周围九格的实际燃料数量，消费成功后再走现有伤害入口。这样火的强度、毒液实际 GMU 和最终伤害仍各自有清晰单位。球形投放也会预检本格可用量和可用动态槽，入队后再遇到容量竞争时保留命令重试，容器操作则沿既有预约事务一次结算。

## 编辑器中的接入

在 Unity Inspector 中，单个单机 `ElementWorldRuntime` 的 **Gameplay Data → Profile** 可直接选 [ElementWorldProfile_Cellular.asset](../ScriptableObjects/ElementField/ElementWorldProfile_Cellular.asset)。这份配置沿用单机 P7 的基础格距、Tick、玩法目录与反应资源，并已指向新后端。若已有独立的世界配置，也可以只把 [CellularWorld.asset](../ScriptableObjects/ElementField/CellularWorld.asset) 拖入该配置的 `Cellular World` 字段。下次创建世界实例时生效。

各个世界需要不同地层和输运参数时，可在 Project 窗口用 **Create → Game → Element Field → Cellular World** 建独立配置。基础格距、Chunk 边长和 Tick 频率读取外层 `ElementWorldProfile`。内层配置的区域坐标相对该世界的原点，Y 轴向上。已有场景或世界若共用同一外层配置，修改前需核对其引用。

新配置随仓库提供，初始没有预设地形或液体。Terrain 可声明 Rock、Soil 或空区，Resting Liquids 可声明装满液体的整数区域。两种实体区域占据相同格会拒绝初始化。Transport 可按材质覆盖相对密度、下落流量分母、侧流分母和气体上方权重。设置在世界创建时烘成只读表。

## 正式地图和真实操作

Home 以实验地面的原 BoxCollider 作为泥土基底，P7 接管关卡明确标记的四处天然岩体，P8 直接使用原 TerrainData 的高度和孔洞。房间设施、建筑、门和角色仍按原有方式参与碰撞。地图保留原外观，开洞时只替换受影响的几何。地图副本的快照记录被改动的格，恢复原材质时撤销相应覆盖。[地图来源](../Scripts/ElementField/World/CellularMapTerrain.cs) · [正式地图导出](../Editor/ElementField/CellularMapContentSetup.cs)

单机及 DS 上的陨石命中会把 Collider、接触点、法线和爆炸强度交给材料世界。世界核对 Collider 的所有权，按材料抗性决定能否挖掉命中的一格。普通法术仍使用各自的玩法合同。投放的物质先算真实可容纳的 GMU，再提交数量。喷口方向在格间短时保留，直线路径遇墙后回到该材料通常的运动规则，邻近沙粒和原有的水继续按各自数量受力。[陨石命中](../Scripts/Combat/Projectiles/NovaFireball.cs) · [格间输运](../Scripts/ElementField/World/ElementCellSimulation.Impulse.cs)

地形与初始液体由地图确定。迁移旧作者配置时，先按旧粗格重建真实 GMU，再把同一总量分配到细格。已经有运行库存、分时启用的作者对象或依赖旧水位的闸门会保留原后端，并记录原因。三个正式地图没有此类闸门迁移要求。P7 的材料掉落物仍属于原有物品系统。[初始物质交接](../Scripts/ElementField/Runtime/ElementWorldRuntime.ContentMigration.cs)

## 相变、气体与表现

加热、冷却、冻结、融化、干燥和挥发由现有 MaterialConversionProfile 决定。世界轮转显式环境区，并把发生变化的材料或火接触送进有预算的候选队列。一次配方先在中心和六个面邻格中预演源量、产物和显式消散量，全部放得下才提交。材料槽、容器、待投放 FIFO 和消耗账本从同一笔数量变更读取。正式 Profile 中禁用的规则保留禁用状态。[配方调度](../Scripts/ElementField/Transitions/MaterialConversionScheduler.cs) · [多产物事务](../Scripts/ElementField/World/ElementCellSimulation.Reactions.cs)

气体占用主材留下的空间，按气体种类、浓差、浮力和风传输。原通风口按真实数量排气，极稀薄的残雾按块浓度、持续时间和处理预算清理。风、通风、消散只需要局部气体数据。客户端继续使用 RealGasVolume 的密度纹理和时间混合。液体外壳只为暴露面生成 Mesh，单独水滴的相邻两次位置可在 Vertex Shader 中插值。客户端按视锥筛选可见页，每帧的重建预算独立于 Gameplay Tick。[气体输入](../Scripts/ElementField/Runtime/ElementWorldRuntime.CellularGas.cs) · [可见页索引](../Scripts/Rendering/ElementField/CellularMaterialRenderer.Culling.cs)

## 联机与恢复

同一份地图基底存在于 Client 和 DS。首次进入时用版本锚点校对地图、格距、Chunk 尺寸和格容量。静态地形编辑、显式挖空、冷页和动态主材与气体在同一块正文中原子安装。安装成功才确认 Revision。离开 Interest 可以释放局部表示，重入后由 Baseline 或 Delta 恢复。没有变化的权威步只推进时钟，局部变化走触达块，缺失可靠变化记录时重新捕获完整状态。旧四域正文仍有各自的读取路径。[局部捕获](../Scripts/ElementField/Replication/WorldReplicationSource.Cellular.cs) · [Replica 读模型](../Scripts/ElementField/Replication/WorldReplicaCellularReadModel.cs)

Checkpoint 保留已提交的材料、明确的洞与有序待处理输入。既有恢复合同中的 `CanRestoreAuthorityRules=false` 表示这份存档不能独立重启整个 DS 的模拟时序。连接恢复和房间内重新进入视野使用已提交的世界版本。

正式配置给已经发生变化的世界留出 4,096 个驻留 Chunk 和 1,024 条近期变更记录。尚未编辑的地图基底由两端各自持有，区块正文按实际数据量分配。单次 Checkpoint 的编码上限为 64 MiB。这些限制分别约束房间状态、增量历史和持久化负载。[复制配置](../Resources/Online/WorldReplicationProfile.asset) · [Checkpoint 合同](../../../../Shared/Protocol/Runtime/Business/OnlineRunAssetCheckpoint.cs)

## 2026-11-21 继续削减随世界规模增长的工作

## 2026-11-21 整图材料与实际运动压测

### 实测后改了哪些路径

* **容量和工作预算独立。** 旧配置先为 32,768 个动态地址预分配槽与索引。真实画面压测中，水、沙、蒸汽各有 4,800 个初始源，第一次持续加料很快就触到了这个上限。现在每个世界从零个驻留槽起步，一次申请 512 格，正式上限为 131,072，活动队列仍然每步最多取 1,024 个候选。槽索引稳定，因此运动、休眠、容器和复制可共享地址。封闭地形与静水仍有自己的压缩表示。[动态页面](../Scripts/ElementField/World/ElementCellSimulation.Storage.cs) · [正式配置](../ScriptableObjects/ElementField/CellularWorld.asset)
* **邻域查询和满槽气体。** 地形与场景阻挡用 4³ 格位图缓存，挖掘或回填立即使该格失效。格内主材和两个气相通道一次读取。所有槽占满时，单格纯气体如果只能向空格扩散，少量分出去就需要两个地址。现在按面累计真实通量，当足够搬运原格全部气体时，原子提交整格迁移，归还源地址。重新有空槽后恢复分量扩散。同格混合物和封闭容器仍然受到空间与数量约束。[环境查询](../Scripts/ElementField/Runtime/ElementWorldRuntime.Cellular.cs) · [气体通量](../Scripts/ElementField/World/ElementCellSimulation.Gas.cs)
* **显示进度。** 旧 Renderer 在每帧轮询可见页并最多重建 8 页。大量页被反复弄脏时，世界已经改变，远处仍显示一秒多以前的状态。可见脏页现在保留首次入队位置，下一帧从尚未服务的页继续。在没有材料 Tick 的帧用有界的 CPU 时间补做重建，并缓存 Mesh 各 submesh 的有效索引。单独替换 Renderer，在相同的 f82 模拟、地图、相机和负载下，最老可见脏页等待的 P95 从 1,478 ms 降到 92 ms，整帧的 P95 从 22.36 ms 降到 19.47 ms。两次均为 1920 × 1080、12 秒窗口，三种材料均有 120 个独立运动 Tick。[渲染 A 组](../../../docs/superpowers/evidence/element-world-scale-20261121/renderer-before.json) · [渲染 B 组](../../../docs/superpowers/evidence/element-world-scale-20261121/renderer-after.json)
* **联机打包和首显。** Authority 为受影响的 Chunk 保留稀疏索引，8³ 纯元胞页可按局部坐标排序。正式 v20 传输可把一个普通材料记录压成一个 32 位字，接收端展开、校验规范 W2 内容并成功安装后才发 ACK。每个连接在订阅通知与已订阅块的正文之间轮流服务，玩家附近可先收到一块。相同 P7 压力下，两名观察者从第 3 帧权威提交到第 4 帧就能看见附近首块；满兴趣范围仍需继续同步。旧调度下首个近处材料要等到第 121、122 帧。[W2 紧凑传输](../Scripts/Core/Online/WorldChunkPayloadCodec.CellularWire.cs) · [双观察者结果](../../../docs/superpowers/evidence/element-world-scale-20261121/network-expanded.json)

## 正式 Home 的积水与沙堆体积

玩家在 Home 倾倒多种物质后，从角色视角看到几块平坦的色斑。我们读取同一时段房间最近一份材料 Checkpoint，按材料和 XZ 列合计所有高度层的 GMU，再乘以格高除以单格容量。这样能把真实薄层与相机、Shader 导致的视觉扁平区分开。旧版水量为 1,032 GMU，散布在 272 列上，覆盖 17 m²，中位深度 2.94 mm，最深 8.82 mm。毒液、黏液和油的最深处均为 5.88 mm。这个快照记录房间状态，截图本身没有记录 Tick。[旧版实测](../../../docs/superpowers/evidence/element-world-volume-20261121/home-prior-depth.json)

**液体怎么停下来。** 原规则在有支撑的平地上反复把高度差二分给相邻空格，流速只影响多久摊开。现在平地上的干格需要源格达到该材料的铺展液位才会被润湿，两个已湿格继续按液位差找平。水和毒液默认使用格容量的 60%，油使用 40%，黏液使用 85%。这些比例是可调的粗格玩法参数。悬边下方有容量时，边缘残量也能排走。活动页求解和休眠页的唤醒判定复用同一规则。历史存档的材料保留在原坐标，收回再倒出时会按新规则运动。

**沙怎样堆高。** 同类沙在竖直相遇时先填满下层，余量留在上层或沿斜面滚落。低于四分之一格的沙在格底中间形成小团，四分之一格以上铺满底面并按量增高。团块的宽 × 高 × 深等于真实填充率。角色的 BoxCollider、活动格和压缩格画出的沙均使用这组尺寸。相邻等高的沙只有互相接触才共享碰撞盒，获取、倾倒、远端 Replica 安装与安装失败还原均使用同一份数量。

**水岸怎样画。** 有水的相邻格共享边界，只给接触干地的浅水外轮廓生成向下的坡肩。暴露凸角向水体内部收圆，贴墙边界保留接触高度。渲染出的岸缘是向内的几何近似，水量、采集和水位从权威网格读取。角色与水使用相同主光环境，水的可见位置、阴影和相机深度使用相同的顶点位置。
