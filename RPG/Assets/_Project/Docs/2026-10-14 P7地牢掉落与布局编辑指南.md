# P7地牢掉落与布局编辑指南

后续M6-T19已将关后奖励改为随机有限20–40次、最终三种不同法术，掉落法杖改为实例属性，金币增加竖立旋转/弹跳；新增配置以《2026-10-14 P7随机奖励与法杖参数编辑指南.md》为准。本指南继续说明四关布局和概率表基础，不再把旧固定8次或全集作为当前P7奖励规则。

本轮采用固定四关；每次进入产生新的敌人与地面物品，死亡掉落重新抽取，不保证每次抽到的结果必然不同。仍按顺序触发战斗、清场开门、领取关后法术，最后按F返回据点。金币落地后角色接触自动入账；其他奖励沿用F拾取或背包附近物品拖拽。气体/液体仍需容器，不能直接作为普通材料卡装包。

## 1. 在哪里调概率和数量

四张ScriptableObject位于Assets/_Project/ScriptableObjects/SinglePlayer/P7Dungeon：Stage1Loot.asset至Stage4Loot.asset。

Items每项代表独立的一次抽奖：Pool是候选ItemDefinition数组，成功后从中等概率选一种；Chance在0–1，0是不掉、1是必掉；MinCount/MaxCount是该种物品的数量闭区间，一次最多16份。SpellCharges是有限法术每份的次数，UnlimitedSpell=true时不显示次数；MaterialQuantity是固体每份GMU，运行时限制在其定义容量以内。容器实例不堆叠，法杖掉落是可正常装备/替换的独立实例。不要把没有注册到当前Catalog的ItemDefinition随意拖进Pool，初始化会明确拒绝，以免玩家拿到无法保存/交易的资产。

默认每关四类：法术概率25/29/33/37%，法杖4/6/8/10%，容器12%，材料35%。金币概率75%，金额分别10–25、18–40、26–55、34–70。每类独立，所以一只怪可能同时掉钱和多类物品，也可能什么都不掉。这是测试经济配置，调表就能改，不必改代码。既有商店以完整冒险进度补货：四关全部清场只计一次，不按每个小关或每只怪重复补货。

## 2. 布局和拾取物

Assets/_Project/Prefabs/SinglePlayer/P7Dungeon/FixedFourStageLayout.prefab包含八段内墙和八个Explore material节点；可打开Prefab分别移动墙、改变长度、替换材料定义。布局与P7外墙/门分开，避免修改生成工具时重建整个地图。WorldItemSpawnPoint的Initial Material Quantity是固体实际GMU，非固体不使用；SpawnId必须唯一。材料量为0会成为空模板，通常不适合探索奖励。

正式P7中的P7 Dungeon · 固定迷宫与探索挂DungeonRunContent，四个Encounter引用必须保持原顺序，各自绑定一张掉落表。运行时初始化在库存工作区完成后执行，避免不同GameObject的Start先后顺序导致没有Session。每个敌人的掉落Adapter挂在独立子节点，敌人尸体销毁后不会让尚未完成的奖励一起消失。

修改内墙后必须重新Bake对应NavMesh；只移动视觉并不能让敌人的寻路自动更新。动态战斗门要用打开状态参与Bake：如果把关闭门烘焙进去，运行时开Collider也不会补回已经删除的导航面。地面材料展示不参与Bake，避免小型拾取物在静态导航上造成永久洞。独立地牢导航数据是DungeonNavigation.asset，保留原P7导航资产。

## 3. 地面法术和金币的美术入口

GroundSpell.prefab是提供的Art/Prefabs/Rewards/Spell.prefab的纯视觉派生包装。保留Visual/Cube及环/粒子，移除旧自动发奖组件和碰撞；真正的物品身份与拾取由WorldItemPickup管理。不要重新加SpellRewardPickup，否则普通丢弃物可能再次发关后奖励。

Cube使用Art/Materials/P7/GroundSpellIcon.mat的URP Unlit材质。运行时MaterialPropertyBlock按实例赋予各法术Icon；不修改sharedMaterial，不通过renderer.material生成整份材质。Multiple Sprite的裁剪是像素坐标，转换为纹理UV的scale/offset，所以冰球等子Sprite不会把整张图集显示在Cube上。若希望更换环/粒子，请在GroundSpell.prefab设计；源ThirdParty和用户原Spell.prefab保留。

GroundCoins.prefab是可替换的金色扁圆柱表现，金币没有新增背包ItemKind。SphereCollider开启Is Trigger，kinematic Rigidbody保证CharacterController接触事件，WorldCurrencyPickup成功提交钱包后才消失。多个Collider同帧接触不会重复加钱，余额溢出/冻结时保留金币。可替换Gold coin子对象模型，但保留根触发组件。

## 4. 验证和保存

先使用隔离P7_DungeonReview验证，不把Hub/P7/P8同时运行。菜单Tools/Norn/P7 Dungeon/Prepare isolated Review会生成资源、保存Review并恢复原场景；Open saved P7打开单独的已保存P7；Apply to current P7 (Undo, no save)通过Undo应用到当前P7，正式图必须作者自行保存。修改布局Prefab后可重新Prepare来Bake独立导航，再Apply把导航接入正式P7。本轮专项结果以TestResults/SinglePlayer/M6-T18-Dungeon/final-verification.md为准，未写最终通过前不把编译、自动测试或截图等同于人工通关。

奖励位置还要检查NavMesh路径连通；最近导航面可能是原有孤立高台。无法从玩家所在面走到高台时，奖励投影到附近可达地面；仍无法找到则落在玩家所在导航面，优先保证能拿到，而不让地图之外的掉落永久丢失。

查看绿色预览时，拖拽的物品轮廓进入附近网格即可，无需鼠标先进入新格；绿色代表可摆放，红色代表占位冲突。取消拖拽或跨回背包会清除原目标色，附近UI重排仍不会改变地面物品的实际世界位置。
