## 1. 你在制作什么

一个天然湖由三部分组成：有 Collider 的 Solid 地形、标记湖盆搜索范围的 Bounds、以及运行时拥有液量和水位的稳定区域。湖底、水面下面的深水不用建立成 GPU 粒子；平静时只更新有变化的数量/水位，画水面 Mesh。局部排水、注入和地形操作才把相关分片展开成活动格，结束后再归入稳定状态。Water、Poison、Sticky 使用同一底层，但材质、流速与反应由各自 Profile 决定。

视觉 Mesh 是 Gameplay 的只读消费者。GMU 是游戏中记账的材料数量单位，**不等于粒子个数**。当前正式 P7 与新建湖泊模板使用液体粗格和统一体积换算：每格 0.5m / 510 GMU，单位 GMU 代表的体积为旧模型四倍。圆润 Mesh 保留有限艺术夸张，但主体厚度随数量变化；自然湖的大体量继续由稳定数量表示承担。

**2026-10-01 数量与表现更新：** 0.32m 现在是圆冠参考厚度，不再是任意微量水的显示下限。少量水变薄，注水抬高主体；接近满一个粗格时圆冠逐渐减小，几何峰值不会提前超过该层的真实容量高度。`M_GridLiquid_Water/Poison/Sticky` 的 `Cartoon Swell Height (m)` 默认 0.025m，继续提供柔和起伏；这项小幅 Shader 动画仍属于显示。Grid 毒爆默认预热 0.2 秒，同一爆炸范围共享 1 秒冷却；持续接触可在冷却结束后再次反应。历史记录中的固定 0.53m 冠高已由本次规则替代。

火焰调校资产为 `GpuFireParcelRenderProfile_Default`。`Minimum Ground Source Height` 默认 0.56 m，避免燃烧源被圆冠埋住；若自定义更厚液体，需将它调到液体显示冠高以上。`Minimum Visual Heat` 只影响低量火的可见性，不能用它修改燃料或伤害。参数变更后退出并重新进入 Play。检查时先隔离 Water/Poison/Sticky，避免 Water 灭火或 Sticky 转换 Water 混淆现象，再检查组合反应。

## 2. 从一个可靠的小湖开始

1. 进入 Edit Mode，保存当前场景。在 `Tools > Element World > Authoring > Configure Current Scene` 配置液体世界。已有元素世界保留 Catalog、反应、状态和火焰规则；新的 Grid Profile 独立保存，不覆写旧 PBF Profile。核对 Liquid World Profile 的 `Resolution Scale = 2`、`Unit Volume Multiplier = 4`。已有自定义 Profile 不会被菜单强行覆写；专用历史测试原型仍可保留 1/1。一个场景只保留一个元素世界。
2. 选中 Element World，找到 `ElementFieldSolidBaker`。`Solid Layer Mask` 应包含湖底、岸壁和岛屿 Collider 所在 Layer。角色和法术 Projectile 的 Layer 不应作为静态湖底。默认新世界以 Default 为 Solid，需要按场景调整。
3. 先用 Cube 制作闭合湖盆：底板中心 `(0,-0.25,0)`、Scale `(8,0.5,8)`；左右岸中心 `(-4.25,1,0)` 和 `(4.25,1,0)`、Scale `(0.5,2,9)`；前后岸中心 `(0,1,-4.25)` 和 `(0,1,4.25)`、Scale `(8,2,0.5)`。这些值假定世界 Origin 为零、液体 Cell Size 为 `0.5m`，内尺寸为 `8×8×2m`。Primitive 自动带 BoxCollider，把五个物体设到 Solid Layer，保持非 Trigger、无 Rigidbody。
4. 执行 `Create Water Lake`（或 Poison / Sticky）。创建的是搜索体积，不会自动给你的地形补墙。默认 Trigger BoxCollider 的 Center `(0,1,0)`、Size `(8,2,8)`，刚好覆盖上例的湖盆内部。保留 `Is Trigger`；它不会被 Solid 查询当成障碍。选中物体可看到彩色搜索框。
5. `StableLiquidRegionAuthoring` 已连接当前液体世界，并启用 `Derive Bottom From Solid` 和 `Sectorize By Chunk`。先保留 `Initial Fill = 0.75`。这是占总容量的 75%，变深湖盆中的水位由容量曲线计算，不一定是高度的 75%。
6. 点击 Inspector 下方的 **检查湖盆地形与封闭岸线**。失败时会显示第一处开口、缺地板、悬空顶板或预算问题。修正后重新检查。该按钮只在你点击时检查 Physics；不在每帧扫描湖盆。
7. Play：区域组件的 `Region Id` 应不小于零，水应从开始就存在。`Grid Liquid World` 的 `Stable Quantity Gmu` 大于零；无操作时 `Active Cells` 和动态 `Resident Chunks` 应为零或很小，不应随深水体积增加。

配置菜单在 Edit Mode 修改组件，不替你保存新场景。满意后 Ctrl+S。不要在 Play Mode 调整持久 ScriptableObject 后忘记保存了什么；场景物体的临时修改则随退出 Play 丢弃。

## 3. 换成自然湖岸、浅滩和岛屿

保持“每一列从湖底到搜索框顶端连续为空”的 Heightfield 模型。TerrainCollider 或其它地形 Collider 都可以作为底面；台阶、浅滩、穿过水面的岛屿由 Solid 采样生成容量与占地。Bounds 的最低面要覆盖最深的底部，最高面要低于连续封闭的岸顶。框内整列 Solid 会成为岛；较浅的 Solid 底部会成为浅滩。

Bounds Collider 可以随物体移动、缩放，但应与世界坐标轴对齐。旋转倾斜的 BoxCollider 的 `bounds` 是更大的 AABB（轴对齐包围盒），会搜索到框外区域，组件会拒绝这种配置。水格与 Origin 对齐，不是与每个湖物体单独对齐；尽量让地板和岸壁边界落在 Cell Size 的整数倍位置。

当前不支持把桥下洞穴、悬空顶板和多层水洞编码成同一个稳定湖盆。这些形状需要分开制作成独立湖盆或保持局部动态液体。两片不连通的水域也应使用两个 Bounds。

## 4. 体量与预算怎么看

所有湖共享当前 `LiquidWorldProfile` 的稳定区域、Surface Patch、动态 Chunk 和活动队列容量。默认新建模板的液体 `Cell Size = 0.5m`、`Chunk Size = 8`，一片水平范围约 `4×4m`。对齐的 `8×8m`、`2m` 深湖约需 4 片；满湖 128m³ 对应 522240 GMU，75% 初始液量对应 96m³。稳定深水由容量曲线记账，避免为湖底每份水建立活动粒子。

当前模板的稳定区域上限为 128，Surface Patch 上限为 2048，单次局部展开最多 1024 格、最多 4 个表面 Chunk。完整 `8×8` 格水平分片在 1024 格预算下最多支持 16 格高，即当前粗格的 8m。Inspector 预检使用与 Runtime 相同的液体粗格及容量；水位虽然低，搜索框仍决定展开上界。请先用 1–2m 深的湖学习，再扩展尺寸。多个岛/凹凸岸线会增加 Surface Patch 数量。

达到预算时系统会拒绝注册/展开并留下诊断，不会为了接收新法术悄悄删掉旧水。想加大关卡容量应同时检查初始化内存、稳定区域、Surface Patch、动态展开和 Renderer `Maximum Chunk Views`，逐级扩展；单纯调高粒子数不解决这些问题。`Rejected Deposits`、`Activity Overflow`、`Omitted Candidate Views` 应保持为零。

## 5. 注水、排水和局部地形操作

法术的液体写入继续通过元素世界统一入口到 Grid Liquid。独立原型中的 `LiquidPrototypeProbe > Deposit In Play Mode` 可以用于注水；要停用粘液反应，应停用 `Sticky Initial Puddle` 或粘液写入源，停用 `Sticky Dynamic Surface` 只隐藏外观，不会删除粘液数量。

选中 Lake Bounds，执行 `Create Outlet For Selected Lake`。把父物体放在岸边缺口的高度；将子物体 `Receiving Cell` 放到湖盆以外一个能接水的空格。默认关闭，Play 中执行 `Toggle Outlet In Play Mode` 开关。`Opening Area Cells` 是开口面积的格单位，`Conductance Gmu Per Second` 是最大流量尺度。排水影响局部动态格和稳定数量；整个湖的水位变化可低频传播，不承诺每帧真实压力平衡。

菜单不会挖开地形。若缺口有塞子 Collider，需要把它赋给 `Plug Collider`；不要在 Play 中直接禁用任意 Terrain Collider 后期待缓存自动正确重建。正式的局部障碍修改要走 `StableLiquidStaticCellAuthoring` 或相应 Runtime 预检/失效接口，先确认展开能接收数量，再更新 Solid 缓存。

## 6. 表现调节与排查

正式使用的三个材质在 `Assets/_Project/ScriptableObjects/ElementField/Liquids/M_GridLiquid_*.mat`，首次创建复制原 `M_ElementWater/Poison/Sticky_PBF.mat` 的表现参数。新网格通过 `ElementLiquidDormant.shader` 复用原表面的 Fragment，不需要 GPU 粒子。`Shallow/Deep/Fresnel Color` 控制浅层、深层和视角边光；`Wave Normal Strength` 控制波纹法线，`Wave Speed A/B` 是随时间移动的两层波纹，`Smoothness` 控制高光，`Foam Strength` 控制接触泡沫。设法线强度为 0 可定位几何问题，正常运行不要开启 `Force Opaque Fragment`，该诊断开关会跳过全部光照并只画纯色。材质创建后不会被配置菜单重置用户参数。

当前表面恢复原来的 Transparent/PBR、世界坐标 Triplanar 波纹、深度渐变、Fresnel 和接触泡沫；URP 的 Camera Depth Texture 应保持启用。它比上一版纯色 Cartoon Shader 有更多 Fragment 工作，之前纯色版本的 GPU 时间不能用来保证本版本的成本。旧 `M_CartoonLiquid_*.mat` 和 Shader 保留作回退参考，正式六个 Renderer 应使用新的 Grid 材质和 Dormant Shader。人工直墙形成的直岸仍是合理形状；粗 Cell 的动态轮廓通过固定两步 Taubin 平滑降低台阶感，视觉顶点调整不会改变数量。空中液体采用连续隐式外壳，邻格接成液团；竖直落水包之间的一格短间隙可视觉连接，远距离断开的液量仍表现为独立滴。

要区分表面动画与液体模拟：Shader 的波纹由 `_Time` 驱动，即使静止湖面的 Mesh 不重建，也能持续变化。真正的下落、横向扩散和排水由 Gameplay 的局部 Flux/Outlet Solver 改变数量；这是简化流量模型，未求每个粒子的 PBF 密度约束、惯性涡旋或真实压力。平静湖泊保持数量与水位，不需要靠持续全湖求解获得表面动画。

如果没有水：先检查 Console 的第一条初始化/注册错误，再看 Layer、Bounds 地板/封闭性、Region Id 和数量。如果有数量没有表面：检查六个 Renderer 是否启用，World/Material/Shader 引用，Pending Views 和 Omitted Candidate Views。角色接触不到状态：检查 Exposure 的 Target Layers 是否包含角色 Collider 的 Layer；画水面不等于已配置状态查询。

## 7. P7 接入与回退

`Migrate P7 To Grid Liquid` 在已有 P7 场景内修改液体相关组件，保留角色、敌人、关卡和法术；旧 PBF 组件留在场景中停用，正式场景 GUID 和 Build Settings 不变。切换前的场景备份保存在项目外资产目录 `Backups/GridLiquidCutover/`，`latest.txt` 记录原始备份。

`Restore P7 Before Grid Cutover` 会显示要恢复的文件名，并再备份当前已保存场景。它拒绝覆盖未保存的 P7。回退只恢复场景接线，新 Profile、Shader 和原型保留以便继续比较。不要手工重置整个 Git 工作区，里面还有你其它开发修改。

以下是之前版本的调校和测试记录；固定厚度、旧粒度及旧性能数字不能作为本次默认值。当前操作与验收以本文前七节、第八节“数量与水位联合检查”和第九节“运动、分层与落水检查”为准。

## 四项反馈后的检查方法（2026-09-30）

- Play 前新增用于池壁/地板的普通 Cube：保持启用 BoxCollider、非 Trigger、无 Rigidbody；Default 层会自动被液体环境采样识别，原 Ground 层仍支持。确保墙贴到池底，没有实际几何缺口。Play 中移动墙体仍需要显式地形失效流程；单改 Transform 不会重烘焙旧缓存。
- 水/毒/粘液的自由岸线现在用连续覆盖率插值，稳定后也保留圆润轮廓。真实墙体的直岸仍可以是直线；真正没有液体的孔洞仍保留，不能以“所有边界都弯曲”作为验收标准。
- 把强 Fire 打在 Sticky 上，应看到接触燃料处产生 Fire，Sticky 被消耗；满强度点火源不能阻止邻格引燃。Water 达到 Wet 抑制阈值仍会抑制点火。
- 从高处生成三种液体，观察下落是否逐渐加速且两 Tick 之间持续移动；落地后铺开，不能穿透墙/底板。Inspector 的 Grid Liquid World Profile 可调 Fall Gravity（m/s²）和 Fall Terminal Velocity（m/s）。大湖内部无需给每份液体保存速度。
- 自由岸线与稳定岸线按四分之一 Cell 进行视觉采样，均匀湖面仍合并大三角形；没有加密 Gameplay Grid。高速连续落水允许同一列的实际液包之间在有限距离内显示为水柱，不会为视觉连接增加液量。自然岸线应更圆润，真实直墙围池的边沿仍可为直线。
- 新材质的 Wave Scale A/B 默认 3.5/5.3，让波纹更宽；水的 Foam Distance/Strength 默认 0.035/0.25。若薄水滩看起来全是白色细点，优先降低 Foam 强度和 Wave Normal Strength，再调宽波纹，不必增加模拟数量。
- 开发回归 XML：`Temp/ElementPerformance/liquid-four-fixes-final-regression.xml`，核心批次 23/23；包含实际 Default Cube Collider 围池 1020 GMU、连续重力加速、点火和跨页水柱。动态与稳定网格的 Warm Rebuild 有零托管分配断言。整体游戏帧时间应单独用 Player/Profiler 判断，不能将算法断言当作 FPS 达标。

## 本轮三项续修后的观察方法（2026-09-30）

**最新圆肩调校（2026-10-01）：** 默认浅滩凸起提高为 **0.32 m**。岸线和高度统一使用连续覆盖场，取消空方格矩形距离的折脊；外轮廓每段补一个曲线中点，内部网格边不加密。圆肩的向内距离过渡尺度为 1.2 Cell（Cell=0.25 m 时约 0.30 m），这是连续场的一阶距离近似，实际宽度随形状变化。顶面波纹保留、侧面波纹减弱。低视角检查边缘是否仍出现竖向折片，并在静止后比较轮廓。该效果提供卡通的视觉张力，没有加入真实 Surface Tension 力。

1. 用一条连续粘液带，把火打在一端。应看到点火沿邻格向外传播、燃料逐步被消耗；积水和燃料空隙可阻止传播。不要把关闭 Sticky Surface 当作关闭燃料来源。点火强度与液体 GMU 是不同量，火有热量种子以维持传播。
2. 降低相机看水滩侧边：应看到隆起和圆润的岸沿，静止后保持体积。根据卡通风格反馈，动态/稳定 Surface 组件的 Minimum Puddle Depth 默认均提高为 **0.32 m**（此前依次为 0.09 / 0.22 m）。想调整饱满程度，应先 Stop，再同时调整两者，建议范围 0.28–0.40 m；这是只读显示下限，状态/排水数量不增加。深湖仍按实际水位显示，现有波纹 Shader 保留。Unity 已序列化的自定义数值不会被 C# 新默认值覆盖，请在 Inspector 检查水、毒液、粘液的 Dynamic/Stable Surface 都采用所需厚度。
3. 从高处持续注水，空中液包使用较粗的一格外壳，落水仍连续积分并受 Solid 阻挡。地面岸线保持四分之一格采样。Profiler 主要看 GridLiquid.Surface.MeshRebuild 及 GridLiquid.Mesh.FieldScatter，不只看 FluxSolver。三个材质共享默认 2 ms 的普通帧重建预算；稳定转动态的交接帧可优先补齐最多四页，避免缺面。单页无法被抢占，所以 2 ms 不是硬帧时间保证。
4. Pending New/Dirty Views 应在停注后下降，Omitted Candidate Views / Rejected / Activity Overflow 应为零。材质轮换处理后允许短暂排队，不能出现越来越长的首显延迟。Whole-game 60 FPS 的目标帧时间为 16.67 ms；本轮 P7 短窗口 P95 约 38 ms，不能标记已达标。组件 GC 实测为零，完整游戏的 GC/GPU 仍应分别检查。

实测与取舍见完整解析 L4.9；本轮报告文件在项目 Temp/ElementPerformance，临时目录可能被 Unity 清理，长期结论以解析中明确标注的日期和验证范围为准。

## 8. 数量与水位联合检查（2026-10-01 当前版本）

### 1. 先理解两个参数

`Resolution Scale` 表示液体格相对世界基础格的边长倍数。世界基础格保持 0.25m，液体设为 2 时使用 0.5m；同样的对齐空间只需原来约八分之一的液体格。火焰和其它世界材料的格子保持原尺寸。

`Unit Volume Multiplier` 表示一个 GMU 代表多少倍旧液体体积。设为 4 时，同一杯水用四分之一的旧 GMU 就能装满。**只改 Resolution Scale 不会减少填槽所需 GMU**：空间变粗时每格容量也要增加，才能保持总量含义。GMU、活动格数、Rendering 顶点数是三种不同指标。

当前每格容量 `255×2³÷4 = 510 GMU`，每 GMU 约 `0.000245098m³`，即 `0.2451L`；1020 GMU 对应 0.25m³。Grid Liquid World 在 Play 中显示 `Runtime Cell Size Meters`、`Runtime Cell Capacity Gmu`、`Total Volume Cubic Meters`。最后一项为已经进入动态/稳定世界的体积；Pending 的请求另记，不能拿尚在排队的水判断已经填槽。

### 2. 做一个可数的小水槽

建议在独立测试场景操作，避免正式关卡其它天然水、毒液、粘液或反应干扰全局统计。保留世界 Origin=0，配置 2/4，先只保留 Water。底板中心 `(1,-0.25,1)`、Scale `(4,0.5,4)`；左右墙中心 `(-0.25,0.25,1)` / `(2.25,0.25,1)`、Scale `(0.5,0.5,3)`；前后墙中心 `(1,0.25,-0.25)` / `(1,0.25,2.25)`、Scale `(2,0.5,0.5)`。四壁围成内尺寸 **2×2×0.5m** 的空槽，所有 Collider 非 Trigger，墙和底不留缝。停止 Play 后制作，进入 Play 后不要直接移动这些静态墙。

容量为 16 个粗格 ×510 = **8160 GMU / 2m³**，旧模型需 32640 GMU。新建空物体，添加 `Liquid Prototype Probe` 组件，将带 `LiquidWorldRuntime` 组件的液体世界物体拖到 `Liquids`。把 Probe 放在槽中央上方，Material=Water、Quantity=1020，Radius 可先设 0.25m；进入 Play 后从组件右上角三点菜单选择 `Deposit In Play Mode`。每次注入后等 Pending 清空、落水趋稳，再记录。没有初始水、泄漏或消耗时，**约八次这样的注入**对应空槽的总容量；1020 是 Probe 数量，不能直接当作任意法术每次的数量。自然湖有 Initial Fill 时，只需要补剩余容量。

观察应连贯：少量水比大量水薄；中等液量有圆润圆肩和柔和圆冠；接近满槽时夸张圆冠逐步收小，水位接近墙顶。当前表面波动用 Fragment 中的 World Space 法线表现，动态合并面停止不兼容的 Vertex 起伏；稳定圆肩/圆冠仍按数量 Uniform 还原高度。不要求局部流量每帧绝对平齐。继续注水应产生真实多余数量，而不能只抬高一张不含水量的表面；水被墙阻挡，真正超过墙顶后才可能外流。

### 3. 分开检查表现与性能

低角度比较三种液体动态与稳定后的厚度、轮廓与材质；空中落水仍是带重力插值的连续外壳。走入实际积水应获得状态；在隔离场景分别检查 Fire+Poison 的局部毒爆和 Fire+Sticky 的沿燃料传播，最后再加入 Water 检查灭火，避免不同反应相互干扰。

Profiler 分别记录流动与静止阶段的 `GridLiquid.FluxSolver`、`GridLiquid.PendingDeposits`、`GridLiquid.StableRegions`、`GridLiquid.Surface.MeshRebuild` 与 GPU 时间；同时看 Active Cells、Resident Chunks、Pending Quantity Gmu、Stable Quantity Gmu。Rejected Deposits、Activity Overflows、Omitted Candidate Views 应为零，停注后队列应下降。较少计算格与较少填槽 GMU 是本次已验证的数据变化，**不代表已经测得八倍 FPS**；全游戏 GC Alloc、CPU/GPU 帧时间仍由本次场景测试确认。

本轮集中 EditMode 为 116/116，通过数量、碰撞、反应、状态路由、几何、Shader 导入及暖机零托管分配断言；随后追加初始 Bounds 的半格/满格体积检查，数量批次 17/17（其中15项为已通过用例的重测）。报告为 `liquid-volume-mapping-final.xml` 与 `liquid-initial-volume-final.xml`。正式 P7 接线审计 Failures=0，保留 Edit Mode，没有用算法测试替代参考图观感或真实帧率验收。

共享 Shader 的静水参数最终有显式关闭默认值，避免动态液体误用静水形状 UV；收尾模式隔离和 Shader 导入2/2通过，报告 `liquid-volume-shader-final.xml`。

## 9. 运动、分层与落水检查（2026-10-01 历史版本，现行规则见第十节）

### 1. 开始操作前

先退出 Play，等 Unity 编译/导入完成。沿用当前场景和已有 Cube，无需重建关卡或重新执行迁移。正式 P7 与 P7Comparison 的三个 Behavior 资产已更新；若自建世界使用其它 Profile，要在对应的 Water/Poison/Sticky Behavior 中配置 Relative Density 和流率，旧资产缺失 Density 时默认1。保持 Dynamic Surface 与 Stable Surface 都启用、引用同一个 World 和对应材料；隐藏 Surface 不等于移除 Gameplay 液体。

Inspector中的侧向最大流量为 `Maximum Side Flow Per Tick`，源格保留比例为 `Side Spread Reserve Fill`。默认参数为：Water Relative Density=1、侧流112、保留0.14；Poison Relative Density=0.9、侧流40、保留0.28；Sticky Relative Density=1.15、侧流6、保留0.55。侧流是255容量的基准参数，当前510容量会缩放成224/80/12 GMU/Tick。Density 是相对游戏配置，决定谁处于上层；流率和保留比例近似 Viscosity/聚团效果。水应该较快铺开，毒液居中，粘液缓慢成团；三者空气中的重力相同。

### 2. 四项画面验收

1. **跨页流动：** 在较大平地连续注 Water，移动相机观察流动到稳定的全过程。表面可有自然波纹和原材质的透地纹理，但不能沿4m Chunk边界出现周期性直线裂缝、整块缺面或邻页轮流消失。Renderer 正在排队时保留完整旧表面，全部完成后统一更新；它允许有限延迟，不承诺每份液量都同帧显示。
2. **毒液浮水：** 向同一小池先注 Water，等待趋稳，再注 Poison。绿色应持续位于混合格的自由面，不能因毒液份额比水多/少而反复换面。再在天然稳定湖的局部注 Poison，检查接触处也连续；`Expanded Stable Regions` 或 `Resident Expanded Sectors` 可以增加，但远处 `Stable Quantity Gmu` 仍应大于0。数量账本中的 Water 不因被盖住而删除。最薄的一层也有明确材料身份，当前实现没有逼真的混色、乳化或完整透明分层透视。
3. **流动差异：** 在三处相似平地用相同 Quantity/Radius 分别注 Water、Poison、Sticky，避免它们接触反应。比较数秒内边缘前进、聚团形态和趋稳速度；应能直接辨认水最快、粘液最慢。使用流率调节手感，不要用提高 Gameplay 分辨率弥补流速。
4. **空中体量：** 把 Water Deposit Probe 抬高到2～4m，先单次注入，再做持续注入。孤立包应圆润、连续加速，不能在某个高度周期性缩没；相连包可形成圆润水柱。落地会改变形状和占地，不能因为本来未显示的网格突然补齐而像凭空多出一摊水。注入前后记录 Pending与Total Quantity；无反应、出口或其它来源时，Pending加已入账数量应与请求一致。

### 3. 看哪些性能指标

流动与静止各记录一段 Profiler。除了 `GridLiquid.FluxSolver`，还看 `GridLiquid.Surface.Snapshot`（冻结附近数量与稀疏湖面）、`GridLiquid.Surface.MeshRebuild`、`GridLiquid.Mesh.FieldScatter`、`GridLiquid.Mesh.SurfaceNets` 以及 GPU 时间。Snapshot/Candidates 不包含在2ms Mesh页预算内，单页构建也不能被抢占；不要把2ms设置理解为整套系统的硬时间上限。

Inspector 中 `Pending New Views`、`Pending Dirty Views`、`Oldest Queued Frames` 应在停注后下降，`Omitted Candidate Views`、Rejected Deposits、Activity Overflow 应为0；活动期间关注是否一直积压。稳定湖远处没有逐格活动量，接触区的有限展开允许产生一段额外计算。检查完整游戏 GC Alloc 与 CPU/GPU 帧时间，不能用单个网格的零分配断言代替整帧结论。

本轮最终相关 EditMode 为 **135/135通过**，报告 `Temp/ElementPerformance/liquid-motion-feedback-final.xml`，包含相位体积、数量/转换、局部展开、冻结湖面、原子提交、跨页闭合与 Shader 导入。这里没有新的 Play画面/FPS/GPU认证。你可以开始制作湖盆，按本节逐项验收；反馈时说明场景、注入数量、高度、是否启用反应，以及流动/静止阶段的指标，便于区分 Solver、重建排队和 Shader 外观。

## 十、连续外壳版本的接线与验收（2026-10-01）

> 第十节记录各轮历史版本。2026-10-04起，页数超出GPU预算采用近处GPU持续更新与独立CPU缓存；本节早期“整体CPU回退”的描述已由第十一节取代。当前制作和可见性参数以第十一节为准，历史测量保留各自时间与输入。

本节取代第九节中“最上层材料赢家”的显示解释。现在使用真实Density液层和统一外壳；同密度颜色按附近数量平滑混合，较轻液体位于上层。Water/Poison/Sticky的各自GMU及反应仍保留。早期135个测试不是本次重构的验收证据，新验证结果见完整解析L4.16和执行记录。

### 1. 场景中需要保留什么

正式P7已经接线，不用再次迁移。自建的已有Grid场景退出Play后，可执行 `Tools > Grid Liquid > Upgrade Current Scene To Continuous Field (Undo)`。它添加或配置世界根对象上的 `Grid Liquid Field Surface Renderer`，连接 `GridLiquidFieldRenderProfile_Default`；三种材料继续取原来的Surface Material。旧Dynamic/Stable组件保留引用。运行时统一外壳工作后，旧Dynamic不再绘制；远处Stable湖面继续稀疏显示。升级可以Undo，工具不自动保存场景，你检查后自行保存。新建原型与制作工具会接入同一渲染Profile。

Profile中的128MiB是共享GPU Buffer预算。当前默认`Input Chunks=256`、`Views=128`、`Fine Views=96`，本机P7实际共享分配121.67MiB。输入容量和r2细显示预算均不改变Gameplay数量或0.5m格子。CPU快照是另一份内存；CPU回退按约2ms软预算在页内分段构建，全部完成后整体交换，显示可能落后。没有要求你准备新模型、纹理、Normal Map或音频。

### 2. 建湖和注水仍然按真实容量

保留Collider、非Trigger、有效环境Layer；普通Default Cube也可作为墙，角色和动态Rigidbody不作为静态支撑。薄于粗Grid的墙要考虑有效碰撞采样，建议厚度至少一个液体格。先用2×2×0.5m空槽检查量：当前4倍GMU体积配置下，理论容量8160 GMU，1020 GMU注入约八次。Pending必须清空；没有出口/反应时数量不应减少。圆冠会使中间液位更饱满，接近满格回到真实层高，不能靠无限抬高显示来掩盖容量错误。

先关闭其它初始液体来源及反应，分别检查单材料静池和坡道。再向水池注Poison，默认较轻的绿色应稳定在上部；低视角看池边应能看到较重水层的侧面。若你把两个Behavior Profile的Relative Density设成完全相同，二者共层且按数量混色，数量仍各自保留。改Density或Drag后退出再进Play，Runtime使用初始化冻结参数。

### 3. 判断平滑是否成立

当前10Hz Gameplay每Tick约100ms，显示约落后一个Tick，但两个已提交状态间每帧连续重建。检查轮廓能否连续跨格，而不只是Shader波纹在动。坡道比较相同Quantity/Radius的三种液体：水应更快，粘液更慢。Density控制上下顺序，Ground Drag控制速度衰减，Maximum Ground Speed控制上限；三者不可混为同一参数。

把Probe抬到2～4m，观察小量液体、连续注水和落地交接。相邻液量应形成有体积的液舌/液帘，离开坡面后保留横向动量；空中不施加Ground Drag。沿Chunk边界和负坐标原点观察；跨界圆肩可以伸入空邻页，不应被齐整切断。Alpha=0到1是正常插值，不是数量减少。

**晚间实际体积校准后的规则：** 连续外壳最低使用r2（0.5m Gameplay格对应0.25m显示采样），CPU回退也使用相同精度。r1曾让一层水没有Triangle，并严重缩小边缘体积，所以不再作为负载降级手段。`Fine Views`现在决定GPU能完整容纳的r2输出页数量；超过实际预算计算出的数量会整体进入CPU回退。调大该值仍受128MiB限制，不能保证增加有效容量。远处Stable湖面依然合并稀疏Patch，不需要给整个湖底建立r2输入。

**贴地液体始终使用共同连续外壳，少量也不会逐格画珠子。** 空中液体也进入统一连续场，不再按格绘制球面模板；相邻同层小量合成液舌/液帘。薄于显示采样间距的贴地层先生成代理厚层，再压回数量对应的厚度。无需为了可见性增加Gameplay水量。

`GridLiquidFieldRenderProfile_Default` 的 `Cartoon Crown Strength` 默认0.8，0.15用于体积校准。美术档先把连接的液量组成一个液团，再收拢横向面积、增加共同高度；少量尾格按自己的数量贡献覆盖率，不能把主体平均成薄纸。旧逐格四次根增厚造成的2.58/7.08倍显示体积已撤回。当前真实4×4 GPU样本：128GMU/格峰高约41.27cm、闭合体积约理论的1.195倍；32GMU/格峰高约24.09cm、约理论的1.106倍。相同2040GMU在平地、30°、60°及2×2集中分布的闭合体积为0.598～0.623m³，跨度约4.23%；理论值0.5m³。闭合积分包含最多2cm隐藏底壳，不能把它当严格物理体积守恒。高度增加来自显示面积与高度一起调整，实际填槽量仍使用GMU。顶面另有最多约3cm柔和起伏，12cm接触带内衰减。满格、大范围湖体逐渐回到实际水位。

### 4. 看新指标

在世界根对象选 `Grid Liquid Field Surface Renderer`：

- `Input Pages`、`Surface Pages`：输入数量页与输出外壳页。空邻页也可能参与输出，所以数值不同是正常的。
- `Subdivision`：CPU及GPU基础为2（0.25m显示采样）；GPU在现有Node/Cube/Index Buffer全部能容纳时升到3（约0.167m）。这是显示采样，不会改变GMU或Collider；不能单靠调高这个数解决整个游戏帧率。
- `GPU Bytes`：实际GraphicsBuffer字节数，应不超过134217728字节。模板和参数预留也计入配置估计。
- `Alpha`、`Display Lag Milliseconds`：连续插值相位与约一个Tick延迟。
- `Capacity Overflow`应为false；`CPU Fallback`为true说明当前走较慢兼容路径，应记录场景规模和页数。
- `Fallback Reason`说明缺少Compute、GPU初始化失败或r2页数超预算的具体原因。CPU分批完成前保留已显示的旧表面；`Display Lag`可能明显增加。CPU回退用于完整性和兼容性，不是大型活动湖泊的60FPS方案。
- `Capture Milliseconds`与`GC Bytes`：前者是最近一次快照CPU耗时，后者累计该Renderer的托管分配；暖机后的增量应为0，不能代替整帧GC Alloc。

Profiler重点看 `GridLiquid.Field.Capture`、`GridLiquid.Field.ShapeBounds`、`GridLiquid.Field.CpuBuildPage`、`GridLiquid.Field.Dispatch`、`GridLiquid.Field.Draw`、`GridLiquid.Terrain.SupportBake`、`GridLiquid.FluxSolver`和`GridLiquid.FireReaction`，再看GPU时间及整帧GC Alloc。当前CpuBuildPage标记是一帧的构建片段，历史版本是整页，比较时先确认工作单位。Dispatch的CPU提交时间不等于GPU执行时间。分别记录持续流动和静止窗口，再比较P50/P95；至少120个正常推进的帧，TimeScale=1、恰好一套统一Renderer，避免把Editor失焦、第一次Shader编译和初始化混入结论。


### 5. 实际制作一座湖的最短操作链

1. 在Edit Mode保留你的地形和关卡。正式P7已有世界接线；新场景先运行 `Tools > Element World > Authoring > Configure Current Scene`，再检查World、Material Catalog、Grid Profile与连续Renderer引用。工具支持Undo，不自动保存，制作结果由你决定何时保存。
2. 用Terrain/MeshCollider或Cube做真实湖底、岸壁，Collider不能是Trigger。湖岸应连续，薄墙建议厚度至少一个0.5m液体格，避免粗Solid采样漏掉。移动/改变地形后重新进Play验证，不用装饰Mesh代替Collider。
3. 运行 `Tools > Element World > Authoring > Create Water Lake`（另有Poison/Sticky菜单）。选中新建的 `Water Lake Bounds`，BoxCollider保持Trigger，Bounds与世界轴对齐，覆盖水的允许范围；它只是描述湖体积，不能充当挡水墙。`Derive Bottom From Solid`和`Sectorize By Chunk`开启，`Initial Fill`先设0.75。边界不要与别的稳定湖重叠，容量超过当前Profile时按提示缩小或分区。
4. 进Play后先关闭开局玩法说明，让TimeScale恢复1。确认Authoring的Runtime ID有效、Stable Quantity>0、Pending清空、Rejected/Overflow为0。单独远处静湖应没有逐格Active Cells；8湖诊断初始共2105280GMU，不用目测估算湖量。
5. 先检查静水的岸线/圆肩和低视角厚度，再向局部射Poison：默认绿色浮在蓝水上，水量身份仍在。等密度混色需要在对应Behavior资产把Relative Density设为相同值，然后重新进入Play；绿色与蓝色交界应平滑共层。
6. 选Lake Bounds运行 `Tools > Element World > Authoring > Create Outlet For Selected Lake`，把Receiving Cell移到湖外、真实净空的格中。Play切换Is Open检查高处排水与下游接收；无消费时源湖+接收区+Pending总量应守恒。远处Stable Quantity保留，局部展开而不是整湖全部成为活动格。
7. 最后在30°/60°实际Collider斜坡以相同注入量分别比较水、毒液、粘液，再看离边缘落水。记录Quantity、Active Cells、页数、CPU Fallback、Display Lag和流动/静止窗口P50/P95。若突然整批退CPU，先检查有效r2页预算，避免盲目增加Gameplay分辨率。

### 1. 先录正常CPU窗口

1. 打开`Window > Analysis > Profiler`，目标选择当前Play Mode，启用CPU Usage和Rendering。GPU Usage在本机Native Graphics Jobs下不支持可靠计时，先关闭它；Deep Profile、Call Stacks关闭。不要为这次录制改变Graphics Jobs或Graphics API，也不要另开场景或重做P7接线。
2. 正常进入游戏、关闭说明面板，TimeScale保持1。保持你觉得卡顿的视角与Game View分辨率；开始Record，正常操作约5秒，停止Record后保存`.data`。避免把Screenshot、暂停、Script编译或展开Inspector大量对象混到窗口中。
3. 在同一处停止施法，等待液体稳定，再记录约5秒；注明是否移动角色/镜头、新增火焰/毒液/粘液或打开说明/编辑界面。保存不同文件不保证不同历史范围，仍需核对时间戳是否重叠。
4. CPU Usage切到Timeline，分别看Main Thread的`GridLiquid.Field.Capture`、`GridLiquid.FluxSolver`、`ElementWorld.FireReaction`、CPU回退构建，以及Render Thread的`WaitForGPU`。可以暂停录制后查看，查看动作不污染已经保存的帧。

不需要一直录到几千帧。两份用户原记录实际导入各600帧，325帧重复；短而条件清楚的窗口更利于对照。关闭GPU Usage只是排除不受支持采样的干扰，仍可能存在真实GPU Compute/透明成本。

### 2. 每个指标回答不同问题

| 看什么 | 可以判断什么 | 不能据此推出什么 |
| --- | --- | --- |
| FluxSolver / Active Cells / Sleeping Cells | 活动液量搬运成本和休眠登记 | 所有Rendering都停止、整个游戏0成本 |
| Capture / Crown / PackCells / ShapeBounds | 整理显示输入、连通液团和范围的CPU成本 | GPU执行用了相同毫秒数 |
| Visible / GPU / Hybrid / Culled Pages | 当前候选、GPU近页、CPU剩余和显示筛选 | CPU页已经全部构建完成 |
| Display Lag / Hybrid Display Lag | GPU插值与CPU缓存分别落后多少 | FPS恢复即代表最新液体均显示 |
| WaitForGPU | CPU/Render Thread存在等待 | 唯一原因是空中液体或某一个Shader |
| 模块GC / 全帧GC | 热路径分配与其他系统分配 | 一个模块0B就代表整场0B |

先比较均值/调用，再看调用频率与每帧摊销，不把父子marker重复相加。Capture包含Crown、Pack和Bounds。两份原始卡顿记录Capture均值23.49/28.46ms，FluxSolver2.05/2.64ms，提示显示准备明显值得优化；GPU状态含`NotSupportedWithNativeGfxJobs`，截图1.559ms不能作完整GPU成本。

当前固定48Chunk对照Capture从29.2753到18.0368ms，减少38.39%，46080GMU、上传/Terrain/Owner Bounds签名和暖机GC0保持；这是CPU方法结果，不能直接换成FPS提升。最终28Fixture、255/255诊断包含真实GPU/CPU几何及可见性/休眠，未代替正常游戏重采样。详细数据、限制和原始文件Hash见[本轮证据](../../../docs/superpowers/validation/2026-10-04-liquid-profiler/README.md)。

### 3. 湖泊仍按数量与局部活动制作

大湖继续使用Stable Authoring与真实非Trigger湖盆Collider，多个湖共用一个世界；保持默认粗0.5mGrid。圆冠和1.8显示倍率只影响卡通外壳，槽中真实填充量仍按510GMU/格计算。先核对总Stable/Dynamic/Pending，再检查湖边局部水/毒/粘液分层与状态接触；不用全湖活动格或每格GameObject模拟天然湖。

验收同时做新命中、转头、离开返回、坡外接收与Stable岸线检查，步骤仍见第十一节。当前CPU采集优化不降低表现，也没有解决无限可见液体的零成本问题；可见CPU缓存等待、真实GPU执行、墙后来源、长时累积与Standalone60FPS仍需要进一步实测。你制作或调整关卡后自行决定何时保存，本轮开发没有自动保存、丢弃或重启P7。

## 十三、累积物质时的显示成本与验收（2026-10-04 L4.26）

这轮优化复用没有变化的连续外壳，并在CPU/GPU查询时跳过确定为空气的位置。液量、Density、反应、角色Wet/Poisoned/Sticky接触、厚度和曲面精度沿用原规则。近处新命中的优先显示及远处休眠仍使用第十一节已有机制；页缓存没有取代真实世界数据。

### 1. 制作湖泊时优先选择合适表示

- 封闭天然湖使用有效Environment Layer、非Trigger的底部/岸壁Collider及既有Water Lake/Stable Region组件，多个湖共用一个ElementWorld。继续开启Derive Bottom From Solid、Sectorize By Chunk；先用Initial Fill=0.75确认水位，再调整数量。
- 大湖的平静主体保持Stable；进水、出口、岸边反应等需要运动的局部才进入活动区。连续圆润渲染解决外壳表现，不能把“大量湖泊”都制作成一直求解、一直重建的动态水。
- 实际填槽和湖水位依GMU。卡通圆冠和Volume Scale是美术映射，不增加Gameplay数量。制作时同时记录Stable/Dynamic/Pending总量与目标槽水位，避免仅比较视觉面积。
- Poison默认比Water轻、Sticky更重；同Density共层按数量混色，各自状态与反应身份保留。修改行为/渲染配置后重新进入Play，使初始化缓存和材质绑定采用新数据。

### 2. 做一次短而完整的回归

1. 进入Play，关闭说明面板，确认TimeScale=1；停止施法观察湖面。没有运动的GPU页应继续可见，Rebuilt Surface Pages可以降到0，不能连Draw一起撤掉。
2. 近处连续施放水/火/毒/粘液，再往脚边及镜头内稍远处各发水球。检查新水可见、Wet接触与水位置相符；比较Surface Pages和Rebuilt Surface Pages，已有静止页不应因远处一个新命中全部重建。
3. 看同量水的30°/60°坡面与地面接缝、平台落水上下圆肩，以及同Density混色/不同Density分层。页换槽、材料移除和插值结束都不能留下旧形态或跳出错误颜色。
4. 转开相机后转回，离开Gameplay活动域再返回。检查总量保留、Sleeping Cells、局部唤醒和出口；Camera Frustum只决定显示，Gameplay唤醒使用已有活动源。
5. 只录固定镜头约5秒，先记液量/活动格/可见页/CPU回退/显示延迟，再看帧时间。不同数量与不同反应窗口不能当作严格优化前后A/B。

当前默认GPU硬预算128MiB，P7实际约125.67MiB；不需要为了本轮优化调整Profile。新增CPU影子缓存约10MiB，初始化一次。CPU overflow仍需分帧生成，Hybrid Display Lag要单独判断，不能因为GPU Alpha正常就认定全部可见页已完成。

### 3. 当前通过范围和实际限制

最后29 Fixture、260/260的Direct NUnit/Coroutine检查通过，包含实际GPU几何/混色/Draw参数、CPU Mesh和数量对照；不是官方Test Runner XML。固定CPU完整构建250.97→115.58ms，固定GPU提交+完成等待9.30→6.21ms；这些指标不是实际FPS。

最终正常P7四法术20组累积：42844GMU、26GPU页、240活动格，P50/P95=38.43/56.07ms，Renderer和火焰路径GC=0、TimeScale1。仍未达到稳定60FPS。可见活动范围很密集时，宽核曲面、透明绘制、反应及CPU准备继续消耗时间；远处休眠不能消除玩家眼前的工作。原始窗口、图片、最终源Hash和撤回的优化实验见[证据索引](../../../docs/superpowers/validation/2026-10-04-liquid-page-cache/README.md)。

日常Profiler录制先只开CPU Usage和Rendering，关GPU Usage、Deep Profile、Call Stacks；本机Native Graphics Jobs下完整GPU计时不支持。GPU模块的额外成本不等于已经证明的游戏卡顿原因，本轮关闭后累积成本仍存在。无需为录制改Graphics Jobs或Graphics API。需要精确GPU pass时间时应另做受控Standalone/支持工具的验证，不能拿WaitForGPU当Shader耗时。

本轮曾发生Editor原生GPU错误，用户许可重开后已恢复P7。根恢复记录现存Assets外的Backups/ElementPerformance，避免Temp在重启时被清空；最终Edit Mode/Clean，关卡未保存/丢弃，没有提交。制作完成后的关卡保存仍由你决定。

## 十四、高 ms 峰值与静止液体的显示工作（2026-10-04 L4.27）

本轮用户截图是同一帧：主线程 95.52 ms，液体采集 28.89 ms，另有呈现等待 38.06 ms。地面的水暂时不流动，仍可能因为新命中、反应、姿态和插值需要提交显示快照或重建曲面。制作湖泊时应同时看真实世界的 Active/Sleeping 和显示侧 Capture/Rebuilt Surface Pages；静止数量与静止几何是不同条件。

### 1. 本轮优化对关卡制作的影响

CPU 解码改用精确 Half 表，塑形复用 Previous/Current 的湿格并集，History 用准确到格的 bit 筛选。显示厚度、Normal、圆冠、Density、真实数量、反应和接触规则保持；无需调整水湖组件或 Render Profile。没有 Stable patch 的显示查询快跳不改变 Stable 湖水位。GPU 预算与细分精度保持，第十三节的湖盆 Collider、Stable Authoring、岸边局部唤醒流程继续适用。

同输入 48 页、46080 GMU 的采集 20.99→10.44 ms，暖机 Alloc=0，上传/Terrain/Owner Bounds 签名保持。固定方法节省约 50% 不能解释成游戏 FPS 翻倍，也不能解释成天然湖、所有密集活动区都获得同样收益。容量不足时保留完整遍历，而不是少显示一些水。

### 2. 比较正常运行与诊断窗口

日常录制保持同镜头、Game View 分辨率和 TimeScale=1，记录总量、Active/Sleeping、可见页、重建页与显示延迟；展开 LateUpdate 到 Capture 的 Crown/PackCells/ShapeBounds。出现 WaitForGPU 说明有图形等待，不能直接认定是哪一个 Shader；本机 GPU availability 含 NotSupportedWithNativeGfxJobs，完整 GPU pass 时间另需受控的支持工具验证。

本轮旧代码与 CPU 优化后的正常四法术 20 组 P50/P95 分别为 35.80/51.68 ms 与 37.79/54.70 ms，数量和反应分布不同；没有证明整体 FPS 提高。后续正常隔离运行还有更慢的窗口，保留了原始记录，波动原因尚未确认。随后冻结同一 25430 GMU/26 页：强制全 Compute 重建 P50 311.15 ms，冻结 Compute 保留绘制 16.53 ms，重复强制重建 324.10 ms。它用于定位重建成本，TimeScale=0，不能验收正常游戏帧率。

### 3. 验证范围与继续制作的边界

最后 29 Fixture、261/261 Direct NUnit/Coroutine 通过，包括坡脚、Stable、分层、History、可见性与真实 GPU/CPU 几何。线程组实验发生 3/6 失败，已完整撤回；没有通过降精度或隐藏显示完成验收。当前优化仅减少 CPU 重复显示工作，GPU 重建、长时累积与 Standalone 稳定 60 FPS 继续未验收。

湖泊数量/水位和角色接触仍按第十一、十三节核对；CPU 缓存不能替代真实世界数据。最终 EditMode/Clean、原十根状态与场景 SHA 保持，本轮没有保存、丢弃或重开关卡。[本轮证据索引](../../../docs/superpowers/validation/2026-10-04-liquid-capture-spikes/README.md)列出同输入、正常和冻结结果，主学习文档 L4.27 解释为什么减少工作以及完整 fallback 的取舍。
