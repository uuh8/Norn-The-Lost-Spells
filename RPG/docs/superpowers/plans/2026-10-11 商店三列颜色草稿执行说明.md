# 商店三列颜色草稿执行说明

用户已明确指定样板和复制的 `InventoryCanvas_商店`，本次完成现有 UI 的可撤销布局草稿。复用现有商店会话、EventBus 命令与真实资产，不新增交易或存档规则。购物车、法术效果、店主美术只提供明确占位；这些后续功能需要另行讨论。本任务直接按已指定排布执行。

## 1. 玩家体验与布局

左侧上方蓝色商品，保留真实搜索、分类、供货与购买选中；下方金棕色购买预览、实际钱包/交易反馈。中间上方绿色携带背包，使用原来的真实占格镜像与双向 ScrollRect；右边预留装备图，下方青色仓库显示真实仓库资产。右侧上方紫色详情、橙色法术预览占位、蓝灰购买设置、酒红店主信息占位，最下方加入清单（停用）、购买所选、关闭。

采用 anchor 比例布局与独立命名区域，用户可以直接调整 Image.color、RectTransform 和内部标题。商品和仓库列表使用 GridLayoutGroup + ContentSizeFitter + ScrollRect，而非手动设置一份固定长度。购买预览不给样板中的虚构数量/余额，避免占位被误解为真实交易。

## 2. 集成与文件

- `Assets/_Project/Editor/SinglePlayerShopDraftSetup.cs`：一次性 Undo authoring 工具与独立 Review，移动既有商店控件，停用复制的背包输入/表现组件。原 ShopController 常驻，Hub 和 HUD 的对象引用不变；内部 Panel 指向用户商店 Canvas。原背包排布节点与商店 DragGhost 保留但停用，便于撤销。
- `Assets/_Project/Scripts/UI/Trading/ShopController.cs`：内部 Panel 的字体初始化、可选仅展示仓库资产，成交仍走现有 Core 事件；默认配置兼容旧测试 Scene。
- `Assets/_Project/Scripts/UI/Trading/ShopBackpackView.cs`：格子大小可配置、余量文字适配紧凑镜像，容量与真实占格规则不变。
- `Assets/_Project/Tests/RunPlayMode/ShopDraftPlayModeTests.cs`：独立 Review + 内存档验证 E 正确窗口、Tab 仅背包、Esc 恢复暂停、实际购买资产与余额。必要时读取 Profiler 现有商店 marker 的稳定帧。
- `Assets/_Project/Scenes/SinglePlayer/SinglePlayer_Hub_ShopDraftReview.unity`：只保存审阅副本，不自动保存正式 Scene。
- 配置指南、单机箱庭解析（更新中）、验收记录：同步精修节点、功能边界、验证与回滚。

## 3. 资源与验证

使用用户复制 Canvas 的现有框架、美术以及商店已有控件。颜色使用 UGUI Image，文字复用 Unity Font 与现有 Runtime 中文字体。不新增模型、贴图、VFX 或外部素材依赖；参考 PNG 用于区域排布，不作为整张 UI 背景导入。

首先复制最新已保存据点，记录旧商店 E 入口与复制 Tab 的失败证据。随后应用 Review，运行实际输入和交易回归，截图检查三列与各区域是否可见、文字/按钮是否越界。仅在验证后对当前 Scene 应用一组 Undo，保持磁盘 SHA256 不变，并让用户 Ctrl+S 保存。Profiler 只声明商店 Update marker 的采样结果，不把整个 Editor 主线程说成零分配。

## 4. 回滚与调试

正式 Scene 禁止自动保存或覆盖。当前场景的一次 Undo 撤销全部作者修改；原布局仍保留停用。精修后不要重复执行 authoring 命令，它会明确拒绝已存在草稿。入口无响应检查原 ShopController GameObject 是否 active、内部 Panel 是否引用商店草稿；Tab 多开检查复制的背包控制器/Action 是否已经停用。交易异常检查现有状态区，禁止靠伪造库存或清空存档修复。
