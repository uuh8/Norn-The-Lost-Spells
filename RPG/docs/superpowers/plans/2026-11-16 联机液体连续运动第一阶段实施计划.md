# 联机液体连续运动第一阶段实施计划

用户已同意审查文档的第一阶段。背包左上整理已在上一轮交付；本阶段复用原 LiquidFluxSolver、GridLiquid Renderer 和材料数量 Owner，补齐 DS 到 Replica 的运动信息，不重建流体系统。

## 目标、范围和取舍

当前 DS 有格内 Offset/Velocity，Replica 却把 Previous 与 Current 设成同一数量、零姿态，导致跨格时跳跃。目标是同一权威 Tick 的完整搬运组能够在 Client 连续呈现，并在 F 采集、Interest 退出、Frozen、重连时正确失效。此阶段不改 10Hz 物理、GMU、反应规则、容器洒出落点语义，不增加独立粒子数量 Owner，也不承诺达到参考游戏的最终美术质量。

已有 GPU Surface Nets、速度 Warp、小水滴继续使用；没有新增用户提供贴图、模型、音效或收费插件的依赖。CPU fallback 的静态构建需要及时丢弃过期结果，但仍不等于 GPU 的连续插值质量。

## 数据与权威

数量继续通过原 Baseline/Delta、Revision、ACK、checkpoint。运动另用 WorldPageMessage Kind 8，固定容量、无数量 ACK、不得进入 checkpoint。协议版本 17 升 18，三端同时重建，保留现有字段与池化 Reset。

一份表现帧包含 World/Connection Epoch、Sequence、MaterialTick、DS SampleTime、Interval、最多32个 Chunk anchor 与128个 Cell/Material 行。每行带 Previous/Current 的 Quantity witness、Offset 和 Velocity；Quantity 仅用于验证，不可写回 Store。每 anchor 带 Generation、提交 Revision、SubscriptionEpoch、Resident。

Source 仅发布同一 Solver window 的完整搬运组。成功 Transfer/Exchange 合并组；非 Solver 写入、Stable/Pending 混入、容量溢出或与 canonical quantity 不符时排除整组，不发半份液体。逐组逐材料检查前后守恒。选择以 DS Actor 位置排序，Client Camera 不决定模拟或真实数量。

Client 要求 World/Connection/Subscription/Generation 匹配，已安装 Revision 不低于 anchor，且每行 CurrentQuantity 与最新数量事实完全一致。允许无关 Cell 推进 Revision，避免整个 Chunk 的无关变化让运动永远无法显示。真实 tombstone 可以证明零，未知/已退出 Interest 的 Chunk 不能假定为空。完整校验后原子发布；坏页、高 Sequence、超时均不推进已接受水位，也不令数量世界 Faulted。

## 时间、延迟与生命周期

DS 与 Client 使用现有 NetworkTime.time 传入纯接口；ElementField 不引用 Mirror。核对本地Mirror源码：Client的该值是已有SnapshotInterpolation的localTimelineScaled，带动态buffer，并非无延迟服务器now。Alpha = clamp((playbackTime - SampleTime) / Interval)，本功能不再额外增加一整 Tick 的 jitter buffer。未来/过期窗口有界等待或降级，不能据此声称零网络延迟。Renderer Capture 冻结窗口身份与 Interval，不因重复 Capture 重新计时。若静态终点已经画出，迟到窗口不能倒播 Previous；新连续窗口才恢复插值。

Replica 的 SimulationSuspended 永远为真是禁止本地模拟的安全边界，不能作为插值暂停条件。单独传入真实 Frozen、失联、ResearchPaused、退出状态；冻结保持相位，恢复不积累追赶债务。新数量安装使 witness 失效时立即回到实际数量快照，并取消过期 CPU 构建，避免采集后残影。

## 明确预算

原数量18,000B/s预算不变，先发数量页。运动每 peer 独立96KiB/s、12KiB burst、每60Hz Pump最多4页，记入72B framing allowance。每页最多160 words/900B，完整最大1607 words，最多11页。超过预算时合并到最新完整窗口，允许平滑质量下降，不消耗数量发送的应用层预算或增长无界队列。两者仍共享可靠Transport，弱网下的实际队列竞争需要单独验证，不能将独立应用层预算称为物理隔离。记录实际发送字节、接受/丢弃窗口、时间及容量拒绝原因。

## 文件责任与实施顺序

1. Core `WorldLiquidMotionContracts/Codec/Assembler`：固定缓冲、Half姿态、严格解码、两阶段接受水位；先行为 RED 再实现。
2. ElementField `LiquidTransportHistory/LiquidFluxSolver/LiquidWorldRuntime` 与 `WorldLiquidMotionSource`：限定 Solver 写入域、组捕获与 canonical witness；绑定由 `OnlineMaterialWorldBinding` 提供。
3. ElementField `WorldReplicaLiquidReadModel/WorldReplicaStore`：只读事实查询、原子运动窗口、冻结与数量失效；Rendering `GridLiquidFieldFrame/SurfaceRenderer`：独立播放时钟、晚帧和 fallback 处理。
4. Networking `WorldPageCodec`、Shared `world.proto/ProtocolCompatibility`：Kind8形状、协议生成、兼容与Reset回归。
5. Multiplayer `WorldLiquidMotionReplication`、Coordinator partial、NetworkChannel 与 OnlineWorldBootstrap：认证身份、整组选取、分页、限流、数量提交后捕获、安装后发布、清理。
6. Editor集中 Refresh/编译/测试，真实 GPU readback 与相同输入对照，再构建 Client/DS 并发布本地版本。服务操作只在核实 PID/启动时间/路径及无活动用户游戏后执行；MySQL 不重置。

## 验证与交付 Gate

- Core：完整往返、负坐标边界、容量、非法浮点、页乱序/重复/损坏/超时、高Sequence拒绝不毒化水位、Connection reset。
- Source：offset-only、完整跨Chunk两端、外部收取/投放污染、Stable混量、overflow、旧量快照、守恒。
- Replica/Renderer：Current witness、真实 tombstone与未知区别、F部分/全部收取、Interest退出、Frozen/恢复、迟到不倒播、捕获不重置 Alpha、CPU过期结果不复活。
- 集成：真实Codec→页Assembler→Store/Sink→Renderer；原数量协议、权限、checkpoint、Reset不回归。
- 同输入比较地面水流、台阶落水、高处落团、F收取；记录来源时钟、安装/Capture/绘制、fallback、带宽及耗时。只报告实际测到的范围，主观液体感仍由用户试玩验收。
- 重建Client/DS，重新导出ContentManifest与GameplayHash；业务服使用同一协议。保护正式Scene/Prefab/SO及全局Build列表，新增脚本.meta由Unity生成。

## Debug 与回滚

先按 Source有效组→发送窗口→完整组装→anchor/witness验证→Capture窗口→GPU实际输出定位。运动拒绝只能降级为已安装数量快照，不能改变数量版本或启动新数量Owner。必要时可关闭可选运动能力回到原数量渲染；保留失败证据，不能用旧测试通过覆盖本次失败。
