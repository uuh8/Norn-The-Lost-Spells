## 1. 玩家成果与范围

产出法术按真正执行的指令扣具体实例一次。修正与多重施法按入局资格扣一次，最后一次从 1 到 0 仍可在本局使用。Trigger 根层成功时预扣全部未来有限次数，未来层仍从原杖支付 Mana，未触发不退款；同一层预算只能尝试一次。冻结本次所有输出命令，编辑程序或修改 SO 不改变飞行中的 Payload。M4 正式出发、终局损失和 PendingRaid 持久化仍按对应 Task 接入。

## 2. 实现与取舍

Skills 在原解释器分支旁记录成功执行的索引、Kind、命令编号和 Payload 范围；诊断 Trace 继续独立。Run 用记录建立不可变执行树，并把省略空槽的 Payload 映射回实例身份。全树限制深度 16、产出 64，拒绝非法 Prefab、Kind、Mana 或没有实际产出的配置。

库存写入口加入内部候选提交策略：准备完整候选表时检查首次安装资格，验证失败不会移动或扣资格。BeginRaid 整笔处理已安装且携带的卡；EndRaid 清除资格。耗尽实例保留为 0 次，M4 负责终局清算，资格不写入 Profile。

根施法采用准备/提交事务：验证并锁定库存，生成成功后提交候选次数与原杖 Mana/CD；异常或提交失败清理已生成对象和 Coroutine，解除锁定。相比提前扣费再退款，此方式避免恢复错误版本的库存。未来层不再读取程序，只消费一枚层预算；失败尝试也消耗该预算，已预扣次数不返还。销毁未触发的父投射物会取消对应未执行子树，避免预算滞留。

Core 只定义 struct EventBus 请求/结果；Run 持有资源与只读计划；Character 生成和清理 Unity 对象；Combat 只增加通用生命周期通知；UI 读取资格并通过 Core 请求测试生命周期。保持原有 P7/P8、Warrior/Archer、Boss 和旧 Mana 路径。
