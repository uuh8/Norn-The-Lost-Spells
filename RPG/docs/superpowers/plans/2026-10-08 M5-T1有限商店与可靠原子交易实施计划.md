# M5-T1：有限商店与可靠原子交易实施计划

> 执行方式：沿用 rpg-combat-and-spell-workflow 和 superpowers:executing-plans，在原工作区自行执行；用户本轮授权按原计划继续。不使用 SubAgent、worktree、自动提交，不保存或覆盖用户当前场景。

**目标：** 带回的实际物资能够兑换据点数字货币，再购买有限供货的法术、法杖、空容器和元素；整笔交易写盘成功后才发布结果。

**架构：** Core 放意图、拒绝原因和结果 struct；Run 放 SO 配置、商店状态、进展与候选 Profile 事务；UI 只读投影并发命令。沿用 ItemOwnershipStore/ContainerComposition/ProfileSaveRepository，不新增反向 Assembly 依赖。

**权威：** 唯一总案 R18、第8/9/10节、M5-T1、D07；M4已交付，用户试玩仍待验。贴图由用户寻找；已确认仓库/背包样板位于 Assets/_Project/Art/UI/样板图，本 Task 使用可替换纯色 UGUI，不生成贴图。完整仓库/背包重排留后续据点整合，图片数值不成为规则。

## 1. 玩家结果、推荐配置与边界

玩家直接进入 TradeSandbox，看到钱包、商品有限库存、收购余额和自己的可交易物。买实体可选择仓库或背包；买元素选择兼容容器；卖材料与卖空瓶壳明确分开。出售混样按相同比例实际扣除各组分，逐组分计价；不提供免费分离材料。余额、空间、货源、预算、资产资格或保存任一失败，原钱包、库存和材料不变。重复请求不会再次成交。

D07推荐实现（保留为集中审阅项）：非实物数字货币，只有据点可交易；成功撤离且本局发生真实采集或有效敌人死亡才累加经济进展。补货阈值由SO配置，初始每1次有效成功冒险重置至配置上限，失败/空跑/重开窗口/重启不增加进展。进展先随结算可靠保存，商店同步只消费已经保存的进展；不能把开店当成刷新来源。所有价格、初始货币和预算是 Sandbox建议值，非已确认平衡。

实体出售只处理指定实例，装有程序的法杖、非空容器、含子物品的背包拒绝整壳出售，提示先卸下/单独卖材料；免费基础本体不可直接变现，来源标记随保存和迁移保留。自产材料不建立假身份，仍受相同材料价格和有限收购预算。有限卡按剩余次数比例折价，无限卡由对应价格项处理；样板价格不承诺最终经济合理。

## 2. 事务、保存与兼容

事务按范围/版本/请求检查→构造独立候选→检查全笔库存与材料→计算整数货币且检查溢出→写候选存档→切换权威内存→发布收据。使用库存版本和商店版本拒绝旧请求，最近请求收据支持重复通知；旧版本请求拒绝，不能重放获利。

Schema5增加商店库存/预算/进展游标、可靠交易收据与累计经济进展。1—4向前读取，尚无商店的档不凭空补钱；未知版本、损坏字段拒绝。出发回滚快照、失败恢复、免费补给、成功/失败结算必须保留钱包与商店，防止只接交易后下一次冒险又重置。当前Profile.Currency只读且Adopt不复制钱包，需要一并补齐，不能只修改UI数字。

材料交易期间不接受在途容器/待提交施法资源。候选与原Profile组分必须独立，写盘失败不得已扣量。UI每次明确离散操作提交，Update仅检查版本/状态，不每帧创建列表/字符串。Shop占独立Pause Reason，与库存暂停相互独立。
