# 物品定义与 F 附近拾取及背包拖拽体验实施计划

> 阶段：M6-T1，据点背包专项；状态：已实现并完成自动验证/当前Scene单Undo接线，406 EditMode/27 PlayMode通过，待用户自行保存与I01–I08人工Gate。本文后续保留设计时的证据与选择，最终交付证据见执行记录和验收文档。
> 执行方式：当前工作区直接实施，使用 executing-plans；不使用 SubAgent，不创建 worktree，不自动 Git commit。依照项目 AGENTS.md，仅维护这一份中文计划，不另建 spec。

**Goal：** 拖住物品靠近背包可视边缘时自动滚动，三杖始终展开，并用用户现有草药、容器、食物模型打通 F 提示 → 真实拾取 → 多形状排布 → 满包决策 → 原实例丢弃/再拾取的循环。

**Architecture：** 沿用 Game.Run 的 ItemDefinition、ItemOwnershipStore、WorldItemPickup 和 NearbyPickupController，不建立第二套库存。Game.Character 解释 F 输入，Game.Run 裁定资产迁移和距离，Game.Core EventBus 向 Game.UI 发布焦点和结果，Game.UI 展示 Billboard、拖拽和滚动。场景初始物品生成与持久化必须有稳定身份，防止反复入据点产生额外资产。

**Tech Stack：** Unity 6.3 / URP 17.3 / C# / ScriptableObject / UGUI ScrollRect / Input System / EventBus / JsonUtility / Unity Test Runner / ProfilerMarker。

**需求依据：** 用户本轮三条要求；此前已确认的 8×8普通背包、独立12格法术专区、七道具引用4–9/0、三法杖1–3、容器左键撒出/E采集/G投掷，以及独立P7/P8练习规则。上层策划仍以《2026-10-07 Norn单机箱庭完整游戏策划案与开发计划》为准。

### 1.3 三个方案与取舍

1. **推荐：扩展现有定义、唯一实例和事务链。** 配置占格，包装现有模型；所有成功拾取移动原实例。成本主要是 Authoring、输入与表现接线，已有存仓、交易和次数规则能够复用。
2. 用物品名字与数量建立另一份背包清单：上线快，但与现有形状/容器组分/法术次数冲突，易产生两个所有者和不同系统中的数量不一致，排除。
3. 每类物品都建独立管理器和拾取逻辑：可定制，但本轮18件素材不需要18条业务路径；重复距离/空间/持久化校验，后续错误更难定位，排除。

### 1.4 本计划需要确认的默认值

- **按键：F改为附近物品拾取，移除正式统一手持栏的F轮换；容器用4–0选择。** E继续站点交互/采集，G继续投掷，J/K原固体操作保持，1–3、Tab、移动/镜头保持。旧无统一手持栏的独立容器 Sandbox 可继续保留原F轮换；P7/P8已有教学操作不作无关改写。

## 2. 拖拽自动滚动与三杖展示

### 2.1 自动滚动的玩家结果与计算

只在有效库存物品拖拽期间启用。鼠标进入普通背包实际 Viewport 内的边缘带，上/下与左/右分别滚动，角落允许两轴同时滚动。默认边缘带约一格宽，且不大于 Viewport相应轴长度的四分之一；速度随靠近边缘逐渐增大，最大约360个UI Local Space单位/秒，可在Inspector调整。

读取 `_lastPointer`，用 RectTransformUtility 转成 Viewport的 Local Space，避免 Canvas缩放后把屏幕像素当局部单位。采用 Time.unscaledDeltaTime，因为打开背包通过暂停协调器将 Time.timeScale置0。即使鼠标静止，LateUpdate也推进 ScrollRect；滚动后重新计算当前格、抓取偏移和形状预览，最终松手使用当前 Content位置。

Content未超出的一轴不滚动；归一化值保持0–1，取消/松手/关闭/失焦停止，退出背包Viewport停止。Scrollbar仍可手工操作；本批不覆盖用户自设 Cell Size。道具快捷引用拖拽不伪装成移动库存占格；附近真实物品拖进包支持自动滚动。Cache ScrollRect与Viewport，不在热路径 Find、LINQ或new；独立Marker测量。

### 2.2 法杖始终展开

删除 Toggle/_expanded/Fold按钮和PersistentListener，旧Scene中的Fold由有Undo的增量工具删除。程序根始终可见；属性继续显示Mana x/x、法术槽x/x、冷却、BaseDraws、预估蓝耗与程序内保护数量。三个程序各自保持自己的OwnerId，拖拽目标不能因选中另一个法杖改变。

保留用户每个法杖区域的外框；不足时滚动内容，不缩小全部法术格来塞满。十二个程序格宽度超过中栏时继续横向ScrollRect；三杖始终展开与滚动查看全部内容兼容。移除Fold不移除程序容量或法术排序逻辑。

## 3. 具体Item定义、素材依赖与Authoring

### 3.1 共享规则与实例状态

ItemDefinition负责稳定ContentId、名称、分类、Icon、WorldModel、ShapeWidth/Height、OccupiedCells、MaxStack及已有容器/法术规则。RuntimeItemState保存唯一InstanceId和动态状态，例如混合材料组分、有限法术次数；位置仍由ItemOwnershipStore唯一维护。

模型看起来多大不决定占几格。Shape是网格设计数据；矩形列出全部格，L形只列实际占格，允许其他物品放进空洞。保持R旋转90°与Shift指定单份逻辑。内容键使用 `item.food.apple` 等稳定键，不用中文名或Unity GetInstanceID；同名物品可以有不同实例状态。

## 4. F拾取、满包与世界身份

### 4.1 Runtime链与权限

1. Scene已投放的SpawnPoint等待正确Session初始化后，注册一份WorldItem资产和代理。不会在OnEnable反复给背包新增物品。
2. NearbyPickupController以有限频率扫描已注册代理（建议10Hz），选同Scene、当前InventoryId、启用且Reach内的最近物品，平距用稳定ID打破并列；变更时发Core焦点事件。
3. Game.UI共享世界空间提示跟随焦点物品，显示“F 拾取 · 名称”，使用现有WorldSpaceLabelBillboard在最终镜头更新后正向面对Camera。打开任何模态UI、离开范围、拾取成功、销毁/转场或失去焦点时隐藏；不把每个物品永久挂一份Update扫描器。
4. Character的F输入重新验证距离、Session、暂停/冻结及活动状态，调用已有自动拾取。E不再同时拾取普通Item；站点和采集不受影响。
5. 普通Item尝试真实格子/旋转和相容Stack，Spell先专区。成功时迁移原InstanceId，再隐藏/销毁世界代理，刷新附近列表与背包；失败不提前销毁物件，不改变版本/数量。
6. 只有空间/形状容量不足或未装备可用背包等“需要排布”的失败打开Tab背包并选中该附近项。存档写失败、事务Busy、距离过远等给相应失败信息，不都冒充满包。
7. 打开背包后可先丢弃、移位、旋转，再从附近列表拖入该真实物品。附近列表是WorldItem的只读投影，不能创建第二份副本；执行时再校验Reach，即使列表曾经显示也不能远程拾取。

F默认一次按下取一件最近物品，不新增未要求的批量全捡/长按连捡；提示先共享单目标，不同时为大量物品遮挡画面。后续若要原神式多条可切换列表，可以在此焦点机制上扩展。

### 4.2 防重复生成、保存与丢弃

推荐为Hub手工投放增加稳定Spawn记录：SceneKey+SpawnId对应原InstanceId，首次创建后记账。已在背包/仓库/程序/专区的物品不再生成地面代理；已经卖出或消失的物品也不能因为原InstanceId不存在就再次发放。重复ID直接拒绝并报告Authoring错误。

新增少量Hub地面资产记录保存SceneKey、InstanceId、位置和旋转，用于重建同一件资产的模型代理，不保存Scene本身、敌人、元素世界或箱庭续玩。已有Schema7地面项没有Pose时保留旧安全Fallback，不能为新字段迁移丢档；Schema1–7迁移生成空记录，未知Schema拒绝且保留原文件。新格式拟Schema8；Spawn记录与资产采用同一候选Profile和可靠写盘，失败不发布半份状态。

ProfileAssetSnapshot、Adopt以及交易/出发/结算候选复制都必须携带这些记录；仅改SaveDto会在交易或转场后丢失一次性标记。记录内不能缓存可写数组共享给候选。重复返回Hub后按真实位置/所有权重建一个代理，不能在持久Session上留下旧Scene对象。

副本新掉落和P7/P8独立练习分别使用原有Run作用域，不写Hub一次性投放账；本批不增加正式探索场景，也不改敌人掉落内容。新增可重置ItemPickupSandbox仅使用隔离目录，不读写用户正式Profile；默认示例物品放这里，正式据点不自动投放18件免费物资。用户通过教程可自行摆放正式物品。

丢弃草药/食物/容器时使用Definition的WorldModel，位置在玩家前方，实例状态保持；没有WorldModel（例如现有法术）复用安全Fallback。世界代理负责形体表现，原唯一身份/次数/组分仍在Store。丢弃后离开距离、再靠近、拾回同一个实例均须测试。

## 7. Debug与回滚

- 拖到边缘不滚：先查IsDragging/Viewport范围与Overflow，再看unscaledDeltaTime和是否仍被旧LateUpdate的early return跳过；不能用解除游戏暂停来补救。
- 滚动后落错格：比较滚动前后Content坐标、Pointer Local Space和_grab；不能直接修改Store坐标来掩盖屏幕/局部空间混用。
- F同时换瓶：检查HeldItemInput与MaterialCollection两条旧F绑定的enabled状态；别只改提示文案。
- 提示可见但拾取无效：先看Catalog/Spawn注册、InventoryId和Scene，再看Reach/冻结/版本/形状失败；不能因失败就Destroy地面物品。
- 满包物品消失/重复：检查WorldItem是否只在事务成功后隐藏、是否独占代理，Spawn记录是否跟Profile候选一起可靠提交。
- 模型粉色/不见：独立检查源Shader/Material、Mesh、Bounds/Scale与LOD，记录实际报错；不把外观问题改成免费库存入包。
- 当前Scene配置用Undo回退；源Prefab保持原样，新定义/包装资产独立。Schema8前备份测试档，生产迁移不能删除原文件或用重置档“解决”；不能把新格式存档交给只支持Schema7的旧代码并声称可逆。
- 回滚只撤本轮改动，保留此前用户UI、外部地图和已有系统。测试失败记录症状→证据→排除→根因→修复→回归/剩余边界，不标记阶段完成直到对应证据与人工Gate真实成立。
