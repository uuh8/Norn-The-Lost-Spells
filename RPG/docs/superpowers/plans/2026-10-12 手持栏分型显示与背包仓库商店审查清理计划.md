**目标：** 接入作者已经精修的十槽手持栏；验证并修正背包、仓库、商店现有功能，删除有证据证明已无消费者的遗留设计。右侧“物品详细”保持当前占位，本轮不开发新功能。

**Architecture：** 改动优先留在 Game.UI，仍从 Game.Run 只读快照获取资产、钱包、手持状态。交互继续通过 Game.Core EventBus 提交意图，库存和交易服务保持权威。确有测试证明的业务错误才修改对应 Game.Run 服务，不增加跨模块直接依赖。

## 1. 当前证据与显示规则

2026-10-12 只读检查发现 HeldItemHud.Start 强制读取每格 Title/Value，Update 强制读取 Selection/Mana/Cooldown；作者新版前三格只有 Icon、Mana、Cooldown，后七格只有 Icon、Title、Value。因此不能继续要求十个槽共享全部节点。旧 HUD 还把所有道具的 Value 当成容器储量，没有数量显示。商店 RefreshDetails 强制访问两种出售按钮；作者删除旧节点后也需要正常运行。ShopController 仍存在旧数量框、容器 Dropdown、入包 Toggle 与只读背包镜像路径，是否删除必须通过消费者核对，不能只按文件名称判断。

本轮玩家看到的规则：

- **1–3：法杖槽。** 只显示图标、Mana 与 Cooldown。已存在的标题或数值节点可以继续接线；作者已经删除的节点不再补回。空槽清图标与条，切换手持时高亮对应槽。
- **4–0：道具槽。** 不显示 Mana/Cooldown。Value 显示绑定物品的真实数量；容器额外显示 `已装量/容量`，例如两行 `1`、`12/150`。当前容器不能堆叠，所以每个容器数量为 1，容量属于该具体实例，不能把所有同名瓶子的材料混成一个数字。空位不显示旧物品数值。
- 已有快捷绑定仍指向具体实例，不因本轮展示变更移动库存。若现有规则允许某种道具同格堆叠，数量仅计该实例所在的真实同格 stack，不统计整个背包的同名物品。不增加新道具种类或使用能力。
- 高亮、图标与数字使用作者现有 RectTransform 和 Image；保留 Frame、贴图、颜色、间距。不会重生成十格布局。

选择分型刷新而非为每格补回隐藏旧节点，是因为 UI 的信息结构已经不同。把数量与容量分开可避免“有两个瓶子”和“瓶中有多少液体”混淆；只读展示也避免 HUD 成为另一份库存状态。

## 3. 清理判定与布局保护

清理前生成可核对的清单：脚本 GUID、Scene/Prefab 引用、运行时组件、Editor 工具入口、测试消费者。确认只服务已退出的旧 UI、且正式入口无消费者时，才删除旧脚本及其 `.meta` 或移除对应组件/节点。二进制 Scene 由 Unity SerializedObject 检查，不能仅用 rg 的无命中当作无引用证据。

重点核对：旧商店只读 ShopBackpackView/ShopInventorySelection 与旧 Quantity/Container Dropdown/ToBackpack 分支；旧自动布局工具的重套入口；已由 WarehouseCatalogGridView/NearbyItemGridView 替代的列表/平铺 fallback；重复的钱包写入和已断开的按钮/listener。仍有其他场景或可执行工具消费者的部分，只限制旧入口或修复兼容性，不盲删。Warrior/Archer、SampleScene 的旧法杖原型和保留的基础设施不因这次 UI 清理删除。

**DragGhost 保留。** 它是拖动中的物品形状与抓取位置预览，Editor 默认隐藏不代表无用。只清重复或孤立的 Ghost，不删除控制器实际引用的对象。选择框、落格预览、滚动条和 RectMask2D 也不是冗余。用户说的拖尾按实际残留状态检查：结束拖动、取消、关闭、禁用后不得留下 Ghost/预览/弹层，不新增视觉效果。

正式 Scene 修改使用单组 Undo，只做增量接线/删除经过审计的遗留节点；不改用户的背景图、区域比例、坐标、尺寸、Frame 或字体素材。先从最新已保存 Hub 复制隔离 Review，设其为 Active Scene 后再创建对象；只保存 Review。禁止同时加载三张正式地图，禁止全局 Canvas.ForceUpdateCanvases 导致正式 UI 重排。P7/P8 只单独检查对应已有 HUD 接线，不重做地图。
