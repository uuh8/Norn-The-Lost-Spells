# 联机普通掉落拾取根因排查与修复计划

本轮继续执行用户已授权的排查、修复和自动回归；实际游玩由用户验收。不提交或推送，不覆盖旧证据，不操作用户资产。

## 问题和已有证据

- 用户确认问题发生在联机副本，单机尚未测试。普通掉落物 F 拾取、附近网格拖入背包均失败；此前还反馈施法后 Busy 长时间不恢复。
- 11 月 15 日修复了空 Trigger 子 Scope 的 Reservation 泄漏，但截图 Rapid 配置没有 Trigger，不能把这项修复认作原问题唯一根因。
- 旧 Native 回归主要覆盖自丢旧实例和直接 UI 回调；没有充分覆盖新生成掉落实例、真实 Mouse 经 InputSystemUIInputModule 派发到 Nearby→背包的整条路径。
- 当前源码中 DS 使用角色根 Transform 的实时位置；超距返回 NotOwned，不是 Busy。新物品 Revision 在归属迁移前准备，尚未证实 Admission 顺序有错。保留这两项被排除的假设，避免重复猜测。

## 本轮步骤

1. 保留当前 dirty files，读取当前 Source、Scene/Prefab 装配、既有计划和最新收据边界；不根据截图替用户猜测模式。
2. 使用正式 Catalog、新掉落实例、Ground Source、WorldItemPickup 和 CombatPresentationScope 构造可控 PlayMode 回归：原 F 和真实鼠标 down/move/up。捕获命令身份、版本、WorldOwner、收据及最终归属，不只检查 UI 回调。
3. 补上会影响真实联机场景的并发状态：施法后的 Owner 快照替换、附近列表刷新、长时间票据与限流。先观察失败断言，再修改对应产品边界，保留 RED 证据。
4. 实现最小修复。保留 DS 权威、唯一物品身份、版本/幂等/Reservation 和失败不改资产的约束；不通过取消安全门或超时补发新物品掩盖问题。
5. 运行针对性 EditMode/PlayMode；必要时构建 Client/DS 并用隔离测试 Schema 完成真实 Wire 验证。只有当前实际执行通过才能报告通过。
6. 更新中文开发解析，记录症状→证据→根因→方案→验证及未复现部分。交付明确区分已修复缺陷与尚未归因的现场。

## 文件和责任

- 主 Agent：产品源码、Editor、测试调度、构建/服务/Git、计划/解析/证据。
- 子 Agent：只读审核；一名子 Agent 仅拥有 `OnlineSharedInventoryPlayModeTests.cs` 及同 fixture 的 GroundPickup partial 测试文件，不操作 Editor 或服务。
- 相关产品入口：`NearbyPickupController`、`NearbyPickupInput`、`WorldItemPickup`、`OnlineGroundItemPresentation`、`SinglePlayerInventoryController`、`InventoryNetworkChannel`、`OnlineCastDriver`、`OnlineGroundItemWorld`、`OnlineOwnedWorkspace`。

## 保护与 Debug

- Editor 先 inspect-safety；不保存用户 DirtyAssets、不覆盖正式 Scene 或全局 Build Scene List。
- 不改 Dev/Test 数据隔离，不结束按名称匹配的进程，不使用用户账号制造失败案例。
- 未知结果只允许原 CommandId 的幂等确认；不能把超时认作失败后重新发放或重复转移。
- 若自动化无法重现现场，明确给出已经排除和仍缺少的证据，不能用累计通过数代替根因。
