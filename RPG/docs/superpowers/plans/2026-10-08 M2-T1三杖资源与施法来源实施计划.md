## 3. 状态、只读投影、命令与提交边界

### 固定参数和实例状态

固定法杖配置（`WandDefinition : ScriptableObject`）只保存 MaxMana、ManaRegenPerSecond、CastCooldown、ProgramCapacity、BaseDraws；配置全为有限值，容量/抽取为正，恢复/冷却非负。规则冻结在目录初始化时，Runtime 不反复读 Inspector 可变字段。

每根实例资源（`WandRuntimeState` 普通 C# 对象）保存 WandInstanceId、固定值快照、CurrentMana、CooldownRemaining。由 `WandLoadoutService` 以原实例 ID 保留对象；装备位只保存引用/ID，选择只换 SelectedWandId。服务保留同会话暂存的资源状态，只有当前携带的至多三根参与 Tick；仓库存放项不进入携带恢复循环。重新装回旧 ID 沿用已有状态。

服务对外的只读接口（`IWandLoadoutReadOnly`）提供选择、装备位、资源快照和程序查询；不暴露 TrySpend 或可写字典。持续恢复遍历预分配三项引用；dt<=0/非有限 dt 不更新。不通过给每个装备对象新建 ManaComponent 实现状态切换。

### 程序投影与快照

程序投影（`WandProgramProjection`）按实际程序容量构造 SpellDefinition 槽和对应实例 ID，未安装位置保留 null。它由权威归属重建，仅在该杖程序实际变化时替换；同时递增该杖 ProgramRevision，避免无关库存变更令排队失效。

一次输入的程序快照（`WandProgramSnapshot` readonly 数据）引用不可变的投影、源杖 ID、ProgramRevision、BaseDraws。旧投影在排队或 Payload 持有期间不能被复用覆盖；可在离散程序编辑时创建新数组，不能为节省分配改写已飞行法术读取的数组。

### Core 事件草案

以下均为 **计划新增接口**，不是当前生产 API。Core 只含原始数据，不含 Run/Skills 类型。

```csharp
// 所有事件均为 struct : IGameEvent，订阅/解绑沿用 OnEnable/OnDisable。
// WandSelectionRequestedEvent：InventoryId、RequestId、SlotIndex（0..2）。
// WandResourceRequestedEvent：InventoryId、SourceWandId、RequestId、
//                           ProgramRevision、ManaCost、IsRootCast。
// WandResourceResultEvent：相同范围/请求/来源，Success、Reason、CurrentMana、CooldownRemaining。
// WandStateChangedEvent：范围、源杖、装备位、Selected、CurrentMana、MaxMana、Cooldown、ResourceVersion。
```

选择和支付为独立命令。支付请求来自同会话唯一 Adapter，RequestId 单调递增；服务保留最近请求和收据，同一 ID 重复只回传旧收据，更旧请求拒绝，不重复扣费。不同会话/无接收者/已销毁来源/NaN 或负支付拒绝。SourceWandId 不从 SelectedWandId 推算。

Character Adapter 在发布前记录当前请求并清除等待结果标记；同步 EventBus 结果必须匹配范围、来源和请求。没有匹配反馈就是失败，不能静默当作免费批准；支付入口不引入全局可写静态 ServiceLocator。

计划公开只读接口如下。`WandStateSnapshot` 与接口放在 `IWandLoadoutReadOnly.cs`，为 readonly struct，包含实例 ID、装备位、Mana/上限/恢复速度、冷却余量/总时长及选择标记；`WandProgramSnapshot` 与投影放在 `WandProgramProjection.cs`，为 readonly struct，包含 SourceWandId、ProgramRevision、BaseDraws 和不可变 Program 引用。

```csharp
public interface IWandLoadoutReadOnly
{
    string InventoryId { get; }
    string SelectedWandId { get; }
    uint ResourceVersion { get; }
    bool TryGetSlot(int slotIndex, out WandStateSnapshot snapshot);
    bool TryGetState(string wandInstanceId, out WandStateSnapshot snapshot);
    bool TryGetProgram(string wandInstanceId, out WandProgramSnapshot snapshot);
}
```

服务构造签名规划为 `WandLoadoutService(SinglePlayerProfile profile, ItemCatalogIndex catalog, string inventoryId)`；其写入口为 `SyncInventory()`、`Tick(float deltaTime)`、`TrySelectSlot(int slotIndex)` 和 `WandResourceResultEvent TryCommit(in WandResourceRequestedEvent request)`。这些写方法仅由同 Assembly 的 Session 调用，外部只获得上述接口。

根/子层结果码（`OwnedWandFailureReason`）放在 `Core/Events/WandResourceResultEvent.cs`，计划含 None、InvalidRequest、WrongSession、UnknownSource、NotCarried、StaleProgram、Cooldown、InsufficientMana、NoReceiver；它不引用上层类型。ResourceVersion 与库存 Version 独立，恢复 Mana 不应不断触发整备格子重建。

根施法在真实出手时验证源仍被携带、程序版本有效、冷却为零、Mana 足够，再一起修改来源 Mana/冷却。Payload 使用捕获的来源会话与杖 ID，不检查后来编辑的程序版本，不重开根冷却；资源会话已结束时拒绝。当前层非法/无可提交产出时不得扣新模式资源，先校验再提交；生产创建失败的完整次数/材料事务在 M2-T2/M3 联合接入。

```text
玩家点击 → 锁瞄准＋来源 ID/不可变程序 → 一份 pending 请求
  → FSM 检查来源资源/冷却 → 锁 active → 进入原施法动画
  → 出手阈值 → OwnedWandCastAdapter → SpellCaster 显式来源入口
  → 纯估算/产出预检 → Core 资源请求 → Run 核对并提交来源资源
  → 既有求值/生成 → Projectile 生命周期
  → 命中/计时/延迟/分裂 → 同一来源上下文 → 对应杖支付下一层

数字键 → Core 选择请求 → Run 换选择 ID → UI 只读刷新
每帧 → Run.Tick(deltaTime) 至多三根 → UI fillAmount / 缓存数字引用
```

## 7. Review Focus、Debug 与回滚

五个重点都对应上文测试：

1. 起手/出手/飞行的三个时点遇到切杖或卡片编辑：明确 pending/active/飞行快照边界，拒绝排队阶段失效，不改飞行快照。

5. 频繁开关/恢复数字 HUD：不要把“仅值变化才格式化”当零 GC，native Font/代理/输入订阅应在 Scene 结束释放。
