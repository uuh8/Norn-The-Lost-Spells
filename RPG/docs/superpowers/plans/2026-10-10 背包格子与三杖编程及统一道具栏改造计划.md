**目标**：以用户自行重排的背包界面为基础，完成左侧真实格子背包、附近物品和金币，中间三根法杖的独立程序面板，以及与游戏左上角 HUD 一致的六个道具快捷位。

## 1. 确认范围、当前证据与审阅重点

用户已经确认：只完善背包的左侧与中间、对应左上 HUD；1–3 是法杖，4–9 是配置后的道具；右侧物品详情之后另行讨论。本轮不改商店、仓库的功能与排布，不改地图区域、传送规则、移动/跳跃/冲刺/镜头参数，也不弱化 Warrior/Archer 保留能力。

本次源码核对发现，真实占格、非矩形形状、旋转、堆叠和金币钱包已有实现。当前不足主要在展示与接线：工具行是自动列出背包中的材料/容器，没有六个手动快捷绑定；法杖只显示所选一根的程序；背包和仓库共享展示控制，旧 Arrange 会主动重写 RectTransform。正式常规背包定义目前为 4×4，基础补缺背包为 2×2；没装备背包时显示 0 格符合当前资产状态，不能靠画出假格子冒充已装备。

2026-10-10 Editor 只读状态：当前 SinglePlayer_Hub，未运行，TimeScale=1，SceneDirty=true。用户最新界面可能尚未写入磁盘。后续作者接线必须以当前 Editor 中的真实引用为准；不能只依据旧磁盘层级重新生成界面。本轮计划编写没有保存或丢弃场景，也没有修改 Runtime。

五个必须覆盖的审阅重点：

1. 单击界面里的法杖/容器是查看或编辑，不能悄悄更换游戏手持物；手持选择由 1–9 发起。
2. 撒出中切换、施法缓存中切换、暂停/失焦后恢复，不能补发旧输入或多扣材料。
3. 快捷位没有额外携带空间；丢弃、卖出、投掷、死亡或换包导致实例不再可用后，不能指向同名的另一份资产。
4. 存档兼容和可靠交易/结算必须保留绑定；仅改绑定也属于未保存变化，不能因物品版本没变而漏保存。
5. 用户调整面板尺寸、位置后，Tab 开关与刷新不能覆盖这些布局；右侧详情、仓库、商店和地图要有实际不变审计。

## 2. 玩家看到什么，以及设计取舍

### 2.1 左侧：真实背包、附近物品、钱包

上区显示当前装备背包的二维格子。建议把正式常规包和基础补缺包都扩大到 **8×8，64 格**；尺寸继续由 ItemDefinition 配置。原有物品身份、数量、坐标与朝向保留，扩大边界不重新排列旧物品，不自动发包或送钱。其他测试包、P7/P8 原数据不随本轮扩大。

物品按真实形状覆盖多个格子；拖动、R 旋转、Shift 拆一份、合法格放入、同类合法堆叠继续走现有命令。拖拽时显示落点合法/非法预览，非矩形物品的空洞格子可以被其他物品利用。放置失败时只显示原因，源物品不移动、不复制。单格尺寸按左上 viewport 与实际宽高计算；最小可读尺寸可在 Inspector 调整，低分辨率不足时允许滚动，不能让图标文字挤到无法辨认。

下区只显示当前 Scene 中、拾取范围内的真实世界物品，不显示仓库或远处物品。E 拾取优先自动合法放入；没有可放置空间时打开背包，地面物品仍留在世界；玩家排布后从附近列表拖入，成功提交才移除世界代理。附近列表使用图标格与尺寸/数量提示，但它是附近物品列表，格子排布本身不产生新的存储容器。原近站点 E 交互优先级保持。

底部金币条读取 Profile.Currency。显示真实 0 或现有余额，移除 999 占位。此处只完善显示，不引入拾取金币、新奖励、实验收费或经济规则。钱包变化时刷新，不在每帧拼字符串。

### 2.2 中间：三根法杖分别编程

移除新背包中的旧三按钮顶部切换条，改成一个可滚动的纵向区域，里面有法杖 1、2、3 三个独立面板。默认全部展开，玩家可单独折叠；空间不足通过滚动访问。折叠只影响显示，不切换手持法杖、不重置 Mana/冷却、不改法术资格。这个方案保留跨杖拖动的直观性，代价是小屏可能需要滚动；后续若用户更偏好仅展开一根，可以切换展示策略而不改库存。

每个标题行保留法杖名称/图标、实际 Mana/最大 Mana、恢复速率、剩余与基础冷却、程序槽占用/上限、每次抽取数。展开后显示该实例自己的程序槽与法术；没有装备的法杖位显示空位和拖入目标。容量多于可见宽度时程序行横向滚动，槽位索引清楚显示，不硬截成 12 格。

法术从左侧背包直接拖入指定法杖程序；支持同杖排序、跨杖移动、拖回背包、合法交换，沿用真实实例/资格/次数规则。新背包不额外显示一行重复的“免费法术库”。法杖的占格容量与程序容量分开，展示不改变这个规则。蓝耗展示沿用 CastEvaluator 的根层预览，标为“本次施法预估”；Trigger 后续层不错误合计为立即扣费。右侧已有详情不在本轮扩写。

### 2.3 中下工具栏与左上游戏 HUD

中下固定 **六个槽，按键 4、5、6、7、8、9**。从背包拖入道具是建立实例引用：物品仍占原背包格子；解除快捷绑定仅清空引用；从一个快捷位拖到另一个执行移动/交换，不触发丢弃。初版只接受已有完整使用链的容器；材料与法术没有定义道具左键行为，拒绝绑定并提示原因。本轮不临时发明药剂、矿石或卷轴使用规则。

同一实例最多绑定一个快捷位；多个同名实例可以分别绑定。堆叠中也绑定具体实例，投掷消耗后清空该位，不自动换上同堆另一瓶，避免玩家误用不同组分的瓶子。实例在同一个装备包内移动或旋转时保持绑定；离开当前装备包、消失或变成在途投掷时解除。法术附着关系仍按已有实例规则处理，不随快捷位重排改变。

游戏左上展示一排 **九格**：1–3 法杖，4–9 道具，明确选中框和空位。法杖格保留简洁 Mana/冷却反馈，容器格显示图标及真实余量；背包里的六格与 HUD 的后六格读取同一套绑定。空位按键不切换、不触发旧物品；初始化优先选择可用法杖，没有可用物品则保持空手。当前手持选择是运行时状态，不把上次按键额外保存成资产。

### 2.4 已确认的统一手持操作

| 状态 | 左键 | E | G | 1–3 / 4–9 |
|---|---|---|---|---|
| 手持法杖 | 保持 P7 点击瞬间锁瞄准与施法缓存 | 原交互/拾取；材料采集须有可用容器 | 保留原容器投掷快捷操作 | 选择装备法杖 / 已绑定容器 |
| 手持快捷容器 | 长按按固定速度持续向前撒出，不进入施法缓存 | 原交互/拾取优先，其余采集到选中容器 | 投掷选中容器 | 切回法杖 / 切换容器 |
| 背包打开或失焦 | 不触发世界操作 | 不触发世界操作 | 不排队投掷 | 不切世界手持 |

保留 H 撒出、F 容器循环、J/K 固体操作的已有兼容入口，避免本轮擅自删除用户原按键。统一手持启用时，F 只循环已配置的有效容器，并同步同一个选中框；不能让 HUD 指向 A 而采集器偷偷切到 B。H/E/G 的目标必须与当前容器选择来源一致。未挂新手持组件的旧 Sandbox/P7/P8 保留原输入链，不要求重配旧教学/Boss 场景。

转换手持时清理“尚未开始”的法术缓存、容器投掷队列和撒出累计预算；已开始且可靠提交的施法/Trigger 不撤销也不退费，继续遵守原动画与资源事务。长按过程中切换到另一个容器，必须松开再按才能继续左键撒出；从容器长按切回法杖也不自动施法。UI 关闭或应用重新聚焦后同样等待释放旧按键，防止界面点击漏进世界。

## 3. 运行链、Assembly 责任与存档

“道具快捷位”是持久的六个实例引用；“当前手持格”是临时的九选一状态。这两类数据不能混在 UI 图标里，否则界面关闭、交易替换 Profile 或跨 Scene 时会丢失/串用。

```text
背包拖容器到4–9
  → Game.UI 发布绑定请求（InventoryId、请求ID、槽位、实例ID）
  → Game.Run 验证真实归属/类型/可写门禁，更新六引用与配置版本
  → 返回结果/变更事件 → 中下工具栏与左上HUD读取同一快照

数字1–9
  → Game.Character 输入适配器发布手持请求
  → Game.Run 验证法杖装备或容器绑定 → 更新唯一手持状态
  → Game.Core 变更事件 → Wizard只接法杖左键，ContainerUse只接容器左键
  → 原施法/材料事务 → 真扣次数/Mana/材料 → 只读HUD刷新
```

Core 的事件用 struct + IGameEvent，只传字符串、索引、版本、枚举，不引用 Run/Character/UI。Run 新增 ToolbeltService 管绑定与选择，并向 UI/Character 提供 IToolbeltReadOnly；金币提供 IWalletReadOnly，避免背包依赖商店视图来取余额。UI 不引用 Character，不直接改 Profile。旧单机施法适配器已有 Run 依赖，沿用该责任边界，不新增反向依赖。

快捷绑定建议纳入 Profile，**Schema 已从 5 升至 6**，新增可选六实例 ID 字段。Schema 1–5 的资产正常恢复，快捷位初始为空；Schema 6 的失效/重复/超长引用按确定规则清理，只清快捷配置，不丢弃已验证的物品与金币。保留原存档格式版本校验，未知未来 Schema 仍拒绝并保留原档。恢复后按当前装备包再验证绑定；不自动猜同名物品。存档增加的只是引用，不保存世界材料续玩状态。

所有复制入口必须覆盖：ProfileSaveMapper、SinglePlayerProfile.Adopt、ProfileAssetSnapshot 出发回滚、RaidProfileOps 出发/结算、商店候选快照。仅改快捷绑定也提高配置版本；Session.HasUnsavedChanges 比较物品版本与配置版本。保存失败保持内存脏状态，不能假报已持久化；可靠交易提交失败不能提前清掉真实绑定，提交成功后再根据最终归属协调。新冒险/练习回程重新查询真实归属，禁止缓存上一个 InventoryId 的对象。

背包与仓库的展示入口分离：Tab 只启用独立 BackpackRoot；OpenWarehouse 仍走原仓库展示。允许共享 Canvas、拖拽仲裁和真实读写端口，但新背包不调用旧 InventoryWorkspaceView.Arrange。作者工具先读取当前用户面板的引用，保留左/中/右宏观 RectTransform；为仓库保留其独立展示引用，不能用背包的新六槽规则替换仓库内容。右侧面板现有功能与排布原样保留，本轮只使新左/中选择能调用既有选择入口。
